逐字书写 vs 整页雕刻：扩散语言模型为什么突然能打了

2026-09-25 · 罗嵩 · Diffusion LLM 非自回归生成 LLM 架构 前沿研究
你盯着代码补全的光标，等了整整两秒。这两秒里，模型在干什么？它在用钢笔写字——从左到右，一个 token 接一个 token，写错了不能涂改，想快只能靠"猜下一步"的投机解码。但如果生成文字可以像 Stable Diffusion 生成图片那样——先铺一整页噪声，再从全局逐步雕出形状呢？2025 到 2026 年，这条路线突然从论文奇观变成了生产候选：Gemini Diffusion 跑到每秒一两千 token，LLaDA 2 把规模推到 40B。这场范式挑战，值得每个做大模型应用的人看懂。

一、自回归是一条单行道

先说清楚被挑战的东西。GPT、Claude、Gemini 这些主流模型都是自回归（AR）的：每个 token 只看左边的已生成内容，预测下一个。这个设计训练效率极高、推理天然可流式，但它有一条铁律——落笔无悔。第 3 个 token 写歪了，后面两百个 token 都要为这个歪字打圆场，因为模型没有任何机制回过头去改它。

一个类比：AR 是用钢笔抄写的书记员，扩散语言模型（dLLM）是先铺满粗坯再整体打磨的雕塑家。雕塑家看的是整块石头的全局结构，手臂的角度和躯干的姿态要互相商量着定；书记员只能看见前一行，写到哪算哪。

技术上的差异只有一处，但很根本：dLLM 去掉了因果掩码，用双向注意力看整个序列。生成过程是迭代去噪——从一段全被 [MASK] 覆盖的噪声开始，每一步模型看着全局，并行揭开一批最确定的 token，重复几轮直到整段成型。训练也变简单了：把干净文本按随机比例打掩码（0% 到 100%），模型学补全。于是一次训练同时学会了润色、填空和从零生成——对 AR 来说这是三个不同的任务，对 dLLM 是同一个。

二、三道"不可能"，是怎么被拆掉的

这条路 2021 年就有人走（D3PM），但一直被三个工程问题钉在论文里。2025-2026 年，三个问题各拿到了一块拼图。

拼图一：块扩散——把 KV cache 和变长买回来

经典 dLLM 有两个基建硬伤：必须预设输出长度（聊天场景致命），且每步都要对全序列做双向注意力，AR 服务栈最值钱的 KV cache 完全用不上。

块扩散（Block Diffusion，BD3-LM，ICLR 2025 Oral）的解法是个漂亮的插值：块与块之间自回归，块之内扩散。就这一个动作，同时买回变长生成和块级 KV cache。LLaDA 2 更进一步，把块大小做成训练调度（WSD：先增块、再全序列、后收块），把整个范式变成了 AR 与扩散之间的连续谱——你想偏哪边，调块大小就行。

拼图二：AR 权重可以回收——血统不作废

"从头训练一个 40B 扩散模型"听着就是烧钱无底洞。LLaDA 2 证明了另一条路：拿现成的 AR 预训练权重，继续预训练成掩码扩散模型。万亿 token 的 AR 血统大部分保留。这一点很关键：范式竞争的本质悄悄变成了迁移成本竞争——dLLM 不需要"赢"，只需要"迁移够便宜"。

拼图三：蒸馏到两步——速度从百步到可用

早期扩散 LM 要几百个去噪步，比 AR 慢 10-100 倍，快从何谈起？Gemini Diffusion 用块并行去噪（每步揭 128+ token）加步数蒸馏，把 32 步压到 8 步甚至 2 步，实测每秒一两千 token；商用侧 Mercury Coder 早就把代码生成做到了千 token 每秒量级。dLLM 的快不是每步快，是"步数 × 并行度"这个乘积大。

三、泼一盆冷水：知识债，不是范式债

速度追上来了，但 Gemini Diffusion 的成绩单有个刺眼的裂缝：

基准Gemini DiffusionGemini Flash-Lite (AR)
HumanEval（代码）89.6%90.2%
LiveCodeBench（代码）30.9%28.5%
Global MMLU（知识）69.1%79.0%
GPQA Diamond（知识）40.4%56.5%

代码追平甚至反超，知识类落后 10-16 分。这个图案说明了什么？差的是后训练数据和蒸馏生态，不是生成范式。AR 模型身后站着几年的指令微调、偏好对齐、蒸馏管线；dLLM 的对齐栈才刚搭起来。这笔生态债要还，但要按年计息——好消息是它终归是钱和时间能解决的债。

四、RL 后训练：新范式的新战场

还有个更深的坑：AR 模型的强化学习（PPO/GRPO）建立在"每个 token 都有 logprob"之上，而 dLLM 整段并行生成，这个量根本不存在——信用分配没了抓手。2025 年的解法开始成建制出现：d1 的 diffu-GRPO 用 critic-free 策略梯度绕开逐 token 概率；TraceRL（ICLR 2026）给扩散模型配了专门的价值函数，训出的 TraDo 系列在数学和代码推理上做到 SOTA。

一个耐人寻味的观察：d1 训练后出现了自我修正行为——模型会认出自己前面写错了，回头改，再继续。这在 AR 里要靠外挂的"反思"提示词工程，在 dLLM 里是结构自带的：因为"改已生成的 token"本来就是去噪循环的一部分。2026 年的 ME-DLM、NVIDIA 的 Self-Correcting MDM 沿着这条路继续修 dLLM 的老毛病（重复、低质量 token 被早早锁死）。

核心判断：dLLM 对 Agent 最值钱的能力可能不是快，是可编辑性。Agent 的核心循环就是"草稿 → 拿到反馈 → 修订"——报告改写、结构化输出修复、代码 patch。AR 模型做修订只能整段重写或外挂 diff 工具；dLLM 结构上原生支持"保留大部分、只动要改的那几处"，还自带风格、长度、安全性的免训练控制旋钮（classifier-free guidance）。速度是卖点，编辑权才是护城河的雏形。

五、别急着迁移：三个清醒剂

  • 延迟优势 ≠ 吞吐优势。dLLM 赢的是首响延迟和"整段一起出"；高并发批式服务里，AR 的 continuous batching 照样把 GPU 摊得很满。你的场景是交互式补全还是后台批处理，决定了这波红利和你有没有关系。
  • 流式 UX 不匹配。逐字打字机效果是 AR 的原生输出形态；并行生成的产品形态要么整段弹出、要么块级流式，交互设计要重想。
  • 知识密集任务先别上。MMLU/GPQA 那个缺口还在，通用问答场景的 dLLM 目前是"快但知道得少"。

至于终局，我倾向于：没有替代，只有混合。块扩散本身就是 AR 和扩散的杂交体，LLaDA 2 的三阶段训练在 AR 基础上长出扩散头。接下来的故事大概率不是"谁消灭谁"，而是同一家模型里，哪些层、哪些场景用哪种生成方式——就像今天的 CPU 里同时有大小核。

六、今晚就能做的事

  1. 跑个延迟基准：Mercury 的 API 或开源 LLaDA 2 推理，拿你手头某个代码补全/文本改写任务，对照同尺寸 AR 模型，画一张"去噪步数 × 质量"的实测曲线——建立第一手成本直觉，比读十篇论文有用。
  2. 扫描你的 Agent 工作流：找出"整段改写"环节（结构化输出修复、报告编辑、批量重排），那是 dLLM 对 AR 的结构性优势区，做 PoC 的性价比最高。
  3. 读两篇原文：BD3-LM（块扩散怎么和 KV cache 相处）和 TraceRL（没有逐 token logprob 时怎么做 RL）——这两篇分别代表 dLLM 的工程面和算法面。
  4. 盯住 serving 栈：vLLM/SGLang 的 dLLM 后端进度是你能在生产里用上它的真正时间表。

范式迁移的历史规律是：新范式先在旧范式做不好的维度上立住（速度、可编辑），再用工程手段把旧范式的红利一点点搬过来（KV cache、预训练血统、RL）。扩散语言模型正处在第二阶段的半山腰——它未必会赢下一切，但你该开始为它留一个接口了。
