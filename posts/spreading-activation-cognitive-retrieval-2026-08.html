激活扩散：当40年前的认知科学成为Agent记忆的检索引擎

2026-08-06 · Agent Memory 认知科学 图检索 Spreading Activation

Agent 记忆系统正在经历一场安静的革命——从向量检索，到图遍历，再到认知激活。这不是又一个 RAG 框架的轮子，而是一次范式跃迁：1975 年的认知心理学理论（Spreading Activation），正在成为 2026 年生产级 Agent 记忆系统的核心检索引擎。本文梳理这条技术线索，给出三种检索范式的对比实现，并分析它们各自适用的生产场景。

一、向量检索的天花板

当前主流的 Agent 记忆系统（Mem0、LangChain Memory、Letta）几乎都采用同一个检索范式：

query → embedding → cosine similarity → top-k results

这个方案简单、成熟、可用。但它有一个结构性缺陷：向量检索是扁平的。

考虑这样一个场景：用户告诉你"我上周刚领养了一只猫，叫小橘"。一周后用户问"小橘的疫苗记录在哪？"。

向量检索会做什么？它把"小橘的疫苗记录"编码成一个向量，然后在所有记忆向量中找最近的。如果这条记忆被原封不动地存下来了，也许能找到。但如果记忆是碎片化的——"用户领养了一只猫"、"猫叫小橘"、"疫苗记录在冰箱上的便签上"——三句话分别存储，那么每一句话和"小橘的疫苗记录"的相似度都不高。

人类大脑不会这样检索。我们想到"小橘"，会自然联想到"猫"，然后联想到"领养"、"疫苗"、"便签"。这种链式联想是认知科学研究了 50 年的现象。

Agent 记忆系统缺的正是这一层。

二、认知科学的答案：激活扩散理论

2.1 从语义网络到 ACT-R

1975 年，Collins 和 Loftus 在《认知心理学》期刊上提出了激活扩散理论（Spreading Activation Theory）。他们的核心观点是：

知识在人类大脑中以语义网络的形式组织。当某个概念被激活时，激活会沿着网络中的边向外扩散，扩散的强度随距离衰减。

这意味着人类记忆的检索不是"全局搜索 + 排序"，而是从种子节点出发的局部扩散。你想到"小橘"，"猫"的概念被部分激活，然后"疫苗"因为和"猫"有强关联也被激活——整个过程在毫秒级完成。

1983 年，John Anderson 在 ACT-R 认知架构中形式化了这个理论。ACT-R 将激活扩散量化为一个公式：

A_i = B_i + Σ W_j · S_{ji}

其中：

  • A_i 是节点 i 的总激活值
  • B_i 是基础激活值（频率和时近性的函数）
  • W_j 是来源节点 j 的注意力权重
  • S_{ji} 是从 j 到 i 的关联强度

40 年后，这个公式正在 Agent 记忆图中被重新实现。

2.2 为什么图是天然的记忆结构

向量数据库是一个"平面"空间——所有记忆点漂浮在高维空间中，靠距离度量组织。图数据库则天然表达了关系：

(小橘) --[is_a]--> (猫)
(小橘) --[adopted_on]--> (2026-07-28)
(小橘) --[vaccine_record]--> (冰箱便签)
(猫) --[needs]--> (疫苗接种)

当你在图中有这样一个结构时，激活扩散就是沿边传播激活值的算法。不需要把所有节点加载到内存做相似度排序——只需要从种子节点出发，沿边走几步，收集被激活的节点。

这就是为什么 2025-2026 年的前沿 Agent 记忆系统（HippoRAG2、A-MEM、GraphRAG）全部转向了图结构。

三、三种检索范式的实现

下面展示在 agent-memory-graph 项目中实际实现的三种图检索 API。全部零依赖、可直接运行。

3.1 个性化 PageRank（PPR）：全局收敛的激活扩散

PPR 是 HippoRAG2（ICML 2025）采用的核心检索算法。它模拟从种子节点出发的随机游走，通过 teleport 机制保证收敛：

def personalized_pagerank(
    self,
    seeds: list[str],
    weights: dict[str, float] | None = None,
    damping: float = 0.85,
    max_iter: int = 100,
    tol: float = 1e-6,
) -> dict[str, float]:
    """Personalized PageRank — HippoRAG2 pattern.

    模拟从种子节点出发的随机游走。高权重路径获得更多激活值，
    噪声路径自然衰减。比迭代式 LLM 检索便宜 10-30 倍。
    """
    node_ids = [r["id"] for r in self.conn.execute(
        "SELECT id FROM nodes").fetchall()]
    n = len(node_ids)
    idx = {nid: i for i, nid in enumerate(node_ids)}

    # 构建邻接表 + 出度
    adj = defaultdict(list)
    out_deg = [0.0] * n
    for e in self.conn.execute(
        "SELECT source, target, weight FROM edges").fetchall():
        i, j = idx[e["source"]], idx[e["target"]]
        w = max(e["weight"], 0.01)
        adj[i].append((j, w))
        adj[j].append((i, w))
        out_deg[i] += w
        out_deg[j] += w

    # 种子分布
    seed_vec = [0.0] * n
    if weights:
        total_w = sum(weights.get(s, 1.0) for s in seeds) or 1.0
        for s in seeds:
            if s in idx:
                seed_vec[idx[s]] = weights.get(s, 1.0) / total_w
    else:
        for s in seeds:
            if s in idx:
                seed_vec[idx[s]] = 1.0 / len(seeds)

    # 幂迭代
    scores = seed_vec[:]
    for _ in range(max_iter):
        new_scores = [damping * seed_vec[i] for i in range(n)]
        for i in range(n):
            if out_deg[i] == 0:
                continue
            share = (1 - damping) * scores[i] / out_deg[i]
            for j, w in adj[i]:
                new_scores[j] += share * w
        diff = sum(abs(new_scores[i] - scores[i]) for i in range(n))
        scores = new_scores
        if diff < tol:
            break

    return {node_ids[i]: scores[i]
            for i in range(n) if scores[i] > 1e-10}

PPR 的关键特性是 damping 参数（默认 0.85）：每一步有 85% 的概率继续扩散，15% 的概率跳回种子节点。这个 teleport 机制保证了算法收敛，但也意味着激活会"渗透"到整个图——适合广泛召回，不适合精确路径查找。

3.2 激活扩散（Spreading Activation）：认知科学的精确实现

与 PPR 不同，激活扩散没有 teleport 机制。激活只向前传播，自然衰减到零。这更接近人类认知的实际过程：

def spreading_activation(
    self,
    seeds: dict[str, float],
    *,
    decay: float = 0.85,
    threshold: float = 0.01,
    max_iter: int = 20,
    edge_weight_factor: float = 1.0,
    directed: bool = False,
    relation_filter: list[str] | None = None,
) -> list[dict]:
    """认知激活扩散检索（Anderson 1983; Collins & Loftus 1975）。

    与 PPR 的关键区别：
    - 无 teleport/reset — 激活只向前传播，自然衰减到零
    - 阈值门控 — 低激活节点不传播（"潜意识"激活）
    - 非对称 — 有向边优先方向传播
    - 迭代非收敛 — 在 max_iter 或无节点点火时停止

    典型用途：
    - 语义启动："哪些概念和 X 相关？"
    - 联想回忆：找到从某概念可达的记忆
    - 上下文扩展：用图邻居丰富种子集
    """
    # 初始化激活值
    activation = {}
    hop_dist = {}
    sources = {}

    for sid, act in seeds.items():
        if not self.has_node(sid):
            continue
        activation[sid] = act
        hop_dist[sid] = 0
        sources[sid] = set()

    # fire-once 模型：已扩散过的节点不再扩散
    already_fired = set(activation.keys())

    for iteration in range(max_iter):
        current_wave = [
            nid for nid, act in activation.items()
            if act >= threshold and nid not in already_fired
        ] if iteration > 0 else list(activation.keys())

        if not current_wave:
            break

        next_act = {}
        next_sources = {}

        for node_id in current_wave:
            already_fired.add(node_id)
            act = activation[node_id]

            rows = self.conn.execute(
                "SELECT target, relation, weight FROM edges "
                "WHERE source=? UNION SELECT source, relation, "
                "weight FROM edges WHERE target=?",
                (node_id, node_id)).fetchall()

            for row in rows:
                nbr = row["target"] if row["target"] != node_id else row["source"]
                if nbr in already_fired:
                    continue

                if relation_filter and row["relation"] not in relation_filter:
                    continue

                propagated = act * decay * (
                    row["weight"] ** edge_weight_factor)

                if propagated < threshold:
                    continue

                if nbr in next_act:
                    next_act[nbr] += propagated
                    next_sources[nbr].add(node_id)
                else:
                    next_act[nbr] = propagated
                    next_sources[nbr] = {node_id}

        for nid, act in next_act.items():
            if nid in activation:
                activation[nid] = max(activation[nid], act)
            else:
                activation[nid] = act
                hop_dist[nid] = min(
                    hop_dist[s] for s in next_sources[nid]) + 1
            sources[nid] = sources.get(nid, set()) | next_sources[nid]

    return [{"node_id": nid, "activation": round(act, 6),
             "fired": act >= threshold, "hop_distance": hop_dist[nid],
             "sources": list(sources[nid])}
            for nid, act in sorted(activation.items(),
                                   key=lambda x: -x[1])]

注意几个设计细节：

  1. fire-once 模型：每个节点只扩散一次。这防止了激活在环状结构中无限循环。ACT-R 理论中也是这样处理的——大脑不会让一个概念反复"点火"。
  2. 阈值门控：低于 threshold 的节点不会传播激活。这模拟了认知心理学中的"潜意识激活"——你能感知到，但它不足以触发进一步的联想链。
  3. 关系过滤：relation_filter 参数允许只沿特定类型的边扩散。例如 ["related_to", "depends_on"] 只走语义关联和依赖关系，不走时序边。这使检索可以被意图引导。

3.3 多跳推理（Multi-hop Reasoning）：PPR + 路径收集

第三种范式将 PPR 的广泛召回和 BFS 的精确路径收集结合起来：

def multi_hop_reason(
    self,
    question: str,
    seeds: list[str],
    max_depth: int = 3,
    min_weight: float = 0.1,
    top_k: int = 10,
) -> dict:
    """熵引导的多跳推理。

    结合 PPR（广泛激活）和过滤遍历（精确证据路径）。
    受 HippoRAG2 / PathRAG / StepChain 启发。
    """
    # 阶段 1：PPR 广泛激活
    ppr_scores = self.personalized_pagerank(seeds)

    # 阶段 2：BFS 收集证据路径（带权重剪枝）
    evidence_paths = []
    for seed in seeds:
        path = [{"node_id": seed, "label": self._node_label(seed),
                 "relation": None}]
        frontier = [(seed, path)]
        while frontier and len(path) < max_depth:
            node_id, current_path = frontier.pop(0)
            neighbors = self.conn.execute(
                "SELECT target, relation, weight FROM edges "
                "WHERE source=? AND weight >= ?",
                (node_id, min_weight)).fetchall()
            for nbr in neighbors[:5]:
                new_path = current_path + [{
                    "node_id": nbr["target"],
                    "label": self._node_label(nbr["target"]),
                    "relation": nbr["relation"],
                }]
                if len(new_path) >= 2:
                    evidence_paths.append(new_path)
                frontier.append((nbr["target"], new_path))

    return {
        "question": question,
        "activated_nodes": [
            {"node_id": nid, "label": self._node_label(nid),
             "score": round(score, 6)}
            for nid, score in sorted(ppr_scores.items(),
                                     key=lambda x: -x[1])[:top_k]
        ],
        "evidence_paths": evidence_paths[:10],
        "summary": f"从 {len(seeds)} 个种子节点出发，"
                   f"激活了 {len(ppr_scores)} 个节点，"
                   f"收集了 {len(evidence_paths)} 条证据路径。",
    }

四、三种范式对比：何时用什么

这三种 API 不是互相替代的关系——它们是互补的，各自有不同的适用场景：

维度个性化 PageRank激活扩散多跳推理
理论基础随机游走 (Brin & Page 1998)认知心理学 (Collins & Loftus 1975)图遍历 + 路径收集
收敛性全局收敛 (teleport 保证)非收敛 (自然衰减到零)有限步 BFS
复杂度O(iter × E)O(hops × degree × fired)O(seeds × branching^depth)
特点广泛召回，全局视角局部精确，可解释路径级证据链
适用场景"和 X 相关的有什么？""X 让我想到了什么？""为什么 X 和 Y 有关？"
典型延迟~10ms (1000 nodes)~2ms (3 hops)~5ms (depth 3)

选型决策树

用户查询
├─ 关键词明确，只需要 top-k 相似 → 向量检索（BM25 / cosine）
├─ 概念关联，想找"相关的" → PPR
│   └─ 需要知道具体激活路径 → multi_hop_reason
├─ 联想扩展，想找"联想到的" → spreading_activation
│   └─ 需要控制扩散范围 → 调低 decay / 调高 threshold
└─ 因果推理，想找"为什么" → multi_hop_reason + relation_filter=["causes"]

核心原则：检索策略应该匹配查询意图。用一种检索 API 应对所有查询类型，就像用一把锤子拧所有螺丝——能敲，但不好看。

五、生产实践：衰减参数的艺术

spreading_activation 的行为被三个参数控制：decay、threshold、max_iter。理解它们如何交互，是生产部署的关键。

5.1 decay：控制扩散半径

decay 是每一步传播时激活值的保留比例。它的效果是指数级的：

decay=0.9, 5步后激活值 = 0.9^5 = 0.59 （种子=1.0）
decay=0.5, 5步后激活值 = 0.5^5 = 0.03 （接近阈值边界）
decay=0.3, 3步后激活值 = 0.3^3 = 0.027 （几乎无法传播）

生产建议：

  • 0.8-0.9：适合"宽联想"场景（发现远距离关联）
  • 0.5-0.7：适合"近邻检索"场景（找直接相关概念）
  • 0.3-0.5：适合"严格匹配"场景（只找强关联节点）

5.2 threshold：认知开关

threshold 决定了节点是否"点火"——即是否向下游传播激活。但它不影响节点是否出现在结果中。这意味着你可以设置低 threshold（让更多节点出现在结果中），同时通过高 decay 实现自然衰减。

这是一个很优雅的设计：阈值控制传播，不控制可见性。这和认知心理学中的"潜意识感知"概念一致——你能隐约感觉到某些概念的激活，但它们不足以触发有意识的联想链。

六、与 PPR 的本质区别

表面上看，spreading_activation 和 personalized_pagerank 很像——都是从种子节点出发，沿边传播激活值。但它们的数学性质完全不同：

特性PPRSpreading Activation
Teleport有 (damping < 1)无
收敛保证收敛到稳态分布非收敛，自然衰减
传播方向全局 (teleport 回种子)向前 (只往邻居走)
节点状态可反复传播fire-once
语义"随机游走会到哪里？""想到 X 后联想到什么？"
心理学映射无直接对应ACT-R 激活公式

最本质的区别是 fire-once vs. 反复传播。

PPR 中，一个节点在每次迭代中都会向邻居传播——即使它已经被传播过了。这保证了稳态分布的存在，但也意味着激活会"渗透"到所有可达节点。

Spreading Activation 中，每个节点只传播一次。这防止了激活在密集子图中反复累积，更接近人类认知的实际行为——你想到"猫"之后，"猫"的概念不会在你的大脑中反复点火。

实际效果差异

假设你有这样一个图：

    A --- B --- C
    |     |
    D --- E --- F

从 A 出发，PPR 最终会给所有节点分配一个非零分数（因为 teleport 让 A 的激活不断"回流"）。而 Spreading Activation 会给出一个衰减梯度：

A=1.0, B=0.85, D=0.85
C=0.72, E=0.72 (从B和D各0.36)
F=0.61 (从E)

这个梯度直接反映了图距离——更近的节点获得更高激活值。PPR 的稳态分布则更"均匀"，不直接反映距离。

七、为什么这很重要

7.1 Token 经济学

在 LLM Agent 场景中，检索的精度直接决定了 token 消耗。一个能精确定位 5 个相关节点的检索器，比一个返回 20 个"大致相关"结果的检索器，在下游 LLM 推理中节省 75% 的 token。

激活扩散天然提供了这种精度——因为它返回的节点按图距离排序，而非向量相似度排序。图距离是一个更强的相关性信号。

7.2 可解释性

当 Agent 做出一个决策时，"为什么？"是一个关键问题。向量检索的回答是"因为 cosine 相似度高"——这对人类没有意义。激活扩散的回答是"因为从 A 到 B 到 C 形成了一条激活路径"——这直接对应人类理解因果关系的方式。

results = graph.spreading_activation(
    seeds={"user_question": 1.0},
    include_seed_details=True,
)

# 每个结果都包含 sources — "谁激活了我"
for r in results:
    print(f"{r['node_id']}: activation={r['activation']:.3f}, "
          f"hop={r['hop_distance']}, "
          f"via={r['sources']}")

这种可解释性在生产环境中至关重要——特别是在医疗、金融等高风险领域。

7.3 与熵框架的协同

在 agent-memory-graph 中，spreading_activation 可以和熵权重结合。高熵节点（信息量大的节点）的边权重更高，因此激活会优先流向信息丰富的区域：

# 为每条边计算熵权重
for edge in graph.get_edges():
    edge_entropy = graph.node_entropy(edge["target"])
    graph.update_edge(
        edge["source"], edge["target"],
        weight=edge_entropy  # 熵越高，边权重越高
    )

# 激活自然流向高熵（高信息量）区域
results = graph.spreading_activation(
    seeds={"query_topic": 1.0},
    decay=0.85,
)

这种"熵引导的激活扩散"是 agent-memory-graph 独有的能力——没有任何竞品实现了这种组合。

八、从理论到产品

1975 年 Collins 和 Loftus 提出激活扩散理论时，他们不会想到这个模型会在 50 年后被实现在一个 npm 库里。但技术发展的路径就是这样的——认知科学的 foundational theory 不会过时，它只是在等待合适的工程载体。

从向量检索到图遍历到认知激活，Agent 记忆系统的检索能力正在经历一次质变。这不是一个"用新算法替换旧算法"的故事——向量检索仍然在，PPR 仍然在，spreading activation 是新增的一种选择。关键是：给 Agent 多种检索工具，让它根据查询意图选择最合适的。

这正是 agent-memory-graph 正在做的事情：5 种检索范式（BM25 / 向量 / PPR / 激活扩散 / 多跳推理），每种都有清晰的适用场景，全部零依赖，全部有测试覆盖。

当 Agent 记忆系统从"存储"走向"认知"，我们需要的不是更大的数据库，而是更聪明的检索。
