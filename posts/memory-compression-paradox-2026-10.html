把日记撕成便签——Agent 记忆的压缩悖论与 2026 年的三条破局路

Agent 记忆 RAG 评测 架构 2026-10-12 · 基于 E-mem (ICML 2026)、Mem0、Pam、Letta、AgentMemBench、REMORY 等 18 个源的调研

问你的 AI 助手一个问题："上个月我是先决定换工作，还是先报的日语班？你后来劝过我什么？"它卡壳了。奇怪的是——聊天记录明明都在，上下文窗口明明够长，它上周还准确记得你喜欢靠窗座位。为什么记得住"靠窗"，却回答不了"先后"？过去两年，所有主流的 agent 记忆系统在同一个地方集体失分，而这背后藏着一个信息论级别的悖论：它们失分，恰恰因为它们记性太"好"了。

一、一片奇怪的高原：F1 卡在 40 分上下

先看数据。LoCoMo 是 agent 记忆领域的标准基准（Snap Research，ACL 2024）：多会话长对话，最长 35 个会话、300 轮，配上 1,540 道题，分单跳事实、多跳推理、时序推理、开放域几类。ICML 2026 的 E-mem 论文给出了一张很扎眼的对照表（GPT-4o-mini 骨干，LoCoMo F1）：

系统Overall多跳时序
全量塞窗口37.3129.2325.97
朴素 RAG（原文+普通检索）44.7327.5046.07
A-Mem39.6527.0245.85
Mem045.1038.7248.93
MemoryOS42.8435.2741.15
LightMem38.4429.7843.71
E-mem（情景重建）54.17+8.56+8.87

三个观察值得停一下。第一，一整代专门设计的记忆系统，F1 全卡在 36-45 之间，多跳题没有一家过 45。第二，最尴尬的一行：朴素 RAG——原文存着、普通检索、没有花哨的记忆管理——以 44.73 打赢了 A-Mem（39.65）和 MemoryOS（42.84）。你精心设计的记忆系统，不如什么都不做。第三，全量塞窗口也不行（37.31），所以答案也不是"上下文够长就行"。

高原的存在意味着这不是某家的实现 bug，而是范式本身的天花板。问题出在哪？

二、诊断：压缩悖论——你扔掉的不是冗余，是未来的查询

这一代记忆系统共享同一个架构假设，姑且叫写时压缩：对话发生时，用 LLM 把每段话抽取成干巴巴的事实条目——"用户喜欢靠窗座位""用户住在东京"——存进向量库或图数据库；查询时检索几条塞回上下文。Mem0、A-Mem、MemoryOS、MemoryBank 全在此列。它的动机很硬：token 贵、上下文有限、检索快。听起来像图书馆做卡片目录，非常合理。

但注意一个差别：图书馆做了卡片目录，书还留在架子上。写时压缩系统把书扔了，只留卡片。

E-mem 论文里有句话说得很准：预处理时被丢弃的原文"结缔组织"（connective tissue），会让 agent 在需要重建事件序列时"被迫去猜、去幻觉缺失的环节"。什么叫结缔组织？"先……后来……""本来打算……结果改成……"、量词、指代、两件看似无关的事在同一晚发生——这些恰恰不构成任何一条值得抽取的"事实"，却在被问到"先后顺序""几次""和什么有关"时是唯一的答案来源。摘要写着"用户报了日语班"，但摘要上没有日期、没有上下文、没有它和换工作那次聊天是同一个晚上这个事实。

所以悖论成型了：写时压缩是一个只对"预期中的查询"友好的有损投影，而损失恰好集中在预期之外的查询维度上——多跳、时序、审计。基准考的就是这些。你压缩掉的不是冗余，是未来的查询。这不是调优能解决的，是信息已经不在了。40 分的高原，是信息论利息。

三、2026 年的三条破局路

路线 A：原文不删，智能后移——情景重建

E-mem（ICML 2026）的做法可以概括成一个比喻：不再把日记撕成便签，而是给日记的每一层楼派一个只读自己那层的保安。架构上是 master + 一队小模型 assistant：每个 Qwen3-4B 的小模型守一段完整原文，只维护一份供路由的粗摘要；查询到来时，多路路由器决定激活哪几个"保安"，被激活的保安在自己的原文段上就地推理，返回带绝对时间戳的证据元组；最后 master 聚合所有证据、按时间锚解决矛盾。结果：F1 54.17，比所有压缩式基线平均高 7.75 个点，多跳 +8.56、时序 +8.87，同时因为只搬运"证据"不搬运原文，token 成本比全量上下文降了 70%。

更硬的证据来自受控实验。AgentMemBench 把五种记忆策略（窗口、外部原文、图、压缩摘要、网络增强）接上完全相同的接口跑同一批数据：保留原文的外部存储 Recall@5 = 0.792，压扁摘要的那组被甩开 +0.324，MRR、答案 F1、忠实度全面落后。范式差异，不是参数差异。

路线 B：文件优先——把检索从基础设施层搬到智能层

第二条路更朴素得近乎冒犯：不给 agent 配向量数据库，给它一个目录和 grep。Pam 用"file-first"架构——agent 自己把信息组织成结构化的本地文件，查询时用原生工具去翻——在 LoCoMo 上拿到 74.35 的 LLM-judge 准确率，多跳 80.1%。Letta（MemGPT 团队）用纯文件系统 + gpt-4o-mini 拿到 74.0，结论是"简单文件存储与专门检索系统竞争力相当"。

这件事你在别处见过：coding agent 从来不把你的代码库向量化，它直接 grep 和 read。模型足够强之后，"检索"正在从基础设施层（embedding + 近似最近邻）上移到智能层（模型自己决定翻哪份文件）。向量检索是模型弱小时代的拐杖；而 agentic retrieval 对齐的是 LLM 本来就会的东西——用工具探索。2025 年你可以说这是玩具，2026 年的两个 74 分说它是可部署的路线。

路线 C：把记忆压进"模型方言"——soft token

第三条路反着走：既然要压缩，就别压成人类文字，压进连续向量。十月初的 REMORY 训练了 32 个 soft token 来承载 8K token 的对话历史，冻结的大模型直接"读"这 32 个 token——长文问答 +37%、多轮对话 +30%、延迟 -43%。同族还有把 KV cache 本身当记忆格式在 agent 间复用的工作（AgentKVShift、边缘设备的持久化 Q4 KV cache），以及用压缩"事实卡"把 prompt token 砍掉 85% 还不掉点的 ENGRAM-R。

这条路 token 经济学最漂亮，但代价要说清楚：它把记忆变成了模型方言。soft token 不可读、不可审计、换模型就作废——工程上等于把数据库换成一块魔结石。成本敏感和端侧场景它有真价值；但凡你的 agent 需要向用户解释"我为什么记得这个"、需要合规审计、需要跨模型迁移，这条路的账就算不平。

四、一个反证和一个陷阱

有意思的是，写时压缩阵营的领头羊 Mem0 自己的进化路线，恰好反证了上面的诊断。它 2025 年论文里的原始 F1 是 25/12/18 那一档；2026 年新算法大幅上涨，而它自述的两个驱动力——抽取侧单遍等权、检索侧多信号并行（语义+关键词+实体）——全部是检索端的手术，没有一个字说"压缩得更狠"。涨分来自让找东西的机制更聪明，不是让存的东西更少。

但这里埋着 2026 年记忆领域最大的陷阱：92.5 是 LLM-judge 准确率，54.17 是 F1，74.35 又是另一家的 judge 口径——这三个数字住在三个不同的宇宙，不可横向比较。各家骨干模型、检索预算、判分方式全不一样，连 Mnemoverse 这样的第三方基准矩阵都专门强调"数字不带配置不可比"。看到一个记忆框架的宣传页写着 90+，第一件事不是惊叹，是找口径脚注。评测口径本身，已经是这个领域的新战场。

五、真正的设计变量：你在管道的哪一段为保真付费

把三条路线放在一起，我看到的是一个统一的问题重构。记忆系统真正要做的决策，不是"压缩率多少"，而是在管道的哪一段为保真付费：

  • 写时付费（写时压缩）：一次付费、终身摊销，但付的是信息论利息——原文烧掉，未来所有预期外的查询一起陪葬；
  • 读时付费（情景重建/文件优先）：按查询次数付费，但原文永在，任何查询维度都保留重算的可能；
  • 训练时付费（soft token）：把保真押进一个不可解释的连续空间，最便宜，也最不可逆。

2026 年的证据正在集体向"读时"倾斜，因为底层经济学变了：存储从来没有这么便宜过，token 和保真从来没有这么贵过。把原文留着（几个 GB 的 SQLite 而已），把压缩从"存储层的永久决定"降级为"工作集的临时操作"——E-mem 的 token -70% 就是这么来的：压缩发生在读出证据之后，而不是写入历史之前。永久压缩只在一个场景仍然正确：查询分布高度可预期（比如纯个性化偏好）。只要你的用户还会问出你没预料到的问题，原文就是你唯一可逆的选择。

六、今晚就能做什么

  1. 给现有记忆系统加一个"原文对照组"。最便宜的实验：把你的对话原文原样存进 SQLite FTS5（或任何全文索引），不做任何抽取摘要，查询时 BM25 检索原文段直接注入。如果你的摘要管线没有打赢这个朴素基线——按上面的数据，大概率没有——你就知道该把钱花在检索侧而不是压缩侧了。
  2. 把检索升级成工具。在 read 路径上试一版 agentic retrieval：不给模型喂检索结果，给它 search(query) 和 read(id) 两个工具，让它自己决定翻几轮。改动只在读路径，一天能上线，对照 Pam/Letta 的结论验证你自己的场景。
  3. 评测报告永远双口径。exact-F1 和 LLM-judge 准确率并排报，标注 judge 模型版本。选型时看到任何单一数字先问口径——这是 2026 年记忆领域防忽悠的唯一硬技能。
  4. 压缩可以留，但换个位置。把摘要从"存储格式"降级为"上下文预算紧张时的临时投影"，并且永远保留从原文重算的路径。判断标准一句话：你的用户会问出你没预料到的问题吗？会，就别烧原文。

回到开头那个卡壳的助手。它答不出"先换工作还是先报班"，不是模型笨，是记忆系统在它出生那天就把答案烧掉了——便签上没有日期，没有那个晚上。2026 年的共识正在形成：agent 记忆的第一原则不是"记住重要的"，而是"别替未来的问题做决定"。书要留在架子上，目录只是找书用的。
