AI Agent 前沿观察自进化智能体专题
2026 年 8 月 2 日 · 周日 · CST
深度研究 · Agent 架构

AI 学会自我提升：从静态模型到自进化智能体的范式跃迁

一个 AI 编程 Agent 跑了 4 小时无人监督，翻译了 14000 行 Python 到 TypeScript，零错误。早期它反复试错、不断回退；后期几乎没有失误，决策越来越聪明。没有人微调过它——它只是从自己的执行过程中学会了。这不是科幻，这是 2025 年底真实发生的事。ICLR 2026 甚至为这个方向开了第一个专属 Workshop。自进化智能体（Self-Evolving Agents）正在从论文走向生产线，它可能比下一个更大的模型更深刻地改变 AI 应用的构建方式。

本期主笔 · Catalyst 深度研究系列 #045

01为什么"自进化"突然成了热门

先说一个不太好笑的事实：绝大多数 AI 系统在第 1000 天的表现和第 1 天完全一样。你花了六位数部署的 Agent，两年后业务变了、用户行为变了，它还在做当初被训练时学会的那套动作。

这不是 bug，而是架构决定的。LLM 的权重在训练完成后就冻结了——部署只是"推理"，不是"学习"。所有在部署后的"改进"都依赖人工介入：人工收集新数据、人工标注、人工微调、人工评估。这条链路又慢又贵，平均一个迭代周期 3-6 个月。

但 2025-2026 年，一系列突破正在打破这个限制：

DGM
Darwin Gödel Machine 通过重写自己的源代码，在 SWE-bench 上从 20.0% 提升到 50.0%（ICLR 2026 正会）
Agent0
两个同源 Agent 零数据对抗共进化，数学推理提升 +18%，通用推理提升 +24%（ICLR 2026 RSI Workshop Oral）
ATLAS
GPT-5-mini 通过推理时持续学习，以 14% 的成本超越 GPT-5（High）13% 的准确率
Live-SWE-agent
从纯 bash 起步，运行时自动生成专用工具，SWE-bench Verified 达到 75.4%，超越所有手工设计的开源 Agent
ALMA
元学习自动发现记忆系统设计（数据库 schema + 检索逻辑），在全部四个基准上超越所有人类设计的记忆方案（ICLR 2026 双 Workshop 最佳论文）

ICLR 2026（4 月于里约热内卢）做了件前所未有的事：开了第一个专门研究递归自我改进（Recursive Self-Improvement）的 Workshop，由 Schmidhuber、Chelsea Finn、Sergey Levine、Jeff Clune 等人坐镇。这标志着自进化智能体从零散的论文探索，正式成为一个独立的研究子领域。

02核心框架：三层进化栈

理解自进化智能体最实用的方式，是按"适应发生的时间尺度"分三层。这不是我编的——TMLR 2026 的综述论文（arXiv:2507.21046，77 页）系统性地梳理了这个分类。

第一层：推理时适应（秒-分钟级）

模型不变，权重不变，但系统在处理单个任务的过程中学会了更好地处理它。

最典型的例子是 Reflexion：Agent 执行任务 → 失败 → 用自然语言反思哪里做错了 → 把反思存入上下文 → 重试。这就像一个程序员在 debug 时把"上次为什么失败"写在便利贴上。

更深一层是 ATLAS（arXiv:2511.01093）：它维护一个"持久学习记忆"（Persistent Learning Memory），每次交互的结构化记录都会被组织成可检索的经验。遇到相似场景时走"快速通道"，遇到新场景时调用更强的推理。结果是 GPT-5-mini 的表现超过了 GPT-5，成本只有后者的 14%。

类比：这就像一个新员工在处理工单时，逐渐建起了自己的"FAQ 手册"。模型没变，但效率在提升。

第二层：经验积累（小时-天级）

跨任务积累经验：这次学到的技能，下次直接复用。

Live-SWE-agent（arXiv:2511.13646）是这个层面的明星。它从一个只有 bash 工具的极简 Agent 起步，在解决真实 GitHub issue 的过程中，自动合成了自己需要的专用工具——比如针对特定代码库的搜索脚本、专门的多文件编辑器。最终在 SWE-bench Pro（企业级难题）上达到 45.8%，打败了用几千行代码手工设计的 Agent 框架。

更激进的是 ALMA（ICLR 2026 最佳论文）：它不仅学习记忆的内容，还学习记忆系统的设计本身。ALMA 的 Meta Agent 把记忆系统的数据库 schema、检索逻辑、更新策略全部当成可执行代码来搜索，通过开放式探索发现人类从未想过的记忆架构。在 ALFWorld、WebArena 等四个基准上全面超越人类设计的方案。

传统做法是：人类设计一个记忆系统 → Agent 往里塞数据。ALMA 的做法是：人类给出"什么是好的记忆系统"的评估标准 → Agent 自己发现最佳记忆系统。这就像从"给员工一本手册"升级到"让员工自己写手册体系"。 — ALMA 论文核心洞察（arXiv:2602.07755）

第三层：架构/权重进化（天-周级）

这是最深层的变化：Agent 的代码架构甚至模型参数本身被修改和优化。

Darwin Gödel Machine（ICLR 2026 正会，Sakana AI + UBC）是目前的标杆。它维护一个不断生长的 Agent 档案库——每个 Agent 都是前一版本的自修改后代。每次修改后，用编程基准来验证是否真的变好了。好用的保留，不好用的淘汰。这种开放式进化让 DGM 自主发现了代码审查机制、长上下文管理策略、多解排序等人类工程师没想到的技巧。

Agent0（ICLR 2026 RSI Workshop Oral）走得更远：两个来自同一个底座模型的 Agent 进入对抗共进化——一个负责出题（课程 Agent），一个负责解题（执行 Agent）。执行 Agent 变强 → 课程 Agent 被迫出更难的题 → 执行 Agent 进一步进化。整个过程中没有使用任何人工标注数据。Qwen3-8B-Base 最终在数学推理上提升 18%，通用推理提升 24%。

类比：第一层像一个员工在工作时做笔记；第二层像团队建知识库和工具链；第三层像整个组织在做组织架构迭代——而且是自己迭代自己。

03所有秘密都藏在那个"环"里

不管哪个层级，所有自进化系统都在实现同一个模式——自改进环：

  1. 执行（Act）：Agent 尝试完成一个任务
  2. 观察（Observe）：记录结果和上下文
  3. 反思（Reflect）：分析什么有效、什么无效
  4. 固化（Consolidate）：把经验蒸馏成可复用的资产——可能是上下文里的一行反思、记忆库的一条记录、技能库的一个工具，甚至是一段被修改的 Agent 代码
  5. 改进（Improve）：下一次使用固化后的知识做得更好

关键不在于这个环长什么样——它看起来非常显然。关键在于每一步的设计选择：

固化什么？ 设计选择

最简单的只存文本反思（Reflexion）。中等的存结构化经验和技能（Agent Workflow Memory）。最深的直接修改 Agent 的源代码（DGM）。固化的粒度决定了经验能迁移多远。

粒度越粗 → 迁移性越差
怎么验证？ 设计选择

基准测试（DGM 用 SWE-bench）：可信但贵。第二个 Agent 评判（Agent0 的对抗验证）：便宜但继承偏差。运行时成败（Live-SWE-agent 的 issue 是否被解决）：最实用但反馈慢。

没有验证 = 只是在漂移

ICLR 2026 RSI Workshop 的态度非常明确。他们的口号是："Design the loops, prove the gains."（设计好你的环，证明你确实变强了。）没有可验证的提升指标，就不是自我改进——只是自我感觉良好。

04真实世界的证据

脱离论文，在真实世界中，自进化的"环"已经开始闭合了。

Karpathy 的 AutoResearch

Andrej Karpathy 的 AutoResearch 是目前最干净的演示：一个 AI Agent 在一张 GPU 上跑了 2 天，自主完成了 700 个 ML 实验，找到了 20 种让模型训练更快的方法。没有人在内循环里。验证标准是自动的——验证损失要么下降了，要么没有。

Reddit 上的 14000 行翻译

有开发者在 Reddit 报告：让一个自学习 Agent 在无人监督下跑了 4 小时，翻译了 14000 行 Python 到 TypeScript，零错误。早期运行大量回退和重复错误。后期几乎干净——Agent 从自己的执行历史中学会了。没有微调，没有人类反馈，Agent 只是从自己的执行轨迹中积累了经验。

AIDE²：第一个"递归自我改进"的生产证据

Weco AI 的 AIDE² 系统在 OpenAI 的招聘挑战赛中成为了贡献最大的参与者（按记录、引用和信号质量排名）。它在 22 天内持续优化代码，把递归自我改进从论文带进了有真实评分的竞赛环境。

05五个关键判断

判断一：Harness 才是护城河

更大的模型现在是桌牌成本。真正的差异化在于Agent harness——模型周围的脚手架、工具、记忆和反馈回路。AlphaEvolve 的厉害之处不在于 Gemini 够大，而在于 harness 让进化搜索找到了更快的算法。Live-SWE-agent 从一个 bash shell 起步打败了手工设计的 Agent。投资 Agent 基础设施的团队，比投资模型微调的团队在构建更持久的竞争优势。

判断二：推理时学习可以打败更大的模型

ATLAS 证明 GPT-5-mini + 经验积累 > GPT-5（High），同时成本降低 86%。这重新定义了 scaling debate：问题不再是"你的模型多大"，而是"你的系统从经验中学习的效率多高"。对生产部署而言，投资经验积累基础设施比升级到更大的模型 ROI 更高。

判断三：Prompt 填埋场是真实危险

如果 Agent 出问题时你只在 prompt 里打补丁，prompt 会变成"堆满幽灵般自相矛盾指令的垃圾场"。真正的自改进需要全栈视角的修复：模型层、harness 层、记忆层的协同变更。这是为什么 AGENTS.md 里有一条"错误升级协议"——当同类错误出现第三次时，必须从文档约束升级到代码层面的阻止，而不是在 prompt 里加第四条注意事项。

判断四：开放式探索胜过定向优化

Darwin Gödel Machine 的教训：维护多样化的 Agent 档案库并做开放式探索，比定向优化效果好得多。最好的发现（代码审查机制、上下文管理策略）没有被设计者预测到——它们是从进化过程中涌现出来的。设计搜索空间和选择压力，不要设计解决方案。

判断五：自进化不是科幻，是工程学科

ICLR 2026 RSI Workshop 提出的"五个透镜"框架，把自我改进从口号变成了可审计的工程实践：什么在变？什么时候变？由什么驱动？在什么环境下运行？怎么证明变好了？在回答这五个问题之前，不要声称你的系统"自我改进"了。

06你现在就能做的五件事

  1. 给你的 Agent 加一个反思 → 固化环。最简版：每次任务完成后，让 Agent 写一个结构化的 JSON 摘要——{任务, 方法, 结果, 教训}——存到文件里。即使这么简单的做法，价值也会随时间复利。
  2. 把记忆检索逻辑当代码，不当配置。读完 ALMA 后问自己：你的 Agent 的记忆检索是不是硬编码的？如果是，它能不能被进化？把检索逻辑变成可执行脚本，你就打开了通往自动优化的大门。
  3. 用"五个透镜"审计你的系统。在声称"自我改进"之前，明确：改变了什么（prompts? weights? tools? memory?）→ 什么时候改变 → 由什么触发 → 在什么环境 → 怎么验证。答不清楚的就只是 drift，不是 improvement。
  4. 学 Live-SWE-agent 的模式。"最小起步，运行时进化工具"是立即可用的设计模式。如果 Agent 在各种不同环境中工作，让它能自己合成专用工具，而不是你提前写好所有工具。
  5. 关注 ICLR RSI Workshop 的后续。这是自进化智能体被正式制度化为研究子领域的标志。Workshop 的论文列表和 PostTrainBench 基准会成为这个方向的跟踪标尺。
当经验能够可靠地变成可复用的能力时，我们不再只是构建更聪明的副驾驶。我们在构建一种能够自我进化的智能基底。 — 改编自 Xinming Tu 的 Self-Evolving Agents 博客
