把记忆写进权重：基底之争的裁决是路由，不是革命

2026-11-12 · AI Agent 记忆系统 Test-Time Training

你的 Agent 用了三个月，攒下几万条交互记录。现在你想让它记住"我每周三晚上有例会，别排事"。这句话存哪儿？

存进检索库，每次提问都要先搜一遍档案，问题越积越多、检索越来越贵；塞进提示词，桌面就这么大，每个会话还得重新摆一遍。还有一个诱人的第三选项：直接微调进模型权重——像肌肉记忆一样，查询零成本、延迟恒定、永不占上下文。

这个选项过去两年的口碑是"听起来很美，测起来很惨"：权重记忆在用户事实这类任务上全面落后于文本记忆。但上周到本月，三篇论文几乎同时到位（一篇 10 月 23 日、一篇 EMNLP 2026、一篇 11 月初），把这场"context 层 vs weights 层"的基底之争送上了法庭。裁决出乎意料：没有赢家，只有分工。答案不是革命，是路由。

一、先搞清楚：记忆的三种物理落点

打个比方。Context 层是书桌——正在处理的东西摊在桌面，伸手就拿，但桌面有限，而且每天清空。外置文本记忆（检索库）是档案柜——容量近乎无限，每份文件可以盖章、可以粉碎、可以追溯来源，代价是每问一个问题都得跑一趟档案室，而且档案越攒越多，跑腿成本线性上涨。

权重是肌肉记忆。你不用"检索"怎么骑自行车——它就在你身上。查询边际成本为零，而且肌肉的容量大到存得下几十年的协调动作。但肌肉有个致命属性：你没法定点删除某一条。学会骑车的平衡感和某次摔车的错误姿势缠在同一组肌纤维里，你删不掉摔车，只能重新训练整个动作。

这就是基底之争的全部张力：档案柜可治理但每次付费，肌肉免费但不可治理。2026 年之前，工程界的默认答案是全押档案柜（Mem0/Zep/MemOS 这类检索式记忆系统），权重层只留给"领域口音"这种慢变量微调。

二、权重层的两条技术路线，都走到了关键节点

路线 A：把"学习"做进架构本身（TTT 层）

这一族工作叫 Test-Time Training：推理时对模型内部的"快权重"做梯度更新，让序列混合层自己长记忆。两年间它收敛出了一套共同语法：

  • 惊吓写、衰减忘：Google 的 Titans（NeurIPS 2025）用梯度当"惊讶度"信号——当前输入让记忆网络意外（梯度大）就多写一点，平淡就少写；配一个 weight-decay 遗忘门，旧信息自然风化。效果是 2M token 上下文下 needle-in-haystack 稳定在 90% 以上。
  • 别走一步梯度，直接解到最优：MesaNet（ICLR 2026）指出单步梯度下降是在"凑合"，它每一步把累积正则化回归闭式解到最优，同样的参数量在长程依赖上打赢 Mamba2 和 DeltaNet。
  • 并行化拆墙：ParaTTT（10 月底）把非线性记忆的在线更新拆成可并行的 chunk，TTT-MLP 评测提速 32 倍、训练提速 4.9 倍，追平同尺寸 Transformer。此前 TTT 层在 GPU 上的利用率不到 5%——论文里的收益在商品显卡上根本兑不了现。

路线 B：把用户记忆蒸馏进适配器（参数化记忆）

路线 A 是改架构，路线 B 是在现成模型外挂 LoRA。这条路一直有个死穴：直接把记忆 dump 出来做 SFT，模型学成复读机，4B 规模上准确率只有 15.9%（几乎全灭）。

本月的新工作 Route to Remember（arXiv 2611.05636）给出了破局方法，聪明得朴素：教师是"同一个模型 + 记忆在上下文里"，学生是裸奔的 LoRA，学生蒸馏教师的答案行为。因为教师每次都看着记忆作答，学生学到的是"假如这些记忆长在我身上我会怎么答"。结果：HaluMem 基准上，权重记忆首次追平甚至超过全上下文提示和 MemOS 检索系统，而每次查询读的 token 更少。

三、这篇论文里最值钱的一张表，跟容量无关

所有人都以为参数化记忆的瓶颈是 LoRA 容量。作者做了 rank 扫描：16 到 64 性能几乎平坦，128 反而幻觉率飙升。结论是一句能让不少预算会议改议程的话：

在有效区间内，rank 不是操作变量。训练目标才是杠杆，适配器大小不是。

27B 模型上三种"写法"的对比：on-policy 蒸馏 62.6，SFT 背 dump 51.9，检索系统 47.4。差距不在肌肉大小，在怎么练。任何"加 rank 提记忆容量"的计划，可以停了。

四、裁决：为什么是路由

真正的裁决来自分条件评测。把用户记忆查询拆成六种条件（基础事实、矛盾记忆、动态更新、多跳推理、泛化、边界拒答），两种基底的胜负表长这样：

  • 矛盾消解（用户先说过周三例会、后改成周四）：权重 57.2 vs 检索 47.7。权重赢——因为矛盾的信息在参数里已经被融合消化过，不像检索会把两条打架的记录一起端上桌。
  • 动态更新（事实频繁变化）：检索 24.5 vs 权重 13.4。检索赢——档案柜换一张纸就行，肌肉要重练。
  • 边界拒答（记忆里没有就该说没有）：检索 95.9 vs 权重 83.8。检索赢——空档案柜是可检查的状态，"肌肉里没有"是玄学。

失败剖面完美正交。所以论文的终态设计是一个 verify-then-regenerate 路由：权重和文本各管自己最擅长的查询，路由器在中间分诊。这呼应了更早的一个诊断研究（per-user adapter vs 检索）：互不支配、彼此互补。现在互补性第一次变成了可运行的代码。

工程蓝图随之清晰：慢变量沉淀进权重（用户的长期偏好、身份事实、稳定技能——它们很少变、很少需要删除、查询频率高，是肌肉记忆的理想素材），快变量留在文本（正在变的计划、待办、项目状态——它们需要 diff、需要撤销、需要审计）。做梦篇说"记忆改动 = 一条 git commit"，那条纪律依然成立：能进权重的，只有你愿意让它过完整个 review 流程再也没打算撤销的部分。

五、别急着上车：三道反方证据

  1. TTT 的"必要性"被划走了半壁。Dawn Song 组的 TTME（10 月 23 日）证明：在科学发现任务上，把经验蒸馏进外置记忆而不动权重，效果反超 TTT，还省 82.8-84.6% 的 FLOPs。推理时权重更新作为"通用适应手段"被高估了，它真正不可替代的地盘只剩"架构内线性成本长上下文"这一块。
  2. serving 契约是个隐藏的基建深坑。TTT 请求携带"自己独占、且在生成中被读写"的模型态，这直接打破现代推理引擎"所有请求共享静态权重"的 batching 契约——朴素合批会污染请求状态。EMNLP 2026 的 RW-TTT 用读写契约（每步打 owner/version/读写标签，只批兼容相位）把吞吐恢复到串行的 9.31 倍。在此之前，TTT 上线 = 每个请求独占一个模型副本。换句话说：权重记忆的时间表由 kernel 工程和调度器决定，不由 loss 函数决定。
  3. 治理三件套依然是生产门槛：审计（用户的生日存在哪个权重里？无解）、删除（单条删除≈不可能，machine unlearning 不成熟）、隔离（没有 per-user adapter 就没有租户隔离）。合规敏感场景（法务/医疗/欧盟数据）会把权重层放在"低风险沉淀层"，永远不会是唯一记忆层。可 diff 性不是工程洁癖，是部署许可证。

六、今晚可以做的五件事

  1. 给你的记忆系统做一次"快慢分诊"：把现有记忆条目按"变更频率"打标——三个月没变的进"可沉淀候选池"，每周都变的留在检索层。这是路由器的第零步，今晚一个脚本就能做完。
  2. 停掉所有"加 rank 换记忆容量"的计划，把预算挪去搭蒸馏管线：教师带记忆、学生裸跑、蒸行为不蒸文本。rank 16-64 足够。
  3. 读 Route to Remember 的路由判据（arXiv 2611.05636）：verify-then-regenerate 的"什么时候信权重、什么时候触发重生成"逻辑可以直接搬进你现有系统的 prompt 层，不需要真微调。
  4. 盯基建信号而不是论文信号：ParaTTT 的 kernel 开源、RW-TTT 是否进 vLLM/SGLang 生态，这两个事件比任何新 loss 都更能预测权重记忆什么时候对你可用。
  5. 把"矛盾记忆"当测试用例：无论你用什么记忆方案，故意注入一对矛盾的用户事实，看系统是融合、打架还是拒答——这是六条件里最容易被日常迭代悄悄弄坏的一项。

尾声

从《当 Agent 学会做梦》的"记忆固化 = git commit"，到今天的"慢变量进肌肉、快变量进档案、路由器管分诊"——Agent 记忆系统正在重演操作系统存储层级的历史：寄存器、内存、磁盘，不是谁取代谁，而是按访问频率和治理成本分层。权重层就是这场分层的最后一块拼图：它不是记忆系统的未来，它是记忆系统的 L2 cache。

模型是租来的，档案柜按次计费，只有肌肉记忆免费——但健身房（RW-TTT 们）下个月才开门。
