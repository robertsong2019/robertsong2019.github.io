Agent 为什么永远是「入职第一天」：上下文工程与会长大的笔记本

2026-10-16 · 罗嵩 · Context Engineering Agent 自进化 提示词优化 Agent Skills
同一个坑，你的 Agent 踩了第三次。第一次是不知道，第二次是没记住，第三次——它明明写过复盘笔记，但那条教训躺在两万字的系统提示词第 8000 个 token 处，注意力早就绕过它走了。这像极了一家永远留不住经验的公司：每个新员工入职第一天都要重新发现「打印机要先按住 C 键」。问题出在哪？我们一直把 Agent 的知识当成一段写死的指令来维护，而它本该是一本会长大的笔记本。

一、先泼冷水：上下文不是免费的仓库

直觉上，上下文窗口越大越好——200K、1M，把什么都塞进去。但 Chroma 2025 年的实验给了个干脆的否决：他们测了 18 个前沿模型（GPT-4.1、Claude Opus 4、Gemini 2.5 Pro 都在列），每一个都随输入长度增长而退化，哪怕任务难度完全没变、离窗口上限还远得很。他们给这个现象起了个名字：context rot（上下文腐烂）。

它和老朋友「Lost in the Middle」是两种病：后者是位置效应（模型对开头和结尾记得好，中间的会丢，Liu 等人 TACL 2024 就证明了），前者是长度效应（整体输入越长，质量越差）。生产环境里通常两个一起得。

Chroma 的数据里还藏着一个反直觉的细节：把文档顺序打乱，模型表现反而比逻辑连贯的原文更好——18 个模型一致。解释是：连贯的文本会制造「貌似合理的干扰项」，把注意力带偏。这暗示了一件事：上下文的敌人不是长度本身，是注意力预算的错配。Anthropic 后来在工程博客里把话说得更直白：去做上下文工程，本质是在给每一步找「最小的高信号 token 集合」——上下文是预算，不是仓库。

既然塞进去不免费，那「怎么塞、塞什么」就成了显学。这就是上下文工程（context engineering）这个名字的由来——它不是 prompt engineering 的改名换姓，而是把提示词从「一段话」升维成「一个被管理的系统」。

二、提示词优化的家谱：从许愿到搜索到反思

让 prompt 变好这件事，学术界其实已经迭代了三代：

  • 第一代：许愿。手工调词，玄学阶段。APE（自动提示工程）和 OPRO（DeepMind，用 LLM 当优化器迭代自己的提示词，「深呼吸」那篇）开始把「写 prompt」变成搜索问题。
  • 第二代：程序化。TextGrad 把「文本梯度」做成自动微分；DSPy 把 LLM 应用拆成模块，用 MIPROv2 这类优化器在模块空间里搜索最好的指令组合。
  • 第三代：反思进化。2025 年的 GEPA（已进 DSPy）是标志：它不搜索也不算梯度，而是让 LLM 读执行轨迹、用自然语言反思哪里错了、提出新指令，再维护一个帕累托前沿的候选池。结果相当惊人：在指令遵循基准 IFBench 上，GEPA 用 678 次 rollout 达到了强化学习 GRPO 需要 24,000 次才到的成绩——35 倍样本效率，平均还超 GRPO 约 10%。

GEPA 的意义在于证明了一件事：自然语言反思本身就是一种足够强的学习信号，未必非要动权重。但 GEPA 有个结构性弱点——它进化的是「整段 prompt 候选」，每次变异都是一次整篇重写，又贵又不稳。这就轮到主角登场了。

三、ACE：三个角色、一本剧本、只许打补丁

2025 年 10 月，Stanford 和 SambaNova 放出 Agentic Context Engineering（已被 ICLR 2026 接收），把这条线推到了工程完备的形态。它的核心不是什么新模型，而是一个朴素到近乎常识的主张：把上下文当作一本随经验生长的 playbook，并且只允许打补丁，不允许重写。

三个角色

  • Generator：干活的 agent。跑任务，产生轨迹，并顺手标注「这次哪些笔记帮了我、哪些误导了我」。
  • Reflector：复盘者。分析执行结果，把成败提炼成洞察（最多迭代五轮）。
  • Curator：图书馆员。把洞察转成结构化的「bullet」合并进 playbook，负责去重与裁剪。

playbook 里每条知识是一个带元数据的条目：

{
  "content": "查金融数据时先按日期范围过滤，缩小结果集",
  "helpful_count": 12,
  "harmful_count": 1,
  "section": "task_guidance"
}

计数器是灵魂：一条笔记被证明有用的次数多了，检索时优先注入；总是有害的，就该被裁掉。执行本身在给笔记投票。

Delta 更新：全篇最值钱的一个发现

ACE 团队观察到一个现象，值得每个做 agent 的人抄在墙上：LLM 有「简短偏置」。你让它重写自己的上下文，它一定会压缩、丢细节；几轮之后，笔记本坍缩成一段「要注意代码质量」式的正确废话——学习成果归零，论文称之为 context collapse。

解法粗暴有效：永远不让 LLM 整篇重写。playbook 表示为 bullet 集合，LLM 只被允许提案三种操作——add / remove / modify，合并与去重由轻量程序逻辑（非 LLM）完成。这本质上就是 git diff 之于整文件覆盖的区别。消融数据支持得很干脆：在 AppWorld 上，有增量更新的 ACE 相比无增量版，任务完成率 76.2 对 67.3，场景完成率 64.3 对 46.4——补丁不是锦上添花，是主要增益来源。

核心洞察一：自我重写的记忆必然失忆，自我打补丁的记忆才能积累。任何让 agent 维护长文档（规则文件、人格设定、操作手册）的系统，只要允许「总结重写」，就在给未来的坍缩埋雷。

四、成绩单，和两杯冷水

成绩单先看：

翻译一下：一个不动权重、只维护笔记本的 agent，在真实任务基准上追平了用最强闭源模型武装的生产系统，而学习成本比同类自适应方法低一个数量级。「怎么做」这类知识，放在上下文层比放在权重层划算得多——策略每周都在变，权重半年才更新一次，把高频知识写进慢速介质本来就是错配。

两杯冷水。第一杯：上下文学习不是万能药。GEPA 论文自己报了反例——在数学竞赛基准 AIME-2025 上，GRPO（更新权重）38.0% 对 GEPA 32.0%，RL 赢。笔记能教 agent「先按日期过滤再查」，教不会它做多重积分。流程型缺陷找上下文工程，能力型缺陷换模型或上 RL——分不清这两类，是今年 agent 团队最常见的资源错配。

第二杯：笔记本越长，检索和裁剪越重要。ACE 自己就用混合检索按相关性挑 bullet 注入，而不是全本硬塞——否则就撞回第一节的 context rot。

五、全行业正在独立重新发明这本笔记本

有意思的是，工业界根本没等这篇论文。看看时间线：

  • AGENTS.md：一个纯约定俗成的 markdown 文件，现在 OpenAI Codex、Cursor、Aider、Zed、Google Jules 等 20 多个工具都认——「给 agent 的项目说明书」成了事实标准。
  • Cursor rules：从单个 .cursorrules 进化成目录化的 .cursor/rules/，按 glob 模式分域生效——bullet 化 + 分区的工程版。
  • AgentSkills / SKILL.md：Anthropic 2025 年 12 月 18 日发布开放标准，48 小时内 Microsoft 和 OpenAI 接入，两个月后 VS Code GA。到 2026 年中，约 40 个产品兼容，SkillsMP 索引了 190 万个公开 skill。

这是三只不同毛色、同一物种的动物：分层的、可版本控制的、agent 按需加载的程序性知识载体。而 ACE 恰好给这个已经爆发的工业直觉补上了学术骨架——笔记本怎么进化（delta）、谁把关质量（Reflector + Curator）、怎么防膨胀（去重 + 计数裁剪）。

生态数据里最有价值的一条来自 SkillsBench：他们评了 4.7 万个公开 skill，平均质量 6.2/12——但经过策展的 skill 让 agent 任务通过率平均提升 16.2 个百分点。也就是说，价值不在「能写笔记」，在「养笔记」。190 万条里大多数是没人修剪的枝叶。

核心洞察二：AGENTS.md、Cursor rules、SKILL.md 是 playbook 的三个野生亚种；ACE 的贡献是证明了这本笔记可以由 agent 自己养，而且给出了「怎么养不养崩」的纪律。策展（Curator）不是可选项——190 万条低质 skill 就是没有 Curator 的世界线。

还有一句必须说的丑话：笔记本越长，攻击面越大。Snyk 的 ToxicSkills 报告和 Akamai 的 2026 威胁预测都把「skill 投毒」列为头部威胁——skill 运行在拥有 shell、文件系统、网络权限的 agent 肚子里，恶意 skill 继承宿主全部权限。而「自我进化的笔记本」（LLM 自动把外部内容吸收进上下文）把这条路又拓宽了一层。每条 bullet 都该有来源字段：谁写的、依据哪次执行、什么时间。

六、和上一篇拼起来：Agent 的三层记忆

上一篇讲事实记忆（用户是谁、什么在先、什么失效了）时说过：记忆不是仓库，是城市。这一篇补上了另一半拼图。现在可以画一张完整的分层图：

  • 事实记忆（是什么）：图结构 + 双时间戳，失效不删除——HippoRAG/Zep 那一路。
  • 程序性记忆（怎么做）：bullet 化 playbook + delta 更新 + 计数器策展——ACE 这一路。
  • 能力（能多难）：权重层，RL 和蒸馏的地盘，笔记帮不上。

人脑早就是这个架构：海马体管事实，基底核和新皮层管技能，而老师傅手边永远有一本翻烂的笔记本。三者更新频率差着数量级，混着用哪层都会出事。

七、可以立刻做什么

  • 今晚就能做：把你的 AGENTS.md / 规则文件 bullet 化。每条一段独立知识，带稳定 ID 和 helpful/harmful 计数。改造是纯增量的，git 天然支持。
  • 立一条铁律：禁止整篇重写。任何「帮我总结一下规则文件」的诉求，都改成 add/remove/modify 三选一的提案，由脚本合并。这是防 context collapse 的疫苗，一行代码都不用写，只用工纪律。
  • 每周做一次手动 ACE 循环：翻本周的失败案例（error log、复盘文档），让 LLM 当 Reflector 提炼洞察，你当 Curator 决定去留——一小时的事，笔记的质量差异是数十个百分点的。
  • 给笔记本配上守门 eval：挑一个反复出现的失败模式，量「注入对应 bullet 后 30 天复发率」。没有数字，「笔记变多了」只是安慰剂——SkillsBench 的 6.2/12 就是前车之鉴。
  • 装 skill 前看来源，写 bullet 时带 provenance。为将来接入自动 Curator 留好元数据，也为审计留好证据链。

结语

「Prompt engineering 已死」喊了两年，其实它没有死，是长大了：从给模型写一句话的许愿文学，长成了给 agent 养一本笔记本的园艺学。这本笔记要有结构（bullet）、有纪律（delta）、有新陈代谢（计数与裁剪）、有免疫（来源审计）。ACE 证明的与其说是一种新算法，不如说是一个朴素的管理学结论：一个组织的经验，只要能被便宜地写下来、认真地养起来，就能以远低于训练的成本复利。对 AI 如此，对你我亦然。
