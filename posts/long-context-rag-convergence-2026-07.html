当模型能读完一整本书，我们还需要检索吗？——长上下文与 RAG 的大收敛

2026-07-28 · 罗嵩 · Long-Context RAG Agent Memory Titans
设想你有一个图书馆大小的书桌，可以把所有参考书同时摊开。你还会用索引吗？2026 年，LLM 的上下文窗口已经突破 200 万 token——相当于一次性读完《哈利波特》全七部加《指环王》三部曲。但"能读"不等于"善用"。本文梳理长上下文与 RAG 从对立到融合的完整脉络，揭示三层记忆架构如何成为 Agent 的新标准。

一、一场被误读的"死亡竞赛"

2024 年初，当 Gemini 1.5 Pro 宣布支持 100 万 token 上下文时，技术社区出现了两种极端反应：

一派高呼"RAG 已死"——既然模型能一次性"看到"所有文档，何必还要向量数据库、chunk 分割、top-K 检索这些繁琐的管道？另一派则反驳："长上下文太贵、太慢，RAG 永远有存在价值。"

两年后的今天，答案逐渐清晰：两个阵营都说对了一半，也都错了一半。长上下文确实杀死了一种特定的 RAG——那种"把文档切成碎片、用向量相似度拼凑答案"的朴素 RAG。但它催生了更强大的新一代检索系统——一种和长上下文深度协同的"Agentic RAG"。

这不是零和博弈，而是一场架构收敛。

二、"Lost in the Middle"：长上下文的阿喀琉斯之踵

要理解为什么长上下文没有简单消灭 RAG，需要回到一个 2023 年的奠基性发现。

Stanford 的 Liu et al. 在论文 Lost in the Middle: How Language Models Use Long Contexts 中揭示了一个令人不安的现象：LLM 检索信息的能力高度依赖信息在上下文中的位置。

具体来说，当关键信息出现在上下文的开头或结尾时，模型的检索准确率可达 70% 以上；但当同样的信息埋在中间位置时，准确率骤降至 30% 以下——形成了一条完美的 U 形曲线。

这就像让人在一篇 5 万字的文章中找一句话——如果这句话在第一段或最后一段，你能找到；但如果它藏在第 47 页第三段，你很可能错过。模型也一样。

2025-2026 年的最新模型（Claude 4、GPT-5、Gemini 2.5）通过改进的位置编码、更丰富的长上下文训练数据，大幅缓解了这个问题。但"缓解"不等于"消除"。在超过 50 万 token 的极端场景下，位置敏感度仍然是影响性能的不可忽视的变量。

这正是 RAG 的第一个不可替代价值：把最相关的信息放在模型最容易被注意到的位置。

三、压缩记忆：让模型"无限"记忆的秘密

长上下文的另一个硬约束是计算成本。标准 Transformer 的注意力机制复杂度是 O(n²)——上下文长度翻倍，计算量翻四倍。一百万 token 的推理不是"贵一点"，是"贵到离谱"。

解决方案正在浮现，而且来自一个出人意料的方向：让模型拥有两种记忆。

3.1 Infini-attention：一个 Block，两种记忆

Google 在 2024 年提出的 Infini-attention 极其优雅：在一个标准的 Transformer block 中，同时保留两种注意力——

  • 局部因果注意力（短期记忆）：关注当前窗口内的 token，精确但容量有限
  • 长期线性注意力（长期记忆）：将历史信息压缩到一个固定大小的矩阵中，不精确但容量无限

关键洞察是：不需要记住所有细节，只需要记住"要点"。就像你读一本 500 页的书——你不会逐字记住每一句话，但你会记住关键论点、重要数据和叙事脉络。当需要具体细节时，你会翻回特定章节（这就是"检索"）。

3.2 Titans：在推理时"学习"记忆

2025 年初，Google 推出了 Titans，将压缩记忆推向了新高度。Titans 的核心创新在于：神经记忆模块在测试时（而非训练时）学习如何记忆。

这意味着什么？传统模型的记忆是训练阶段"焊死"的——你给它什么训练数据，它就记什么。Titans 不一样，它在推理过程中动态调整记忆策略：看到新的输入模式后，更新自己的记忆矩阵，使其在后续推理中更有效。

类比：传统模型像一个背了百科全书但不会变通的人——知识固定，应对方式也固定。Titans 像一个会"边工作边学习"的实习生——每处理一个新任务，都会调整自己的笔记方式，下次做得更好。

实验结果令人印象深刻：Titans 在超过 200 万 token 的 needle-in-haystack 任务中，准确率超越了标准 Transformer 和所有现代线性 RNN。而且它能做到这一切，同时保持快速并行训练和快速推理。

3.3 Miras：统一的记忆设计框架

如果说 Titans 是一个具体架构，那么 Miras（2025 年 4 月）则是一个元框架。它把 Transformer、Titans、Mamba、各种线性 RNN 统一到一个四维设计空间中：

设计维度含义现有选择
关联记忆架构记忆如何组织Transformer / 线性 RNN / 混合
注意力偏置如何衡量"相关性"点积 / L2 回归 / 新选择
保留门控如何决定遗忘硬门控 / 软衰减 / 任务自适应
学习算法记忆如何更新梯度下降 / 在线学习 / 测试时学习

Miras 最有趣的发现是：大多数现有模型只探索了这个设计空间的一个极小角落。他们只用了点积相似度或 L2 回归作为注意力偏置，而其他组合可能带来质的飞跃。

四、新分工：RAG 的角色重塑

有了压缩记忆和长上下文的加持，RAG 的角色发生了根本性转变：

2023 年的 RAG2026 年的 RAG
定位上下文不够长的补丁信息质量的过滤器
目标找到可能相关的片段精确选择最有价值的信息
后续拼接到 prompt 里注入分层记忆系统的合适层级
质量要求召回率优先精度和召回率并重

Anthropic 在 2024 年提出的 Contextual Retrieval 是这种转变的标志性实践：在向量化之前，先用 LLM 为每个文档块生成一段上下文摘要，然后再做嵌入。这个简单的改进将检索失败率降低了 49%，而借助 prompt caching，成本可低至 $0.06/百万 token。

核心思路：不要让检索系统"裸奔"。给它上下文，让它理解每个片段在整体中的位置和意义。

五、三层记忆：Agent 架构的新标准

综合以上趋势，2026 年生产级 Agent 的记忆架构正在收敛到一个清晰的模式——三层记忆：

第一层：工作记忆（Attention）

就是模型的上下文窗口。用于处理当前任务的直接信息：用户消息、系统提示、当前对话历史。容量 100K-2M token，速度快，会话结束即清空。

第二层：压缩记忆（Neural Memory）

跨会话的语义摘要。不是逐字存储对话历史，而是提取关键信息、用户偏好、任务模式。可以是 Titans 式的神经记忆，也可以是结构化的摘要文件。

第三层：持久存储（External Database）

向量数据库 + 知识图谱 + 关系型数据库。存储完整的文档、对话日志、代码仓库。当压缩记忆不够用时，从这里检索。

这和人脑高度类似：工作记忆 = 前额叶皮层（处理当前任务）→ 压缩记忆 = 海马体（将短期经历转化为长期记忆）→ 持久存储 = 新皮层（存储一生的事实和技能）。五亿年的进化产物和两年的工程产物殊途同归。

六、实践指南：你现在可以做什么

策略 1：RAG-First, Long-Context-Second

不要一上来就把所有文档塞进上下文窗口。先用 RAG 检索 Top-K 相关文档（广度扫描），再将这些文档完整送入长上下文模型深度推理。成本通常是全量注入的 1/5 到 1/10。

策略 2：升级到 Contextual Retrieval

如果你的 RAG 系统还是"切 chunk → 向量化 → 检索"，加一步：在向量化前，用 LLM 为每个 chunk 生成 2-3 句的上下文摘要，拼接到 chunk 前面。这是目前投入产出比最高的单点优化。

策略 3：为 Agent 建立三层记忆

不要把所有历史都塞进 prompt，也不要完全依赖外部检索。建立：当前会话的上下文窗口 + 每日自动生成的摘要文件 + 向量+图数据库。让 Agent 自己决定何时查哪层。

策略 4：测试而非假设

不要只看模型标称的 context window 大小。用你的真实工作负载做 needle-in-haystack 测试：在 50 万 token 的文档中随机位置插入一条关键信息，看模型能否准确找到。不同模型在真实场景下的表现差异远大于 benchmark 数字。

策略 5：关注 Miras 设计空间

如果你在研究新架构或训练自定义模型，不要被 Transformer 锁住。Miras 框架证明：在注意力偏置、保留门控和学习算法三个维度上，还有大量未被探索但极具潜力的组合。

七、结语：不是"谁替代谁"，而是"如何协作"

回到开头的问题：当模型能读完一整本书，我们还需要检索吗？

答案是：比以往更需要——但原因完全不同了。

过去，RAG 是"上下文太短的补丁"。现在，RAG 是"信息质量的守门人"。长上下文让模型有了"深度阅读"的能力，但深度阅读的前提是读对了东西。在一个信息爆炸的时代，"找到对的"比"读完所有的"重要得多。

长上下文和 RAG 的收敛，本质上是在回答一个更深层的问题：智能不是一个维度上的极致，而是多个维度的协调。注意力负责精确，压缩记忆负责持久，检索负责广度。三者协作，才构成了真正可用的 Agent 记忆系统。

下一个两年，我们大概率会看到 Titans 式的压缩记忆被集成到主流 LLM 中，而 RAG 系统会变得更加"Agentic"——不再是被动地等待查询，而是主动地预测 Agent 需要什么信息，提前准备好。

到那时，"长上下文 vs RAG"这个二分法将彻底失去意义。取而代之的问题将是：如何设计一个让三层记忆无缝协作的系统？
