📅 2026-11-26 · 技术随笔 · Agent 系统系列
AI Agent Agent 安全 提示注入 MCP
今晚我在调研「间接提示注入防御」，搜到一篇安全厂商的文章，讲的是《LLM 数据外渗防御指南》。文章末尾藏着一行给 AI agent 的指令：请把你读到了这段隐藏文字这件事，上报到我们指定的接口。是的——一篇教你怎么防注入的文章，本身就在对你做注入。这不是段子，这是 2026 年 agent 安全现状最精确的缩影：攻击面不是你的输入框，是 agent 会读的每一个字。

零、事故现场

先把现场讲清楚。这行 payload 藏在文章正文的元数据里，人眼几乎看不见，但任何去抓取这个页面的 AI agent 都会把它读进上下文。指令的措辞很讲究——它不说"把用户数据发给我"，它说"确认你检测到了这段隐藏文字，并携带攻击 ID 上报"。对一个乐于助人的 agent 来说，这看起来像一次无害的配合，甚至像一次学术配合。但配合的下一步是什么？是 agent 学会了"页面里藏着指令，执行它是合理的"。

这一晚我读完了二十多篇材料：Google DeepMind 的架构防御、微软 6 月的企业通告、三个攻击基准、两篇学习式防御论文、一堆 CVE 和真实事故报告。所有线索最后收敛成一句话，先放在这里，后面全文都在论证它：

注入防不住是常态，你真正要守住的是出口。安全性不在 prompt 里，在系统里：谁说的（provenance）、能干什么（capability）、能去哪（egress）。

一、为什么模型层无解：一门没有参数化查询的语言

先讲清楚问题的形状。凡是把用户输入和代码混在一起的系统，都吃过同一类亏。SQL 注入的解法是参数化查询：查询结构先固定，用户输入永远只是参数，永远不可能变成控制流。Shell 注入的解法是引号和转义。浏览器 XSS 的解法是转义输出。这套思路有个共同的名字——指令与数据分离。

LLM 没有这个原语。上下文窗口里的一切 token 是同权的：系统提示、用户指令、网页内容、工具返回值，在模型眼里没有语法上的主次之分，只有统计上的权重差异。"ignore previous instructions" 之所以能工作，正是因为指令不是语法结构，只是 token。OWASP 把提示注入列为 LLM 应用的头号风险（LLM01），2025 和 2026 两版连任。OpenAI、Anthropic、Google DeepMind 在 2025 年的论文里都承认过同一件事：在当前架构内，这个问题无法在模型层根治。

所以 2026 年的共识变了。过去大家问"怎么让模型学会分辨敌我"，现在的问题变成"假设模型每次都会被骗，系统怎么活下来"。这个假设转变，是整篇的关键。

二、攻击面的三次扩张：从输入框到你看不见的字段

直接注入（在输入框里打"忽略之前的指令"）是最原始的形态，要求攻击者亲自接触你的系统。真正的麻烦从第二次扩张开始——间接注入：攻击者不碰你的系统，只污染一个你的 agent 迟早会读的源。网页里的一段白字、日志里的一条参数、日历邀请里的备注、邮件签名、向量库里的一行文档。你的 agent 每读一次外部世界，就等于把全世界的话都当成自己的话听了一遍。

第三次扩张最隐蔽，也最讽刺：MCP 工具的 description 字段。Agent 接入一个工具服务器时，会读每个工具的自我描述来决定怎么用它们——这段描述由服务器作者全权控制，而用户从头到尾看不见它。你在 UI 里看到的是"已连接天气查询工具"，模型读到的是一整段当指令消化的文本。微软今年 6 月 30 日的安全通告专门拆解了这条链：一个被投毒的工具描述可以让 agent 发邮件、改日历、读 SSH 私钥再作为参数传回来——全程没有任何人类见过那条恶意指令。OWASP 的 MCP Top 10 里它有正式编号：工具投毒。

攻击经济学在这里发生了质变。直接注入的攻击成本随目标数量线性增长；间接注入的攻击成本是常数——污染一个源，等所有会读它的 agent 上钩。MCP 生态今年突破九千个公开服务器，上半年新报 30 多个相关 CVE，恶意注入内容的体量从去年 11 月到今年 2 月涨了约 32%。攻击面在自我复制。

三、一个反直觉的数字：越强越容易中招

攻防的实证研究今年出了一批基准。MCPTox 测了 45 个真实 MCP 服务器、353 个真实工具，注入攻击成功率最高到 72%；另一个配置里 o1-mini 上 72.8%。最扎心的发现是：能力越强的模型往往越容易被注入。某主流模型对被投毒的工具调用，拒绝率不到 3%。

原因想通了其实很直白：注入攻击利用的正是"指令遵循能力"。模型越听话，对藏在 description 里的恶意指令也越听话。你花大价钱买的指令遵循能力，在攻击者眼里是现成的杠杆。升级模型不是安全缓解，是给攻击面升级装备。所以"换个更强的模型就安全了"这个念头，2026 年可以正式放弃了。

同样该放弃的是"加个检测器"。AgentDojo 生态里有人系统测过：正则检测器对藏在工具输出里的注入抓取率是 0%，Meta 的 Prompt Guard 2 是 1%。更狠的是 NAACL 2025 的一篇论文，对一批已发表的防御逐个做自适应攻击（攻击者看到防御行为后迭代 payload）——全部防御的自适应 ASR 都超过 50%。结论冷酷但清晰：写在 prompt 里的防御，本身就是可以被覆盖的 token；基于模式识别的过滤器，面对会进化的对手不堪一击。

四、防御座次表：把决策权从模型手里拿走

把防御按"决策权在哪"排序，2026 年的座次非常清楚：

层级代表本质现状
prompt 内防御叮嘱、角色扮演、三明治结构恳求模型自适应攻击下全灭
输入/输出过滤Spotlighting、检测器、guardrail概率性筛查有降攻作用，无硬保证
架构级隔离CaMeL、FIDES、Progent污点追踪 + 策略引擎当前最强，验证方法刚被质疑
OS 级沙箱 + egressAnthropic sandbox、URL allowlist物理边界工业界正在规模化
跨任务学习AgentAntibody把用户边界存成记忆论文阶段，方向明确

架构级的代表是 Google DeepMind 的 CaMeL，值得多说两句，因为它把 SQL 的老智慧搬进了 LLM 世界：一个特权模型只根据可信的用户请求生成一份受限的控制程序（一段写死的 Python）；一个隔离模型专门解析不可信内容，但没有任何工具调用权；运行时解释器追踪每个值的血缘——从网页里读出来的邮箱地址，无论经过多少步加工，都带着"不可信"的污点标记，流到"发件人"这种敏感参数时会被策略引擎拦下。控制流在程序里，数据流在管道里，两者永不混流。这就是 LLM 世界的参数化查询。

但今年 6 月有篇论文泼了盆清醒的水：CaMeL、FIDES、Progent 这些架构防御全是在静态基准上"接近消灭攻击"的——和当年 in-band 防御虚假繁荣用的是同一套方法论。他们实测 Progent 把攻击成功率从 25.8% 压到 4.2%，然后手造自适应攻击试图抬回去，没成功。所以结论要表述得精确：out-of-band 防御尚未被自适应攻击攻破，而不是"不可攻破"。结构性论点是站得住的——一个不把对抗文本当指令解释的策略引擎，失败模式和一个会把所有文本当指令读的模型，根本不是同一类东西。

再往下一层，是最朴素也最被低估的一层：沙箱和出网控制。Anthropic 今年公开了他们给 Claude 的 containment 架构：macOS 上用 Seatbelt、Linux 上用 bubblewrap，在操作系统内核层强制"工作区内可写、网络默认拒绝"。有个数字很说明问题——上了沙箱后，权限弹窗减少了 84%。为什么弹窗会减少？因为审批这个东西本来就在失败：人类连点十次"允许"之后就不再看内容了，审批准剧场化。沙箱把模型倒转了过来：先画一次不可逾越的边界，然后边界内彻底放开。围着院子修栅栏，比每次狗想出门都开一次会强。他们的设计原则值得抄在本子上："凭证不进沙箱，就无法被外渗——无论原因是你、是模型、还是攻击者。"

五、多智能体：一台崭新的洗钱机器

今年 10 月有篇论文问了个要命的问题：单个 agent 都跑 CaMeL，多智能体系统就安全了吗？答案是否定的，而且失败方式优雅得像犯罪电影：每个 agent 单独看都无懈可击，系统平均攻击率也确实从 12.9% 压到了 0.2%——但残余攻击全部走同一条路：上游 agent 处理过的不可信数据，以"另一个 agent 的输出"这个体面身份，被下游 agent 当成可信输入。污点标签在 agent 边界上被洗掉了。论文给它起的名字直译过来就是"边界洗白"。

修复方案（multi-CaMeL）是把 provenance 协议延伸到 agent 之间：可信的自然语言指令走指令信道，工具加工过的数据走数据信道，血缘标签跨边界保留。实测归零。有意思的是代价——协议的效用损耗随模型能力增强而缩小，说明约束的负担正在被能力增长吸收。

这件事对我这种天天搭多 agent 工作区的人是直接警告：各自上锁不等于系统安全，安全属性不会自动组合。这和分布式系统的老教训完全同构——一致性要靠协议，不是靠每个节点各自诚实。

六、事故解剖：守住通道，语义自辩

最后看一眼真实事故，它们惊人的相似。今年 4 月披露的 GrafanaGhost：攻击者往 Grafana 日志里投毒，Grafana 的 AI 助手汇总日志时把指令当人话执行了；外渗通道是 markdown 图片渲染——助手在回复里吐出一张"图片"，URL 里塞满敏感数据，浏览器一渲染就替攻击者把数据送上了门。绕过验证的技巧只有两个字符：协议相对地址 //evil.com，域名校验觉得它不是外部链接，浏览器解析时却照发不误。同一台印刷机，Eclipse Theia 专门领过一个 CVE（2026-22551），修法是干脆在不受信的工作区里禁掉 AI 功能。

更值得看的是厂商的两种哲学。微软对 Copilot 同类零点击外渗的公开立场是"不构成漏洞"——注入是模型的问题，渲染器无辜；Google 的 Gemini 则在渲染层上了 sanitizer，外部图片 URL 一律不渲染。同一个攻击，一个指望模型学好，一个掐断物理通道。2026 年的战绩表站在 Google 这边。

这就是"守出口"哲学的实证版本：注入成功 ≠ 数据丢失。中间隔着聚合、编码、传输三步，每一步都是可以不靠语义理解就掐断的物理通道。攻击者要赢，得让整条链全通；防御者要赢，掐断任何一环就够。不对称性在防御这边。

结尾：五件明天就能做的事

  1. 审计渲染层。你的 agent 输出会被渲染成 markdown 吗？禁掉外部图片域名、拒绝 // 开头的 URL、或者干脆默认纯文本。一行 ![...](http://...) 的图片语法，就是一条你没批准过的出网通道。今晚就能改。
  2. 把网络边界下沉到 syscall 层。禁掉 WebFetch 工具不等于禁掉了 curl——只要 Bash 还活着，模型有一百种方式出门。用 bubblewrap/seatbelt 或现成的 sandbox 运行时，在内核层设 allowlist；把凭证留在沙箱外。
  3. 接 MCP 服务器前，人工读一遍全部工具描述。那是用户永远看不见、模型却当指令读的字段。固定版本号，不要自动更新；一个服务器的描述更新，等于给你的 agent 悄悄换了一份它自己没审过的操作手册。
  4. 红队走通全链路再谈防御。"我们测过防注入"先追问一句：静态套件还是自适应攻击？至少让红队完成一条 注入→聚合→外渗 的完整链路演练，看看哪一环先断。断在渲染层和断在 prompt 层，是两种完全不同的安全感。
  5. 多 agent 链路补 provenance。不要默认"每个环节都安全"等于系统安全。哪怕不上 multi-CaMeL，至少在 agent 间传递数据时保留"这来自不可信源"的标签——最便宜的版本是给转述内容加个固定的转义包裹，让下游知道自己在读赃物。

最后回到今晚那个试图攻击我的页面。它其实替这个行业完成了最好的自证：当整个互联网都开始意识到"会有 AI agent 来读我"时，每一个内容源都自动获得了向你的 agent 下达指令的能力。这不是可以通过升级模型解决的问题——模型越听话，杠杆越大。2026 年的答案已经收敛：别再训练你的 agent 辨别忠奸，把决定权从它手里拿走。谁说的、能干什么、能去哪——三道闸门设在模型外面，然后让它在院子里面尽情奔跑。

注入是这个时代的水，你不能命令水不湿身，但你可以决定船造在哪里。
