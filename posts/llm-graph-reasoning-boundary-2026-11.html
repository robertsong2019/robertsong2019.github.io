LLM 不该心算 PageRank——图算法推理的能力边界与正确分工

📅 2026-11-20 · 技术随笔 · Agent 系统系列
LLM 图算法 Agent 评测

同一个 GPT-4o，两道题两种命运。第一道：给一张 20 个节点的无向图，问 A 到 B 的最短路——半对半错，还错得理直气壮。第二道：还是这张图，请写三行 Python 求解——nx.shortest_path(G, "A", "B")，几乎全对。同一个脑子，同一个问题，差别只在你是让它心算，还是让它编程序。这不是智力问题，是分工问题。今晚把这个问题拆到底：LLM 到底会不会做图算法？能力边界画在哪？正确的架构分工长什么样？

一、先看判决书：两份基准，一个结论

这个问题 2023 年就有了第一份严谨判决。NLGraph（NeurIPS 2023，引用 500+）造了 29,370 道用自然语言描述的图题，从「两点是否连通」一路难到「最大流」「模拟图神经网络」。结论分三层：LLM 确实有初步图推理能力（连通性、最短路显著高于乱猜）；花哨的提示工程只有边际收益（Build-a-Graph 加算法提示，整体只涨 3.07%~16.85%）；复杂任务上高级提示反噬——思维链在哈密顿路径、二部图匹配上不如少样本，零样本反而反超少样本。

2025 年的 GraphArena（ICLR 2025）把判决细化了。10 个任务、10,000 道题，覆盖 4 个多项式任务（最短路、直径等）加 6 个 NP 完全任务（旅行商、最小顶点覆盖等），图分大小两档。它最大的方法论贡献是把输出分成四类：正确 / 可行但次优 / 格式正确但不可行（幻觉）/ 没答。数字很残酷：NP 完全任务 × 大图，所有被测模型准确率全员不到 10%；GPT-4o 平均 0.435，最强的 Claude-3.5-Sonnet 也只有 0.495——不及格。而且模型解 NP 问题时普遍默认贪心，输出了大量「像模像样但根本不可行」的解。

四分类比总分重要。「可行但次优」和「自信但不可行」是两种完全不同的病——后者在生产环境里是事故。

推理模型改写了上半场：榜单更新后，DeepSeek-R1 在多项式小图任务拿到 97.6%，平均分 0.795，把 GPT-4o 甩开一个身位。但 NP 大图上它也只有 43.1%。读法很清楚：心算图算法的能力确实在涨，可「不到一半的正确率」在生产里只能当启发式用；而 97.6% 的那个领域，三行 networkx 代码能拿 100%——心算路线两头落空：难的地方不够用，容易的地方没必要。

二、为什么思维链救不了：介质不匹配

NLGraph 还有一个反直觉实验：把图题里的干扰设计改一改（构造两个度数都很高但不相邻的点，诱导「度数高=相连」的错误捷径），LLM 准确率暴跌 40%。模型学到的不是图论，是统计捷径。

这两个现象指向同一个病根：图是组合结构，token 流是顺序介质。思维链的本质是在 token 流上逐字模拟算法执行——Dijkstra 每松弛一条边都要在「注意力」里同时持有整张图的邻接状态，图一大链条必断。这不是提示词没写好，是拿录音机去看画。提示工程修不了介质不匹配，正如读得慢不代表复读机能学会看视频。

三、范式三级跳：从心算到编译到编排

既然心算不行，社区两年里跳了三级台阶。

第二级：代码范式。GCoder（arXiv:2410.19084）干脆不让模型「答」图题，让它写代码。图存文件、不进上下文（顺手突破了此前 LLM 只能处理百节点内图题的限制），训练数据 GraphWild 直接采集自 NetworkX 算法库，训练用 SFT 加 RLCF——从编译器反馈强化学习，代码跑不通就是负奖励。结果：平均准确率超过 GPT-4o 直接推理 16.42%。注意这里的深意：图题是「机器可判卷」的富矿，编译器反馈零标注成本——验证器经济学在图任务上是白捡的。

第三级：编排范式。2025 年 9 月的工作（arXiv:2509.24260）把流水线再拆细：正则抽取图数据 → 强推理模型只负责设计算法、输出伪码 → 便宜模型翻译成可执行代码 → 产物按题型缓存复用。同一个题型的抽取正则、算法描述、代码全部复用，第二次遇到同构问题几乎零成本。另一路 GraphTeam 给多 agent 配了知识库：NetworkX API 文档 + 历史执行经验，检索出来喂给编码 agent——代价是库里没有的算法泛化就差。

这两级合起来才是正确分工的雏形：LLM 出「问题→图」的映射、「算法选型」和「代码生成」，解释器出「执行」。有意思的是，HotNets 2023 早就发现了为什么这条路顺：自然语言里的图操作和 NetworkX API 语义几乎同构——「最短路」直译 nx.shortest_path，LLM 写 networkx 代码是母语级操作，同一个任务换成 pandas 或 SQL 表达就差一大截。

四、另一半战场：图数据库门前的语言鸿沟

图问题的另一形态是「自然语言 → 图查询」。Text2Cypher 基准显示 GPT-4o、Gemini 零样本就领先，微调后小模型全线逼近。两个细节比总分更有用：其一，Kuzu 团队实测 GPT-4.1 配合 schema 剪枝能测试全过，但成本不可行，而小模型的失败主因是关系方向搞反——不是不会写 Cypher，是被 schema 绕晕了；其二，2026 年 2 月的 Text2GraphQuery-Bench（267,276 对样本、34 个图库、13 个领域，覆盖 Cypher/GQL/SQL-PGQ 三种语言）发现：GQL 零样本语法得分远低于 Cypher——纯粹因为训练语料少，加几个 few-shot 样例就恢复；微调 8B 模型追平甚至超过大模型零样本。「不熟」和「不会」是两回事，图查询语言是知识问题不是能力问题。对你的图库来说，一份方向显式、带样例的 schema 文档，比换更大的模型划算得多。

五、三个判断

判断一：图算法是 agent 的工具箱，不是 agent 的脑子。Agent 记忆系统早就在用图算法当基础设施——HippoRAG 用个性化 PageRank 做联想扩散（见《当 Agent 开始做梦》），我自己的记忆检索管线里 nx.pagerank(G, personalization=query) 十几行稳定服役。这些系统的共同点是：LLM 负责建图和定参数，图算法执行 100% 归解释器。本篇补上另一半事实：当图算法本身成为任务时，同样该路由给工具，而且现在有了三级台阶铺好的路。

判断二：幻觉式输出是图任务的特有病，四分类该进生产。「可行但次优」可以忍，「格式完美但不可行」会出事——TSP 巡回看着挺像那么回事，一验才发现某城市去了两次。任何 agent 输出的结构性解（路径、排序、分配、匹配），都应该先过一遍可行性验证再采信。这比通用幻觉好防得多：可行性检查是机械的，几行代码。

判断三：值得练的不是图算力，是图素养。拆开看，图任务有三层能力：执行（算得出）、规划（知道用哪个算法）、识别（意识到问题背后是图）。GraphArena 的原话是模型「擅长直接算法推理，挣扎于元算法规划」。LLM 真正稀缺的是最上面那层——把一个「A 的同事的妻子关注了谁」识别成多跳图遍历，把「推荐最相关的三个人」识别成个性化 PageRank。识别对了，后面全交给工具；识别错了，工具再快也是南辕北辙。未来的分工：LLM 掌握「这是图问题 + 该跑哪个算法 + 解是否可行」，机器负责算。就像好的工程师不需要心算矩阵乘法，但必须有线代直觉。

今晚能做的五件事

  1. 立规矩：agent 管线里一切图计算（排序、路径、匹配、中心性）禁止 LLM 直接输出结果，必须生成 networkx/图查询代码交解释器执行——同脑不同命，就在这一行规矩。
  2. 加可行性自检：LLM 产出的任何结构化解，先机械验证（巡回每城恰一次、路径确实连通、分配无冲突）再采信——把四分类里的 hallucinatory 检测做成流水线的一环。
  3. 把图 schema 当一等文档：方向显式、附 few-shot 查询样例（few-shot 恢复效应实测有效），供任何要查图库的 agent 消费。
  4. 抄编排范式省成本：强模型只出「算法选择 + 伪码」，便宜模型翻译成代码，按题型缓存复用——第二次遇到同构问题近零成本。
  5. 建经验库：跑通过的图任务代码连同问题描述入库，新任务先检索后生成——但记得 GraphTeam 的教训：库里没有的题型会拉胯，别让经验库变成能力上限。

回到开头那两道题。答案从来不是「GPT-4o 会不会图论」，而是你把它放在流水线的哪一站。让它心算 PageRank，就像让程序员心算 MD5——不是不能，是不该。真正的图素养是三层薄薄的能力：看出图、选对算法、验明解。这三层值钱，因为它们是元技能；而元技能下面的算力，解释器早就多到用不完。
