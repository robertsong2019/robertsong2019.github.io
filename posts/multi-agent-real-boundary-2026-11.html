+90% 与 −70% 是同一个机制——多智能体的真实边界

📅 2026-11-22 · 技术随笔 · Agent 系统系列
Multi-Agent AI Agent 上下文工程 架构决策 Token 经济学
同一个夏天，同一种技术，两家顶级实验室给出方向相反的头条：Anthropic 说内部评测多智能体比单智能体好 90.2%，Cognition 发文《别做多智能体》。更魔幻的是——他们都没说谎。这篇讲清楚 +90% 和 −70% 为什么是同一枚硬币的两面，以及怎么在动手前判断自己拿到的是哪一面。

三个数字的罗生门

2025 年 6 月，Anthropic 发布多智能体研究系统的构建复盘：主 agent 派生 3–5 个子 agent 并行检索，在内部研究评测上比单 agent Opus 4 提升 90.2%。同一周，Devin 背后的 Cognition 发布《Don't Build Multi-Agents》，给出两条原理：上下文隔离会让 agent 丢失关键决策信息；每个动作都携带对全局状态的隐式判断，拆给多个 agent 就是让这些隐式判断互相打架。

到 2026 年，证据链补全了。一项覆盖 180 种配置的对照研究给出了两个方向的数字：可并行的金融分析任务，多智能体 +80.9%；顺序推理任务，多智能体 −39% 到 −70%——所有测试过的多智能体变体全部劣于单 agent。Berkeley 的 MAST 研究则解剖了七个开源框架的 1642 条执行轨迹：失败率 41.8%–86.7%，其中 44.2% 是系统设计问题，32.35% 是 agent 间错位，23.5% 是任务验证问题。

三组数字并不矛盾，它们指向同一个变量：任务子部分之间的上下文耦合度。

一、上下文耦合度：唯一的先验判据

把一个任务拆给多个 agent，本质不是「分工」，而是上下文切割。每个子 agent 拿到的是完整任务的投影——它看不到别的 agent 看到的东西。

这个切割在两种任务上产生截然相反的效果：

低耦合任务（广度优先的读）：调研「X 领域十家公司的技术路线」，子问题互相独立、只读外部信息源、不改共享状态。切割 = 每个子 agent 拿到一份干净的上下文，没有无关信息的注意力污染。这是 Anthropic +90% 的场景，也是他们自己注脚里的边界——「高度相互依赖的工作是多智能体的糟糕适配」。

高耦合任务（顺序依赖的写）：改一个跨五个文件的 bug。第二步的方案取决于第一步改了什么、为什么这么改。切割 = 每个子 agent 都在做「不了解前情提要的决策」，然后把冲突的决策合并。这就是 Cognition 的两条原理，和 −70% 的来源。

一句话记住边界：读任务并行是红利，写任务并行是协调地狱；读写混合的任务，在架构上把读和写分成两个相。子任务间共享状态只读且可独立合成结论，多智能体大概率赢；共享状态被顺序修改，单 agent 大概率赢。

二、失败是组织问题，不是模型问题

MAST（Multi-Agent System Failure Taxonomy，NeurIPS 2025）最有价值的发现不是 14 种失败模式本身，而是两个结构性结论。

第一，失败方式和人类团队失败同构：最高频的失败模式是「步骤重复」（15.7%——两个 agent 干了同一件事），其余包括角色违规（某个 agent 越权终止了整个流程）、信息隐瞒、验证形同虚设（代码能编译≠符合需求）。44% 的失败归类于「规格与系统设计」——是组织架构的锅，不是模型智商的锅。

第二，各类失败模式之间的相关系数只有 0.17–0.32。这意味着没有银弹：修好「终止权归属」（给 ChatDev 的 CEO agent 终审权，+9.4%）不会顺带修好「信息隐瞒」。实验里重设计拓扑能把正确率从 25% 拉到 40.6%——有效，但离生产可用还远，而且每一个失败面都需要单独的结构性修复。这就是为什么「加一个协调 agent」通常让系统更糟：你用引入新失败面的方式去修旧失败面。

对工程师的启示很直接：多智能体系统是分布式系统，要按分布式系统的方法对待——显式定义接口、数据格式、终止条件，而不是按「一群聪明人开会」的直觉对待。

三、辩论的幻觉：质量打败多样性

多智能体的流行叙事里有个更古老的分支：让几个 agent 辩论，真理越辩越明。证据不支持。

正面的例子真实存在：Mixture-of-Agents（ICLR 2025）用纯开源模型层叠聚合，在 AlpacaEval 2.0 上拿到 65.1%，胜过当时 GPT-4o 的 57.5%。「collaborativeness」现象是真的——模型看到其他模型的输出后，确实会产出更好的答案。

但 Princeton 的 Self-MoA 反转了剧本：不用不同模型，只用单一最强模型自采样聚合，结果比混合模型 +6.6%。原因朴素得扎心——聚合质量对成员质量高度敏感，混入弱模型是在拉低均值。「多样性带来提升」的前提是成员质量足够接近，而这个前提在模型能力快速分化的时代越来越难满足。至于辩论（debate）文献的验尸结论更冷：收益大多来自答案格式对齐（锚定了彼此的表述方式），而不是正确性提升。

再算上「More Agents Is All You Need」那类采样投票实验，把「多 agent」的收益来源拆开看，其实是四种被混为一谈的机制：额外的推理算力、并行性、模型多样性、真正的协作。前三种，单 agent 加采样预算、加并行调用、换更强模型，大多能等价获得。只有第四种——分工、交接、相互验证——是多智能体独有的，而它恰恰是 MAST 显示最容易做错的部分。

四、脚手架不是终点：模型越强，红利越薄

还有一个长周期变量：arXiv 2505.18286 的系统对比发现，ChatGPT 时代多 agent 框架报告的增益，用 Gemini-2.0-Flash 单 agent 就能复现相当部分——很多「协作收益」其实是对基线模型能力缺陷的补偿，基线变强，收益蒸发。Token 账也在恶化：多智能体的 token 倍率实测在 4–220 倍之间（Anthropic 系统约 15 倍），而收益端的上限随模型增强持续缩水。

当然，极端反例依然坚挺：复杂规划任务上多智能体 42.68% vs 单 GPT-4 的 2.92%——能力缺口越大，脚手架越值钱。所以 2026 年的工程共识收敛成 MIT 那句最硬的判据：加一个 agent / 一个阶段，只有三种情况值得——引入新的外生信号、更好保留决策相关信息、提供非冗余的审查。三者皆无，就是纯税。

注意第三条「非冗余审查」是多智能体最被低估的合法用途：验证器视角不同的多个审查者（而非多个执行者）能提供真正独立的错误检出。前提是你先有值得独立的验证器——验证能力没跟上，多智能体放大的不是产出，是错误产量。

结尾：动手前三问

回到开头：+90% 和 −70% 为什么都没说谎？因为多智能体从来不是智能放大器，它是一种上下文工程手段——用隔离换干净，或者用隔离换失忆，取决于你的任务。判断只需要三个问题：

  1. 子任务间的共享状态是否只读？有顺序写操作 → 单 agent。
  2. 每个子 agent 的上下文能否自足？需要父会话全部历史才能干活 → 单 agent。
  3. 结果能否由固定判据合成？合成本身需要「品味」级判断 → 要么单 agent，要么把合成做成显式的第二阶段并给它独立预算。

三问全过再上多智能体，并且预算好 4–15 倍的 token、按分布式系统的纪律写接口和终止条件。三问有任何一问含糊，Anthropic 的建议就是最好的建议：先找最简单的单 agent 方案，把多智能体留给被测量逼出来的那一天。

多智能体解决的是上下文装不下的问题，不是脑子不够用的问题——把后者当前者，是这一代架构里最贵的误会。
