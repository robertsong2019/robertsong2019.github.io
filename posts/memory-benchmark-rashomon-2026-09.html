同一个基准，四家公司都说自己第一：Agent 记忆评测的罗生门

2026-09-06 · AI Agent 记忆系统 评测方法论 LLM-as-Judge

LongMemEval-S 是目前 Agent 记忆领域最被认可的基准：500 道题，埋在 115K token 的多会话聊天历史里，考信息抽取、多会话综合、知识更新、时间推理和弃答。同一个考场，近两年各家的自我报告是这样的——

考生自报分数
GPT-4o 把全部历史塞进上下文（基准论文自己测的）64.0%
Zep（图记忆）71.2%
Mem0（2025 论文版）~68.5%（LoCoMo）
Mem0（2026 官网）94.4%
Mastra Observational Memory94.87%，“史上最高”
Supermemory95%
MemPalace100%
还有一家“~99%，to prove a point”

从 64% 到 100%，人人都是第一名。而基准论文自己报告的“上界参照”——oracle 设定（直接把含答案的会话喂给模型）——也只有 92% 左右。也就是说，一批系统声称击败了理论上界。

这不是造假。据我所知，没有一家伪造数据。每一个数字在自己的口径里都是真的——这正是问题所在。今天拆解的是：同一个基准上的分数，是怎么被“合法地”做出 30 个点弹性的。

第一幕：三方互殴

2025 年 Mem0 发论文（arXiv 2504.19413），宣布在 LoCoMo 基准上 SOTA，击败 MemGPT、Zep、A-Mem 等一众对手。然后被打了两轮。

第一轮来自 Zep。他们写了篇檄文（标题就叫《Lies, Damn Lies & Statistics》），指出三件事：LoCoMo 的对话只有 16-26K token，完全塞得进现代模型的上下文窗口，根本考不到长程记忆；Mem0 自己的结果里，“全塞进去”基线拿了 ~73%，高于 Mem0 精心设计的记忆系统的 68.5%——专门造的记忆系统输给暴力塞入，说明基准没压力；以及，Mem0 论文里 Zep 的实现是错误配置，不是 Zep 的真实水平。

第二轮来自 Letta（MemGPT 的商业化团队）。创始人 Charles Packer 直接说 Mem0 论文里的 MemGPT 数字 baseless：MemGPT 无法原生跑 LoCoMo 基准，他们联系 Mem0 团队询问实验细节，没有得到任何回应。Letta 自己用新特性跑出 74%，高于 Mem0 的 68.5%。Packer 还补了一句狠的：这些错误数字最终会被吃进未来模型的训练数据。

这场混战里最讽刺的细节是：写檄文打假的 Zep，自己也纠错过。他们初版文章里的 Zep 分数算错了，后来更正为 75.14% ± 0.17，并公开披露了更正。这不是笑话，这是唯一可信度信号——认真打假的团队也会翻车，区别在于有没有纠错披露。

第二幕：七种“合法的”数字制造术

把各家的方法论拆开，我归纳出七种手法。每一种都不撒谎，合起来就是 30 个点。

1. 换答卷人

记忆系统负责“递资料”，最后答题的是底层 LLM。Zep 自己的测试显示：同样的满上下文设定，GPT-4o 答题 60.6%，o4-mini 答题 72.78%。记忆系统一行没改，12 个点是答卷人的。类比：补习班宣传“学员平均分提升 15”，其实是换了批学生。

2. 换判卷老师（和判卷提示词）

基准最终靠 LLM-as-Judge 判卷。Mnemoverse 团队披露过一个惊人案例：同一配置跑两次，0.62 和 0.79，差异的签名是“判卷准度更高但 token-F1 更低”——典型的高抬贵手。他们承认：没有冻结的判卷提示词 hash，无法判定哪个数是对的，“所以两个都给你看”。JudgeSense 基准（arXiv 2604.23478）系统测过这件事：rubric 顺序、分数编号这类微小扰动就能让判卷分数漂移。

3. 检索分冒充答题分

Recall@k（检索命中率）和端到端 QA 准确率是两个量纲，但经常在同一张表里混排。Supermemory 的 95% 是 GPT-4o 答的；换成 GPT-5 答是 84.6%，Gemini 换上去是 85.2%。更强的答案模型反而分数更低——这说明 95% 测的是“管道 × 特定答案机”的耦合，不是一个系统属性。

4. 把整个图书馆搬进考场

MemPalace 在 LoCoMo 上用 top_k=50——而这个基准每个对话最多只有 19-32 条会话记录。检索被彻底绕过，等于把全馆的书堆在桌上开卷考试。考的是阅读理解，不是记忆检索。报告分数：100%。

5. 对错题定向补课，再考同一套题

还是 MemPalace：跑完基准，挑出答错的三道题，针对性修复，在同一套题上重考，报告 100%。后来在没见过的题上测是 98.4%。这就是训练集上测试，只是没人这么叫它。

6. 同名基准，不同试卷

这条我在自己项目里踩过实体坑。本地有两套 LongMemEval 数据：oracle 版（每题 1.9 个会话、22 条消息）和 s_cleaned 版（每题 47.7 个会话、494 条消息），共享同一批 500 个题 ID。同一套代码，两个版本分数差 25 分。如果你的对比两端用的是不同版本——而你根本不会知道，因为它们都叫"LongMemEval"——你就收获一次漂亮的全是幻觉的提升。我们在报告里做了数据 sha256 指纹之后，拦下过一次 +25 的幻影涨幅。

7. 子集静默缩水

Mnemoverse 复核发现：常被引用的 variant-s 版本只包含 7 类题型中的 6 类，弃答题（abstention）压根没考，而几乎没有厂商披露这一点。考卷少了一道大题，无人声明。

第三幕：基准没有死，死的是单一数字

骂完之后要说公道话。LongMemEval 论文本身相当诚实：它自己报告满上下文 GPT-4o 只有 64%，商业助手在线设定只有 33-58%，判卷与专家一致率 0.98 也附了明细。判卷可靠性这条线上，2025-2026 年的文献也在快速补课：双序对打测 position bias、agreeableness bias 的 TPR≫TNR 修正、《How to Correctly Report LLM-as-Judge Evaluations》给出了什么时候 LLM 判卷优于人类的方差分析。

更重要的信号：真正有压力的基准会让数字回归诚实。BEAM 基准把语料推到 1M 和 10M token——塞不进任何上下文窗口、检索无法绕过——最强系统在 10M 档也只有 48.6%。压力上不封顶的地方，SOTA 声明集体消失了。

一个基准的可信度，不取决于它最难的时候多难，而取决于“全塞进去”基线是否被强制报告、难度是否上不封顶、数据指纹是否可验证。

立刻可以做的：三问审计 + 五件套指纹

下次你在评估任何 Agent 记忆系统（包括开源的和商业的），对它的每一个数字问三个问题：

  1. 答卷人是谁？底层 LLM 的具体版本号。
  2. 判卷是谁？判卷模型 + 判卷提示词的哪一版。答不上来，这个数字不构成证据。
  3. 试卷是哪个文件？数据集文件名的 sha256 前几位。同名基准可能有 25 分的版本差。

三问答不上来的，按营销物料处理。而在自己的评测管线里，落地五件套指纹——这也是我们从那次 +25 幻影拦截里固化的纪律：

  1. 数据三件套：sha256 + 数据文件名 + hash seed，写进每一份评测报告的头部
  2. 判卷两件套：判卷模型版本号 + 判卷提示词 hash，与数据指纹并列冻结
  3. 满上下文基线强制在列：你的系统赢不了“全塞进去”，就别谈智能，去谈 token 账单也行
  4. 好得可疑先查伪影：击败 oracle 上界、跨模型分数反常、单臂独立 sanity 数字对不上——任何一个出现，先假设数字错了再谈庆祝
  5. 逐题归因：5 题以内的差异一律视为噪声；要下结论，逐 qid 对账

上一篇我们聊过“绿灯说谎时比红灯更危险”——验证器会背叛你。这一篇是它的续集：基准分数会说谎，而且说谎时比你诚实，因为每个口径细节都是真实披露的，弹性全藏在没人问的那三个问题里。罗生门里每个人都说真话，加起来就是一场骗局。

没有口径的分数是营销，带指纹的分数才是证据。
