416 变 6：一段正则如何偷走一枚数字，还让你测试全绿

正则表达式 信息抽取 回溯 测试工程 2026-09-13 · 基于 amg C568 page-count sum lane 事故复盘

原文写着 "a 416-page novel"，正则捕获组交回来的是 '6'。不报错、不抛异常、类型正确、语义上完全说得通——6 本来就可以是一本书的页数。这篇文章完整解剖这次偷窃：引擎的任务是找到一个匹配，从来不是找到你的匹配。

一、值合法的错误，是最深的错误

bug 有个残酷的等级制。崩溃是好 bug——大声喊疼，堆栈指路。异常次之——至少留了痕迹。静默失败再次之——好在它产出空值，空值容易在下游撞出 TypeError。最深的一档是：错误产出了一个类型正确、语法合法、语义上完全说得通的值。

这周在 amg（agent-memory-graph）评测管线里抓到一例，属于这一档的教科书形态：一段正则要从对话记录里抽取小说页数，原文是 "a 416-page novel"，捕获组交回来 '6'。格式正确、int('6') 完全合法。如果这道题的答案恰好对容差不敏感，这个 bug 会永远活着。

它不巧很敏感。下面从头讲。

二、现场：一条"把自由文本算成账"的抽取任务

amg 的 live-500 基准里有这样一道题："What was the page count of the two novels I finished in January and March?"——从约五十万 token 的对话记录里，找出用户"刚读完"的两本小说的页数并求和。标准答案 856 = 440 + 416。

haystack 里的证据长这样：

s9:  "just finished … The Nightingale … 440 pages"   （×2，需 distinct 去重）
s33: "just finished a 416-page novel"
诱饵: The Power, 341 pages —— 十二月读的，句中没有 just-finished 标记

顺带一提这道题本身的设计就很有性格：全语料没有一处提及 January，March 的命中全是诱饵（Chicago 行程、Marchmont、阿拉莫 1836），会话日期全在五月。所以抽取器被刻意设计成 month-blind——只承诺"刚读完的页数求和"，不承诺语料撑不起的月份语义。抽取器的承诺范围，以语料能支撑的下界为准，这是另一条纪律，今天不展开。

展开的是：第一版实现里，负责"锚定 just-finished 标记、捕获其后页数"的，是一段 mega-alternation 锚点正则。简化掉所有分支，病灶只剩一行：

import re

line = "just finished a 416-page novel"

pat = r"finished .{0,40}?[\w'\"]+(\d+)[- ]?page"
m = re.search(pat, line)

print(m.group(1))   # 期望 '416'

跑一下：输出 '6'。

三、解剖：引擎找到的是"一个匹配"，不是"你的匹配"

要理解这枚数字是怎么被偷走的，得先纠正一个广为流传的误解：正则不是"模式匹配器"，正则引擎是一个分划搜索器。给定模式和文本，它的任务是在文本的所有可能切分方式里，找到任意一种能让整个模式成立的切分。它搜索的对象不是"页数"，是"切分"。

逐步回放引擎的搜索过程。模式有三个关键部件：

  • .{0,40}? —— 懒惰通配符：先占 0 个字符，不够再一格格扩
  • [\w'\"]+ —— 贪婪前缀类：尽可能多吃，而 \w 包含数字
  • (\d+) —— 捕获组：至少要 1 个数字

引擎从锚点 finished 之后开始，懒惰通配符先占 0 个字符，前缀类从字母 a 起吃——吃到空格停，捕获组在空格处要数字，失败。通配符扩 1 格、2 格，前缀类起点滑到 4：

  1. 前缀类贪婪吞下 416（\w 吃数字，理直气壮）
  2. 捕获组 (\d+) 面对下一个字符 -：要至少一个数字，失败
  3. 引擎回溯：让前缀类吐出恰好一个字符——前缀变 41
  4. 捕获组接过吐出来的 6：满足最低要求，贪婪吃下
  5. [- ]?page 对上 -page——整个模式成立

引擎宣布成功，捕获组里的值是 '6'。注意第 3 步的阴险之处：回溯的步长是"满足下一个部件的最低要求"。捕获组要 1 个数字，前缀就只吐 1 个。你要 416，引擎只欠 1。只要存在一种切分能让模式成立，引擎就交付那种切分——它对"哪一种切分是写模式的人心里想的那种"没有任何义务。

更妙的是对称性：把前缀类改成懒惰的 [\w'\"]+?，偷法就变了——前缀只占 4，捕获组拿到 '16'。贪婪版偷尾数，懒惰版偷中间，两种写法都错，且错得不一样。只要那个含 \w 的字符类和数字捕获组贴在一起，数字的切分权就不在你手里。

四、为什么它比 ReDoS 更值得害怕

正则回溯的"著名亲戚"是灾难性回溯（catastrophic backtracking / ReDoS）——指数级回溯把 CPU 拖死。但 ReDoS 其实是良性亲戚，因为它偷的是性能：请求超时、服务挂掉、告警响起来，全世界都知道出事了。有 lint 工具、有安全公告、有一整个 CVE 类目盯着它。

这个亲戚偷的是语义，且三个免疫一样不缺：

  • 不超时——回溯深度只有个位数，性能毫秒级
  • 值合法——6 是个完全合理的页数，类型检查、范围检查、形状检查全过
  • 测试绿灯——单元测试断言"返回一个 int"就过；只有把断言钉到具体真值上，灯才会红

一句话总结两者的差别：ReDoS 是拒绝服务，这个是伪证。前者让你的系统停下来，后者让你的系统继续跑——带着一个错误的数字。

五、LLM 时代，这类正则的密度翻了几个数量级

搁十年前，"从自由文本里抽数字"是日志解析和爬虫的 niche。现在，几乎每一条 agent 管线的中枢都是这类代码：从模型输出里抽 JSON 字段值、从对话记录里抽事实、从 RAG chunk 里抽元数据、从工具返回里抽 ID 和金额。

而 LLM 的输出有一个统计上的残酷特征：数字密度极高，且语法上"说得通"的错误切分无穷多。人写的语料里页数稀疏、金额规整；模型生成的文本里 416-page、v2.3.1、$1,204.50、Room 302 比肩接踵。每一个"字符类含 \w + 紧邻数字捕获组"的写法，都是把切分权拱手让给回溯搜索——而回溯搜索交付的第一种合法切分，统计上几乎不可能是你想要的那种。

这不是假设。amg 的这条 lane 单题分值就是被它咬掉 410 分的（856 的答案被算成 446），而全套件一万多个测试全绿——直到一个把断言钉到真值的 pin 站出来。

六、修复：朴素的位置扫描，胜过聪明的巨型 alternation

修复没有用更聪明的正则。用了更笨的代码：

import re

_NUM = re.compile(r"\d+")

def pages_after_marker(line, marker="finished"):
    """锚定标记位置，取其后首个数字短语。"""
    i = line.lower().find(marker)
    if i < 0:
        return None
    m = _NUM.search(line, i + len(marker))
    return int(m.group()) if m else None

print(pages_after_marker("just finished a 416-page novel"))   # 416
print(pages_after_marker("just finished it -- 980 pages"))    # 980

两步：str.find 锚定标记，re.search(text, pos) 取其后第一个数字短语。没有 alternation，没有跨部件协商，每一步都能用一句话复述——"标记之后的第一个数"就是题面语义本身。原来的 mega-alternation 为什么错？因为它把"锚定"和"抽取"焊在同一次回溯搜索里，锚定的贪婪和抽取的贪婪在搜索空间里互相讨价还价，没人能复述那笔交易。

外围再加一道题面基数 guard：题目说 "two novels"，_CNT_WORD2NUM 把基数钉死为 2，distinct 抽取结果不等于 2 就整体 fall-through 弃权——宁可交白卷，不交错卷。

这个形状在抽取器家族里反复出现：alternation 只做锚定，不做抽取；抽取交给位置扫描。凡是"锚点 + 贪婪通配 + 捕获组"三件套焊在一起的写法，都值得警惕。

七、防御清单

这次事故之后，四条纪律固化进管线：

  1. 真值钉死（value pin）。单事实抽取的测试，断言必须钉到真实语料的具体值：这道题的 416 必须恰为 416，不是 isinstance(x, int)，不是 0 < x < 5000。形状断言防崩溃，值断言防伪证。陷阱本身已固化为永久回归 pin——谁再写出含 \w 前缀贴数字捕获组的模式，测试当场变红。
  2. 正则评审的一句话判据：含 \w 的字符类紧邻数字捕获组，等于把数字的切分权交给回溯。看到这个形状，先问：这个类会不会吃到本该属于捕获组的数字？
  3. 优先位置扫描。锚定和抽取分离：find 锚、search(pos) 抽。每步一句话能复述的代码，才配进入抽取管线。
  4. 敌意语料常态化。测试语料必须包含数字黏连形态：416-page、980 pages、page 217、v2.3.1。乖语料（数字两边永远有空格）测不出回溯偷窃。

尾声

那条 lane 最终 keep：banked 303→304，0.606→0.608，全套件 10476 测试 0F/0E，full-500 回放确认预测变化恰好且只有这一题——'6' 再没出现过。

复盘时最触动我的是那个不对称：引擎找到的是 a match，工程要的是 the match，两者的差距恰好等于回溯搜索空间的大小。把搜索空间压到一句话能复述，差距就消失了。正则很强，但它的强项是搜索，不是理解——当你需要的是"那个"数字而不是"某个"数字时，别让一个搜索器替你做切分决定。

你的管线里那段"从模型输出里抽数字"的正则，今晚就可以拉出来跑一遍 416-page。
