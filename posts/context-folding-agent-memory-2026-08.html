为什么你的 AI 助手做了三步就忘了第一步？Context Folding 正在解决 Agent 的记忆危机

2026-08-11 · Context Folding Long-Horizon Agents RL Agent Memory

想象你请了一个研究助手，帮你调研一个复杂课题。他先搜了十篇论文，读了三个小时，做了二十页笔记。然后你问他："刚才第三篇论文的核心方法是什么？"——他一脸茫然。不是因为没看到，而是因为他脑子里的"工作记忆"已经装不下了，新的信息不断涌入，旧的细节被挤到了看不见的角落。

这正是今天 LLM Agent 面临的真实困境。2026 年，Agent 已经能自主搜索网页、写代码、操作软件——但一旦任务变长（几十步甚至上百步的交互），它们就会像那个健忘的研究助手一样，在第三十步忘了第三步的关键发现。

解决方案不是更大的上下文窗口，而是一种全新的能力：Context Folding——让 Agent 学会"做完子任务后，把过程折叠成结论"。这项技术在 2025 年底至 2026 年初迎来了爆发，三篇重量级论文分别被 ICML 2026、ICLR 2026 和 NeurIPS 2025 接收。本文拆解它解决什么问题、怎么工作、以及为什么它可能是 2026 年 Agent 领域最重要的范式转变。

一、上下文饱和：比你想的更严重

先理解问题的严重性。当前主流的 Agent 架构（ReAct 模式）是这样工作的：每一步交互——不管是搜索结果、工具输出还是 Agent 自己的推理——都被原封不动地追加到上下文窗口里。100 步交互后，上下文可能膨胀到 50K-100K token。

你可能会说：现在的模型不是支持 128K 甚至 1M token 吗？问题不大吧？

问题很大。原因有三：

第一，注意力不是均匀的。研究反复表明，LLM 在长上下文中存在"lost in the middle"效应——开头和结尾的信息记得清楚，中间的容易被忽略。100 步交互中，第 30-70 步的关键决策恰好落在注意力的盲区。

第二，成本随上下文线性增长。Transformer 的注意力计算是 O(n²) 复杂度。128K context 的推理成本是 8K context 的 256 倍。更关键的是，KV cache（存储已计算注意力值的缓存）在 128K 时会占掉 GPU 70-90% 的显存。这意味着长上下文不仅仅是质量问题，更是经济问题。

第三，噪声淹没信号。每一步工具调用都产生大量格式化输出（JSON、HTML、日志）。Agent 真正需要的信息——"这个网页的答案是 X"——被淹没在几百行 HTML 标签里。上下文越长，信噪比越低。

2025 年的一篇综述论文将这个现象命名为 context saturation（上下文饱和）。它不是 bug，而是 ReAct 范式的结构性缺陷。

二、人类怎么解决？答案在认知科学里

在谈论技术方案之前，先看看人类是怎么处理类似问题的。

你正在做一道复杂的数学题。中间需要查一个公式、做一个辅助计算、验证一个假设。做完这些辅助步骤后，你的大脑会怎么做？——你会忘掉查公式的具体过程，只记住"公式是 F=ma"。你不会把翻书的每一页都记在脑子里，然后一边解题一边回顾翻书的过程。

这就是认知科学中的工作记忆（working memory）模型。人类的工作记忆容量极小（经典的 7±2 模型），但我们能处理极其复杂的任务，靠的是主动管理工作记忆：

  • 分段处理：把大任务拆成小步骤，每步完成后只保留结论
  • 回顾性整合：定期回顾和压缩已完成的工作，提炼出更高层的理解
  • 遗忘策略：主动丢弃不再相关的细节

Context Folding 的核心洞察就是：Agent 也需要这种能力——不是被动记录一切，而是主动雕塑自己的"认知工作区"。

三、Context Folding：让 Agent 学会折叠

基本机制：Branch 和 Fold

Context Folding 最重要的思想来自 ByteDance/CMU 的论文（ICML 2026）。它给 Agent 增加了两个核心操作：

Branch（分支）：当 Agent 遇到一个子任务（比如"查一下这个函数的文档"），它可以创建一个临时的子轨迹来处理。这个子轨迹有自己独立的工作上下文，不占用主上下文的空间。

Fold/Return（折叠/返回）：子任务完成后，Agent 不把中间步骤带回主上下文，而是将整个过程"折叠"成一句摘要。

打个比方：就像函数调用。你调用一个函数 search_documentation("torch.compile")，函数内部可能做了 20 步操作，但返回给你的只有一行结果。你不需要知道函数内部怎么实现的，你只需要那个返回值。

主上下文：
  [系统提示] → [用户问题] → [Agent: 需要查文档]
    → Branch: [搜索 torch.compile → 阅读 5 个页面 → 总结用法]
    → Fold: 返回 "torch.compile 支持 mode='reduce-overhead'..."
  → [Agent: 继续推理...]

// 子轨迹的 20 步被折叠为 1 步摘要
// 主上下文始终保持精简

结果是什么？Agent 用 32K 的活跃上下文（10 个折叠槽位），在 BrowseComp-Plus 上达到 62.0% 的准确率——而 GPT-5 用完整的 327K 上下文是 79.3%。一个 36B 的开源模型，用 1/10 的上下文，达到了 GPT-5（推测参数量远超 100B）约 78% 的水平。

多尺度折叠：AgentFold 的精细设计

阿里巴巴 Qwen 团队的 AgentFold（ICLR 2026）进一步提出了多尺度折叠——不是所有折叠都一样粗粒度。它设计了两种操作：

  • 细粒度凝聚（Granular Condensation）：只折叠最近一步。适合上下文还没太满、但需要控制增长速度的情况。就像你做完一步后顺手在笔记上浓缩一下。
  • 深度合并（Deep Consolidation）：把多个步骤甚至整个子任务合并成一段摘要。适合上下文已经接近饱和、需要大幅压缩的情况。就像你完成一个章节后，回头写一段总结。

Agent 在每一步都可以自主选择折叠粒度。这种"元认知"决策本身也是通过训练学到的——Agent 学会了感知"我的上下文快满了"和"这个子任务已经可以收尾了"这样的信号。

AgentFold 的结果令人印象深刻：一个 30B 参数的模型，在 256+ 轮交互的长程任务上，匹敌 OpenAI o4-mini 的表现，而活跃上下文始终保持在 ~20K token 以下。

四、让折叠成为可学习的能力：RL 训练的突破

早期的 Agent 系统用手动规则做摘要——"每 10 步总结一次"、"只保留最近 5 步"。这些规则是脆弱的：不同任务需要不同的压缩策略。

2025-2026 年的关键突破是：用强化学习（RL）训练 Agent 学会何时折叠、如何折叠。

FoldGRPO：过程奖励的群体相对策略优化

ByteDance 的 FoldGRPO 在标准 GRPO 基础上增加了分离的 process reward：

  • 任务完成奖励：子任务是否正确完成
  • 折叠质量奖励：摘要是否准确、是否保留了关键信息
  • 上下文效率奖励：是否有效控制了上下文增长

这三个奖励信号让 Agent 同时学会了"做对事"和"高效地做对事"。

FoldAct：解决三大训练难题

但 RL 训练折叠策略远比想象的难。2025 年底的 FoldAct 论文揭示了三个根本性挑战：

挑战一：梯度稀释。在一个典型的 agent 轨迹中，action token（工具调用、推理步骤）占了 95% 以上，而折叠/摘要 token 只占 5% 不到。标准的 PPO loss 会把训练信号均匀分配给所有 token，导致折叠决策几乎得不到学习信号。FoldAct 的解法是分离 loss——为 action token 和 summary token 分别计算 PPO 目标，各自有独立的 advantage 和 importance ratio。

挑战二：自我条件化。一旦 Agent 在第 N 步写了一个摘要，第 N+1 步的状态就依赖于这个摘要。这意味着观测分布本身是策略依赖的，违反了 PPO 的重要性采样假设。FoldAct 加入了一个全上下文一致性损失——用未压缩的完整历史作为参考，约束压缩后的策略不偏离太多。

挑战三：计算成本。每次折叠都产生唯一的、被压缩的上下文，Transformer 无法复用之前的 KV cache。FoldAct 的解法是选择性段训练——每个 rollout 只随机采样部分轮次计算梯度，大幅减少计算量。训练速度从 933s/step 降到 ~180s/step。

五、另一个角度：常数级内存的 Agent

MIT 和 NUS 的 MEM1（NeurIPS 2025 Workshop 最佳论文）从另一个角度切入同样的问题。与其折叠上下文，不如让 Agent 维护一个紧凑的内部状态，每一步只更新这个状态。

MEM1 的做法更像人类的长期记忆+工作记忆模型：

  • Agent 有一个紧凑的内部状态（而不是完整的交互历史）
  • 每一步，Agent 用 RL 学到的策略更新这个状态：整合新观察、丢弃过时信息
  • 状态同时服务于记忆巩固和推理——不是先记忆再推理，而是两者协同

结果是：一个 7B 参数的 MEM1 Agent，在 16 个子问题的复杂 QA 任务上，超越了一个 14B 参数的模型，而 peak memory 只用了后者的 27.1%。这不是渐进改进——这是数量级的效率提升。

MEM1 的核心贡献在于它证明了一个反直觉的结论：上下文管理是比模型规模更重要的 scaling 维度。给一个 7B 模型好的记忆管理策略，胜过给一个 14B 模型更大的窗口。

六、不需要训练 Agent 也能做：ACON 的优雅方案

如果你不想用 RL 训练 Agent（毕竟需要大量 GPU 和数据），微软的 ACON（ICML 2026）提供了一个完全不同的思路：不动 Agent，优化压缩策略本身。

ACON 的做法非常巧妙：

  1. 用完整的上下文运行 Agent，记录成功轨迹
  2. 用压缩后的上下文运行同样的任务，找到失败的案例
  3. 对比成功和失败，找出压缩时丢失了什么关键信息
  4. 用 LLM 自动更新自然语言压缩指南（"压缩时必须保留 URLs 和数值结果"）
  5. 迭代上述过程

这本质上是在 prompt 空间做优化，而不是在参数空间。好处是：完全模型无关，适用于 GPT-4、Claude、DeepSeek 等任何 API 模型。ACON 在 AppWorld 和 OfficeBench 上将峰值 token 减少 26-54%，同时保持 95%+ 的准确率。更惊人的是，蒸馏后的小压缩模型甚至能让小 Agent 的性能提升 46%——因为压缩去掉了噪声，Agent 反而看得更清楚。

七、技术全景图

将 2025-2026 年的主要工作放在一张图上：

               Context Folding 技术分类
                     │
    ┌────────────────┼────────────────┐
    │                │                │
  内部化            外部化           预算感知
 (Agent 自学)    (独立管理器)      (按预算分配)
    │                │                │
 ├ FoldGRPO      ├ ACON           ├ ContextBudget
 ├ AgentFold     ├ AdaCoM         ├ SAM
 ├ MEM1          ├ ContextCurator
 ├ FoldAct       ├ ReSum
 └ U-Fold

内部化路线把折叠能力训练进 Agent 自身——通用性最强，但训练成本高。 外部化路线保持 Agent 不变，训练独立的压缩器——更实用，但可能不够灵活。 预算感知路线根据 token 预算动态调整压缩策略——适合生产环境。

这三条路线不是互斥的。未来的 Agent 系统很可能会同时采用：内部 RL 训练 + 外部压缩器 + 预算感知策略。

八、这对实践者意味着什么

说了这么多研究，如果你正在构建 Agent 系统，今天能做什么？

第一，检查你的 Agent 是否有上下文饱和问题。一个简单的方法：在一个长会话（50+ 轮）中，在第 5 轮放一个关键信息，然后在第 45 轮问 Agent 那个信息。如果它答不上来，你就有了上下文饱和问题。

第二，实现最简版的"folding"。在 tool call 完成后，不要保留原始输出。取而代之，用 Agent 自己（或一个简单的摘要 prompt）将工具输出压缩为一两句结构化摘要，替换掉原始内容。这一步就能大幅减少上下文增长。

第三，引入子任务分支机制。让 Agent 可以"fork"出一个临时子任务——有独立的消息历史——完成后只返回一个结构化结果。这比在主上下文里混入所有中间步骤要高效得多。

第四，考虑预算感知。为 Agent 设定一个 token 预算。当上下文接近预算时，自动触发更激进的压缩策略。这不需要复杂的 RL 训练——一个简单的 if-else 加上不同粒度的摘要 prompt 就能生效。

第五，关注 KV cache 优化。在推理层面，DeepSeek 的 MLA（Multi-head Latent Attention）可以将 KV cache 压缩 7-14 倍。FP8 KV cache 在精度损失 <1% 的情况下减半内存。这些底层优化和上层的 folding 策略是乘法关系——两者叠加可以实现 40-100 倍的效率提升。

九、更大的图景：从"更多上下文"到"更好的上下文"

2024 年，Agent 领域的主旋律是"扩大上下文窗口"——从 32K 到 128K 到 1M。2025 年，KV cache 技术让 1M token 成为可能。但 2026 年的共识正在转变：更大的窗口不是答案，更聪明的管理才是。

Context Folding 代表了一个深层的范式转变：从"给 Agent 看更多"到"让 Agent 知道该看什么"。这与认知科学的发现一致——人类之所以聪明，不是因为大脑容量大（相比鲸鱼，人脑很小），而是因为我们有极其高效的注意力管理和遗忘机制。

更深层地说，Context Folding 揭示了一个关于智能的真理：忘记什么和记住什么同样重要。甚至更重要。一个什么都记住的系统（全量上下文）会被噪声淹没；一个什么都遗忘的系统（只看最近几步）会失去关键背景。真正的智能在于知道什么该保留、什么该丢弃、什么时候该回头整合。

这不仅仅是一个技术问题——这是关于智能本质的洞察。而 2026 年的 Agent 研究正在把这个洞察变成可以训练、可以测量、可以工程化的能力。
