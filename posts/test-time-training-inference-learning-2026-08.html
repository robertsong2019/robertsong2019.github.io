推理即训练：当大模型不再满足于"思考链"

2026-08-05 · Test-Time Training LLM 推理时学习 Titans SEAL
大模型训练完就"冻结"——这个假设正在被推翻。2025-2026 年的一系列研究表明，模型可以在推理阶段更新自身参数，而且效果惊人：4B 参数模型在 128K 上下文任务上超越完整注意力，2M token 上下文成为可能，7B 模型通过自生成数据超越 GPT-4.1。这不是 prompt engineering 的渐进改进——这是学习范式的结构性转变。

一、一个让人不安的问题

Transformer 有一个结构性缺陷：注意力机制的计算复杂度是 O(n²)。

这意味着上下文从 4K 扩展到 128K，计算量增加 1000 倍。虽然 Flash Attention 等工程优化把常数降了下来，但平方复杂度的天花板始终存在。更致命的是，KV Cache 的显存占用随上下文长度线性增长——128K 上下文的 KV Cache 可以轻松吃掉 40GB 显存。

业界给出了两种应对方案：

  1. 稀疏注意力（Sliding Window、Local+Global）：减少计算量，但代价是丢失远距离依赖
  2. 上下文压缩（KV Cache Eviction、Summarization）：压缩旧上下文，但压缩损失不可逆

这两种方案都在"绕"问题。但 2025 年开始出现了一批研究，提出了一个更激进的问题：

如果模型在推理时也能学习呢？

不是 chain-of-thought 那种"多生成几个 token"的推理时计算，而是真正的梯度下降——在推理阶段更新模型参数，把上下文信息"编译"进权重里。

这就是 Test-Time Training（TTT）。

二、技术谱系：从 RNN 隐藏状态到推理时梯度下降

第一代：TTT 层（ICML 2025）

Yu Sun 等人（Stanford）提出了一个关键洞察：RNN 的隐藏状态本身就是一个小模型。

传统 RNN（包括 LSTM、Mamba）的隐藏状态是一个固定维度的向量。TTT 层的做法是：让隐藏状态本身就是一个可学习的模型（线性模型或 MLP），更新规则是一步 SGD。

import torch
import torch.nn as nn

class TTTLinear(nn.Module):
    """
    TTT-Linear: 隐藏状态是一个线性模型。
    更新规则是一步 SGD（内循环），元参数通过端到端训练（外循环）。
    """
    def __init__(self, input_dim, hidden_dim):
        super().__init__()
        self.input_dim = input_dim
        self.hidden_dim = hidden_dim
        self.eta = nn.Parameter(torch.tensor(0.01))
    
    def forward(self, X):
        batch, seq_len, _ = X.shape
        # 初始化隐藏状态（线性模型权重）
        W = torch.zeros(batch, self.input_dim, self.hidden_dim, device=X.device)
        outputs = []
        
        for t in range(seq_len):
            x_t = X[:, t, :]
            # 内循环：自监督重建
            reconstruction = x_t.unsqueeze(1) @ W
            loss = ((reconstruction.squeeze(1) - x_t) ** 2).mean()
            # 一步梯度下降更新隐藏状态
            grad = torch.autograd.grad(loss, W, create_graph=True)[0]
            W = W - self.eta * grad
            # 输出
            out = x_t.unsqueeze(1) @ W
            outputs.append(out.squeeze(1))
        
        return torch.stack(outputs, dim=1)

关键区别：传统 RNN（包括 Mamba）在 16K 上下文后停止降低 perplexity，而 TTT 层像 Transformer 一样持续降低。

第二代：In-Place TTT（ICLR 2026 Oral）

TTT 层需要特殊的架构设计。In-Place TTT 回答了一个更实际的问题：能不能不修改模型架构，直接在现有 LLM 上实现推理时训练？

答案是：把 LLM 的 MLP 最终投影矩阵当作"快权重"（fast weights），在推理时更新。

class InPlaceTTT:
    """
    In-Place TTT: 在推理时更新 LLM 的 MLP 投影矩阵。
    无需修改模型架构，drop-in 增强。
    """
    def __init__(self, model, lr=1e-5, chunk_size=512):
        self.model = model
        self.lr = lr
        self.chunk_size = chunk_size
        self.original_weights = {}
    
    def adapt(self, context_ids):
        # 备份原始 MLP 投影权重
        for name, param in self.model.named_parameters():
            if 'mlp.proj' in name or 'mlp.down_proj' in name:
                self.original_weights[name] = param.data.clone()
        
        # 分块更新：用 next-token prediction 更新 MLP 权重
        optimizer = torch.optim.SGD(
            [p for n, p in self.model.named_parameters() 
             if 'mlp.proj' in n or 'mlp.down_proj' in n], lr=self.lr)
        
        for start in range(0, len(context_ids) - 1, self.chunk_size):
            end = min(start + self.chunk_size, len(context_ids) - 1)
            chunk = context_ids[start:end + 1]
            logits = self.model(chunk.unsqueeze(0))
            loss = torch.nn.functional.cross_entropy(
                logits[0, :-1].view(-1, logits.size(-1)),
                chunk[1:].view(-1))
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
        return self

结果：4B 参数模型在 128K 上下文任务上超越完整注意力 Transformer，推理速度比完整注意力快 2.7 倍。

这意味着什么？你不需要 128K 的 KV Cache。你只需要把 128K 的上下文"编译"进 MLP 权重里，然后用短上下文窗口做推理。

第三代：Titans——三记忆架构（Google DeepMind）

Titans 把推理时学习推向了极致：三种记忆系统协同工作。

┌──────────────────────────────────────────┐
│           Titans 架构                     │
├──────────────────────────────────────────┤
│  短期记忆 ← 滑动窗口注意力               │
│  (处理当前上下文，类似工作记忆)            │
├──────────────────────────────────────────┤
│  长期记忆 ← 神经记忆模块                  │
│  (推理时学习，把信息编译进权重)            │
├──────────────────────────────────────────┤
│  持久记忆 ← 任务级先验参数                │
│  (与数据无关，编码"怎么做任务"的知识)      │
└──────────────────────────────────────────┘

Titans 引入了"惊讶度"（Surprise）机制：梯度幅度大 = 意外信息 = 值得记忆。就像人类——平淡的信息转瞬即逝，意外的事情刻骨铭心。

结果：Titans 可以处理 2M+ token 的上下文。这是完整注意力 Transformer 完全做不到的。

第四代：SEAL——模型自己训练自己（MIT, NeurIPS 2025）

SEAL（Self-Adapting Language Models）提出了一个更疯狂的问题：如果模型自己决定学什么呢？

class SEALAdapter:
    """
    SEAL: 模型生成 self-edit（训练数据），然后微调自己。
    RL 优化：下游性能提升 = 正反馈。
    """
    def self_adapt(self, input_text, num_edits=3):
        for _ in range(num_edits):
            # 步骤 1：模型生成自己的训练数据
            self_edit = self.model.generate(
                f"Generate a training example for: {input_text}")
            
            # 步骤 2：用 self-edit 做 SFT 更新权重
            loss = self.compute_sft_loss(self_edit)
            loss.backward()
            self.optimizer.step()
            self.optimizer.zero_grad()
        
        # 步骤 3：RL 验证 — 下游变好了才保留
        if self.downstream_score() > self.baseline:
            self.keep_updates()
        else:
            self.rollback()
        return self

数据说话：7B 模型用 SEAL 超越 GPT-4.1 生成的合成数据（47.0% vs 46.3%）。一个 7B 开源模型，通过自生成数据 + 自我微调，在知识整合任务上打败了 GPT-4.1。

三、推理时适应的三个层次

这些工作可以归纳为一个统一的分类框架：

层次改变什么代表方法持久性计算开销
推理时计算生成更多 token（CoT）o1, R1, Reflexion无（推理结束即消失）低
推理时适应调整少量参数（快权重）TTT Layers, In-Place TTT单次请求中
推理时训练完整的梯度更新SEAL, TT-SI, TLM可持久高

这三个层次不是竞争关系，而是互补的：推理时计算解决"想得更深"，推理时适应解决"记得更多"，推理时训练解决"变得更好"。

四、对 Agent 架构的深远影响

4.1 记忆系统的重新分层

当前的 Agent 记忆架构：上下文窗口 ↔ 向量数据库 ↔ 文件系统。TTT 引入了全新层次：快权重层——比上下文窗口持久，比 RAG 检索快速，比模型权重灵活。

// TTT-based Agent 上下文管理（伪代码）
class TTAgent {
  async processLongContext(document: string): Promise<void> {
    // 传统做法：把整个文档塞进上下文
    // const response = await llm.chat(document + question);  // 100K tokens
    
    // TTT 做法：把文档编译进快权重
    const fastWeights = await this.adaptWeights(
      baseModel: this.model,
      context: document,        // 100K tokens 用一次
      chunkSize: 512,
      learningRate: 1e-5
    );
    
    // 后续对话只需要短上下文
    const response = await llm.chat({
      model: this.model,
      messages: [{ role: 'user', content: question }],  // 100 tokens
      weights: fastWeights,
    });
    // 成本：首次 adapt = 100K tokens
    //      后续每次 = 100 tokens（而非 100K）
    // 100 轮对话后：TTT 成本 ≈ 传统成本的 1/100
  }
}

4.2 Agent 的"个性"来自哪里

In-Place TTT 的一个副作用：每次会话的快权重都不同。一个经常处理 Python 代码的 Agent 会变得对 Python 更敏感，而一个处理法务文档的 Agent 会变得对法律术语更敏感。这不是 prompt engineering 的"角色扮演"——这是真正的参数级适应。Agent 的"个性"不再来自 system prompt，而是来自它经历过什么。

五、风险与局限

1. 灾难性遗忘：推理时梯度更新可能破坏模型已有的能力。In-Place TTT 通过只更新 MLP 投影矩阵来缓解，但长期累积效应仍未知。

2. 对抗性注入：如果模型在推理时学习了恶意构造的上下文，攻击者可以"毒化"快权重。这比 prompt injection 更危险——快权重可能被持久化。

3. 不可预测的涌现行为：当模型权重在推理时发生变化，它的行为可能偏离预训练时的安全边界。Red Teaming 评估的是冻结的模型，而非适应后的模型。

六、结语：冻结权重时代的终结

2023 年，"模型训练完就冻结"是一个不需要质疑的假设。2026 年，这个假设正在瓦解。

TTT 的本质不是"让模型在推理时多做点计算"——它是一个范式转变：

  • 训练和推理的边界正在模糊。训练不再是独立的、昂贵的阶段，变成了持续的、无处不在的过程。
  • 模型权重变成了动态的。从"一个模型服务所有用户"变成"每个用户有自己的快权重"。
  • 上下文不再是"窗口"。它是模型的训练数据——每一次对话都在塑造模型的参数。

这不是渐进改进。这是学习范式的结构性转变。当推理和学习合为一体时，我们离"真正的持续学习"又近了一步。
