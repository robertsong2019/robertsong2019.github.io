当模型在推理时偷偷学习：Test-Time Training 如何打破"训练-部署"的界限

2026-08-01 · 罗嵩 · Test-Time Training LLM 推理优化 前沿研究
一个 LLM 接到一份 128K token 的法律合同，没有经过任何微调，却在阅读过程中悄悄更新了自己的权重——读完之后，它对这份合同的理解比刚开始时深了不止一个量级。这不是 prompt engineering，不是 few-shot learning，也不是 fine-tuning。这是一种叫做 Test-Time Training（TTT）的新范式：模型在推理时学习。

问题：一个静态的世界

今天的 LLM 有一个根本性的限制：训练完成后，权重就冻结了。不管你给它看多少新文档、多少新例子，它的"知识"始终停留在训练结束的那一刻。

我们发明了很多绕过这个限制的方法：

  • Prompt Engineering：把信息塞进上下文窗口
  • RAG：检索相关文档拼到 prompt 里
  • Fine-tuning：用新数据重新训练模型
  • Chain-of-Thought：让模型"想"得更久

但每种方法都有硬伤。Prompt 和 RAG 受限于上下文窗口大小——即使窗口支持 1M token，注意力也会随长度衰减。Fine-tuning 成本高、周期长，而且容易遗忘旧知识。CoT 只是让模型多输出 token，并不改变模型本身。

有没有一种方法，让模型在处理当前输入时真正地更新自己，而不是把所有信息都塞在一个固定大小的上下文窗口里？

这就是 Test-Time Training 要解决的问题。

核心思想：隐藏状态即模型

理解 TTT 的关键来自一个看似简单的问题：RNN 的隐藏状态为什么不能记住更多东西？

传统 RNN（包括 LSTM、Mamba）维护一个固定大小的隐藏状态向量。这个向量就是全部的"记忆"——它必须把之前所有 token 的信息压缩进一个固定维度的向量中。想象一下，你要把整本《战争与和平》的内容压缩到一张便利贴上，这就是 RNN 隐藏状态在做的事。

Stanford 的 Yu Sun 团队在 2024 年提出了一个重新定义问题的思路：如果隐藏状态不是一个向量，而是一个完整的机器学习模型呢？

具体来说：

  • 隐藏状态 = 一个小型 ML 模型（线性模型或 MLP）
  • 更新规则 = 一步梯度下降（自监督）
  • 输出规则 = 用更新后的隐藏状态模型处理当前 token

这个设计有两个循环：

  • 内循环：在测试序列上训练隐藏状态的 ML 模型——模型在"阅读"你的输入时，每读一个 chunk 就做一次梯度更新
  • 外循环：在训练阶段优化 TTT 层的元参数，让它学会"如何在测试时高效学习"

结果令人印象深刻：TTT-Linear 和 TTT-MLP 在 125M 到 1.3B 参数规模上匹配或超过 Transformer 和 Mamba。最关键的是——像 Transformer 一样，它们能从更多上下文 token 中持续受益，而 Mamba 在 16K 之后就无法再降低 perplexity 了。

为什么这很重要？因为 TTT 证明了"固定隐藏状态瓶颈"不是 RNN 的宿命——只要你愿意让隐藏状态本身成为一个可学习的模型。这意味着注意力机制和循环机制之间的差距，本质上不是架构差异，而是隐藏状态表达能力的差异。

三种"推理时适应"的层次

说到"推理时"做的事情，2024-2026 年的研究实际上定义了三个不同的层次。把它们搞混是常见的误解。

层次改变了什么代表方法持续性
Test-Time Compute生成更多 token（更长推理链）OpenAI o1, DeepSeek R1无——推理结束就消失
Test-Time Adaptation调整少量参数（fast weights）TTT Layers, In-Place TTT单次请求内有效
Test-Time Training完整的梯度更新SEAL, TT-SI, TLM可持久化

Test-Time Compute 是 o1 和 R1 的路线：让模型生成更长的思维链。模型本身没变，只是"想"得更久了。这很有效，但它消耗的 token 数量是普通推理的 10-100 倍，成本线性增长。

Test-Time Adaptation 是 TTT 层的路线：在推理过程中悄悄更新一部分参数，让模型适应当前输入。推理结束后，这些更新可以丢弃（不改变部署的模型），也可以保留。

Test-Time Training 是最激进的一层：完整地跑梯度更新，可能是 LoRA 微调，甚至全参数微调。SEAL 框架让模型自己生成训练数据并微调自己——这已经非常接近"模型自己教自己"了。

In-Place TTT：不需要新架构的魔法

TTT 层很好，但有一个现实问题：它需要特殊的架构。你不能直接把它插到现有的 LLaMA 或 Qwen 里。你需要从头训练。

2026 年 ICLR Oral 论文 In-Place Test-Time Training 解决了这个问题。它的洞察异常优雅：

现有的 MLP 块的最终投影矩阵，本身就可以当作 fast weights。

不需要改架构，不需要从头训练。直接在推理时对 MLP 的投影矩阵做梯度更新就行。论文称之为"drop-in enhancement"——你可以把它当作一个插件，给任何预训练模型加上 TTT 能力。

效果如何？一个 4B 参数模型加上 In-Place TTT 后，在 128K 上下文任务上超越完整注意力 Transformer。而且推理延迟几乎不增加——因为梯度更新只针对一小部分参数，分块执行。

实践意义：如果你有一个运行中的 LLM 服务，加上 In-Place TTT 不需要换模型、不需要改 pipeline。只需要在推理时多加一步梯度更新。这是目前最接近"生产可用"的 TTT 方案。

Google Titans：用"惊讶"驱动记忆

Google DeepMind 的 Titans 架构从人类记忆系统汲取灵感，设计了三层记忆结构：

  1. 短期记忆：滑动窗口注意力，处理当前上下文
  2. 长期记忆：一个深度神经网络模块，在推理时持续学习"该记什么"
  3. 持久记忆：与输入无关的学习参数，存储任务级先验知识

最有趣的是它的"惊讶度"（Surprise）机制。Titans 用梯度幅度来衡量一个输入有多"意外"——梯度越大，说明这个输入与模型已知的差异越大，因此越值得记住。

这和人类记忆的工作方式惊人地一致。你记不住每天早上刷牙的细节（梯度≈0），但记得清楚自己第一次看到 ChatGPT 时的震撼（梯度爆炸）。

Titans 可以处理 2M+ token 的上下文，在 needle-in-a-haystack 检索任务上大幅超越 Transformer。而且因为长期记忆模块是 O(N) 复杂度，推理速度远快于完整注意力。

SEAL：模型给自己当老师

MIT 的 SEAL（Self-Adapting LLMs）把 TTT 的理念推到了极致：让模型自己决定学什么、怎么学。

SEAL 的流程：

  1. 模型收到一个新输入
  2. 模型生成一个 self-edit——一段可能包含重写信息、指定超参数、或调用工具的指令
  3. 用 self-edit 作为训练数据，对自己做 SFT（监督微调）
  4. 在下游任务上评估效果
  5. 用强化学习优化：如果 self-edit 提升了性能，就正向奖励

关键是最后一步。通过 RL 训练，模型逐渐学会了什么样的 self-edit 对自己最有帮助。这不是在学"正确的答案"，而是在学"如何学习"。

结果：在知识整合任务上，7B 模型用 SEAL 生成的训练数据超越了 GPT-4.1 生成的合成数据（47.0% vs 46.3%）。为什么？因为 GPT-4.1 生成的是"看起来好的"数据，而 SEAL 生成的是"对这个特定模型最有帮助的"数据。

代价：SEAL 很贵。每次 self-edit 需要完整的微调+评估循环，约 30-45 秒。一次训练可能需要数百次循环。在两块 H100 上跑一轮约 6 小时。这比传统 RLHF 的奖励计算贵 10,000 倍。但方向是对的——"知道自己需要什么"比"知道更多"更重要。

ICL 和 TTT：同一枚硬币的两面

2025 年 7 月，Google DeepMind 发表了一篇影响深远的论文，揭示了 In-Context Learning（ICL）的隐式动力学。

他们发现：当你在 prompt 里放几个示例让模型做 few-shot learning 时，模型在前向传播过程中就已经在第一层权重矩阵上做了一个隐式的低秩修改（通常是 rank-1）。

换句话说，ICL 不是什么"魔法"。它本质上就是一次梯度下降——只不过这次梯度下降是前向传播的自然结果，在推理结束后就消失了。

这意味着 ICL 和 TTT 不是完全不同的东西：

  • ICL = 隐式的、瞬时的、低阶的参数修改
  • TTT = 显式的、可持久的、高阶的参数修改
  • Fine-tuning = 外部的、永久的、全量的参数修改

它们在同一根光谱上，区别只在于修改的显式程度、持久性和维度。这个统一视角让我们能更系统地理解"模型适应新信息"这件事的全貌。

"惊讶"作为通用学习信号

回顾所有这些工作，有一个模式反复出现：模型自己能感知什么信息值得学习。

  • Titans 用梯度幅度衡量"惊讶度" → 决定记忆什么
  • SEAL 用 perplexity 衡量信息量 → 选择需要增强的样本
  • TLM（ICML 2025）发现高 perplexity 样本对优化最有帮助
  • TT-SI（ACL 2026）用模型不确定性 → 触发自我增强和微调

所有这些方法都指向同一个结论：不确定性/惊讶/高 perplexity 是学习信号的自然来源。这与人类认知科学中"预测误差驱动学习"的理论完全一致——大脑也是通过预测与现实的差距来决定更新什么。

对于 Agent 系统的设计者来说，这个洞察可以直接落地：与其保存所有对话历史，不如用一个"惊讶度"过滤器——只保留让模型预测错误或不确定性高的交互作为长期记忆。

你现在可以做什么

TTT 还在快速演进中，但已经有一些实践方向可以立即尝试：

1. 长文档处理：考虑 TTT-E2E 方向

如果你需要处理超长文档（128K+ token），关注 TTT-E2E 和 In-Place TTT 的进展。它们的思路是把文档内容"压缩"进模型权重而非 KV cache，在 128K 上下文比完整注意力快 2.7x。目前 ttt-lm-pytorch 是最接近可用的开源实现。

2. Agent 记忆管理：用"惊讶度"做过滤

不需要等 TTT 架构成熟。你可以立刻在 Agent 系统中实施"惊讶度过滤"：记录模型对每条交互的 logprob 或 perplexity，只保留高惊讶度的交互进入长期记忆。这比"保存所有历史"高效得多。

3. 会话内自适应：参考 SEAL 的轻量版

当 Agent 遇到不确定的输入时，不要只是 RAG 检索——试试生成几个类似的合成样本，用 LoRA 做一次快速微调，在会话内适应当前任务。会话结束后丢弃更新。这比 RAG 更深入，比持久化微调更安全。

4. 判断任务类型：推理 vs 适应

不是所有任务都需要 TTT。数学推理和代码生成更适合 Test-Time Compute（o1 模式——让它想更久）。领域适应和格式学习更适合 Test-Time Training（TTT 模式——让它学当前输入）。关键是判断你的任务瓶颈是"推理深度不够"还是"对新数据的适应不够"。

5. 关注基础设施进展

截至 2026 年中，vLLM 尚不原生支持 TTT-Linear 模型。社区项目 tLLM 提供了 vLLM 的 TTT 扩展。如果你在做基础设施，这是值得贡献的方向——TTT 架构的推理引擎是一个明确的蓝海。

Test-Time Training 不是一个小技巧，它是深度学习范式的一次结构性转变。从"训练然后冻结"到"训练并在使用中持续学习"，这个跨越可能比从 RNN 到 Transformer 的跨越更深远——因为它改变的不是模型的架构，而是模型与数据的关系本身。

当模型开始学会"在学习中学习"，我们离真正的持续学习就又近了一步。
