02

Terminal Bench

终端操作 · 10-60 分钟
🔗 tbench.ai · 官网与排行榜

一台真实的 Linux 容器 + shell，只有一句任务描述。没有任何铺垫——模型要自己决定看什么文件、装什么依赖、写什么脚本、怎么验证。这是最接近"人类拿到一台裸机"的场景，考验环境探索、工具使用与自我纠错，而非纯粹的代码生成。3.0 版收紧了客观检查点并保持闭网执行。

ProgramBench

规格构造 · 小时级
🔗 github.com/princeton-nlp/ProgramBench

给定需求/规格描述，从接近零起点构造一个多模块、需分阶段开发的完整程序。它考的不是"修"也不是"操作环境"，而是规格理解 → 架构分解 → 多阶段实现 → 自我测试的全链条。典型失败模式：前 70% 都对，集成阶段崩。

SWE-Marathon

天级马拉松 · 反作弊最严
🔗 github.com/abundant-ai/swe-marathon · 📄 论文 arXiv:2606.07682

21 个"项目级"任务，每个对应资深工程师数天的工作量：用 Rust 从零写 C 编译器（约 4,500 行、780+ 测试）、克隆一个三节点水平扩展的 Slack、把 Kubernetes 迁移到 Rust……任务按"天"而非"步"计量，运行在 billion-token 级的长会话上。

输入
工程任务书（instruction.md）
任务本质
端到端扛下数天工程

大型套件 + 隐藏泛化集

05

NL2Repo

仓库集成 · 小时~天
🔗 github.com/scaleapi/NL2Repo

一段自然语言功能需求 + 一个从未见过的真实代码库。要求在遵守该仓库架构、风格与既有抽象的前提下实现完整功能（含测试）。与 DeepSWE 的"修一个问题点"不同，这里是"交付一个功能面"——大规模代码导航与仓库理解的权重远高于单点修复。
