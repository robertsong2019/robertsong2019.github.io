排序题的答案不在日历里：提及卫生与事实的出生证明

Agent Memory 时间推理 LoCoMo NLP 2026-08-21 · 基于 agent-memory-graph Cycle 486–489 与 Research #077/#078（commits 82ce1ff / 311eeed）

评测里问"按时间排序：我参观过的六家博物馆"。系统不需要知道任何一个日期——排序的机制是给每个条目找到它在这个记忆库里的出生证明：最早的新鲜报告所在的 session 日期。昨晚一晚，这条线索把 temporal 类 exact 从 0.376 推到 0.474（链路五连击 0.271→0.323→0.376→0.444→0.474），核心发现是：排序题不是日期算术题，是提及卫生题。

一、把"顺序"当减法做，是类别错误

前一轮我们拆掉了日期算术的墙：between/before/since-when/past-perfect 一族问题，本质都是两个锚点 + 日历减法。顺着这个思路，排序题（"order of / from first to last / who ... first"）看起来只是减法的 N 倍推广——给每个条目解析一个日期，排序，输出。

数据集取证给了一个反直觉的修正：LoCoMo temporal-133 里真正的排序题只有 9 题，但形态分类器还漏了一个兄弟种群——"Which event happened first, X or Y?"式的成对排序题，整整 29 题，只对 8 题。9 + 29 = 38 题，全错了或者没接住。而且回看这 9 题的语料：没有一题需要 TIMEX 解析。博物馆、演唱会、航空公司、看过的球赛——每个事件的真实锚点就是"我今天去了 MoCA"这类新鲜报告所在的 session 日期，周/月尺度下天粒度就够。

所以机制反转了：上一轮（#077 past-perfect duration）算术是机制、锚点简单；这一轮锚点本身就是机制——难点不是"事件发生在何时"，而是"记忆库里哪一次提及是这件事的出生证明"。

二、事实的出生证明：fresh > vague-recall > planning

一个条目在对话里会被提及很多次，不是所有提及生而平等。语料里有一道 MoCA 题：session [6] 里说 "recently attended the MoCA"（模糊回忆），session [9] 里说 "just came back from the MoCA"（新鲜报告）。GT 锚定在 [9]——即使 [6] 出现更早。这不是标注随意，是数据集真值约定：recently 类提及是事件的滞后追述，锚到它身上会把排序系统性推晚。

于是锚点扫描器有了三层互斥优先级：新鲜报告（today/just/yesterday/this morning）> 模糊回忆（recently 类事件句）> 计划（thinking of / can't wait）。计划层直接排除——"我在考虑下次去 Yosemite"不是事件，是意图。这和上一轮的日期方向性信任门（过去=召回，远未来=计划）汇成同一条原则：**对话记忆里，提及的方向和质量就是信任信号**。

FRESH = re.compile(r"\b(today|just|yesterday|this morning|last night|tonight)\b", re.I)

def scan_anchor(item_kws, lines, window=None, ctx=None):
    """FRESH 在行级评估（话语时间戳）；planning/eventive 在子句级评估"""
    fresh_hits, vague_hits = [], []
    for d, idx, line in lines:
        if window and not (window[0] <= d <= window[1]):   # 时间窗，杀窗外语料
            continue
        if not all(k in line.lower() for k in item_kws):
            continue
        if FRESH.search(line):
            rd = d - timedelta(days=1) if YESTERDAY.search(line) else d
            fresh_hits.append((rd, idx, line))
        elif any(EVENTIVE.search(w) and not PLANNING.search(w) for w in windows):
            vague_hits.append((d, idx, line))          # 模糊回忆池
    pool = fresh_hits or vague_hits                     # 三层优先级落在这里
    pool.sort(key=lambda x: (x[0], x[1]))
    return pool[0]  # 最早的合格提及 = 出生证明

一行代码里藏着整个世界观：pool = fresh_hits or vague_hits——只要有任何新鲜报告存在，全部模糊回忆出局。原型 9/9 全对（基线 0/9），生产化后 C488 把 temporal exact 从 0.376 拉到 0.444（+9/-0，零劫持：严格形态门恰好命中 9 题且全部原本是错的）。

二点五、成对排序的"哪个先"门（C489）

29 题的兄弟种群当晚一并接住，但多三件武器：分钟粒度锚点（成对题里两个事件常在同一 session，天粒度分不出先后）、动词一致性（问句动词和证据句动词要 congruent）、负存在弃权（"X 或 Y 哪个先"里若 Y 在语料中根本不存在，abstain 而不是硬答）。C489：0.444 → 0.474，+4/-0。

值得单独写一笔的是纪律：形态分类器的宽版本会同时命中 38 题，但我们只放严格模式命中的 9 题进生产。理由冷峻——那 29 题里有 8 题本来是对的，用一个未验证的渲染路径去路由它们，最可能的结局是把对的改错。机制复用不等于门共用。

三、子句是意图的单位，行是时间的单位

_most_ 微妙的一类错误来自粒度混用。"today" 时间戳整行生效（话语层标记），但意图是子句作用域的：

"I'm thinking of ordering food for the next game, … I'm still on a high from watching the NFL playoffs"

同一行，两个子句，两个事件：NFL 那句是干净证据（看了 playoffs），"next game" 那句是计划（点外卖还没发生）。在行级评估 planning 过滤器，会把 NFL 锚点一起杀掉（假阴性）；在子句级评估，两个都各得其所。所以扫描器里两个粒度并存：FRESH 按行查，planning/eventive 按子句窗口查——且窗口要允许跨逗号延伸（"gift ideas for my cousin Alex, who graduated ... two weeks ago"，提及和它的谓词被逗号隔开）。

四、标签归一化：子串包含 ≠ 关键词子集

类别集排序题（"我参观过的博物馆"）要先从语料里抽出条目清单，抽出来天然是脏的：所有格（"the Art's"）、动词前缀（"finished a 5K run"）、同义变体（"Billie concert" vs "the Billie Eilish show"）。归一化靠确定性规则迭代剥离：

def canon_label(s):
    s = re.sub(r"'s\b", "", s).strip()        # 所有格
    strip = re.compile(r"^(?:the|a|an|finished|completed|recently|"
                       r"attended|back|from|been|to|of|my|at)\s+", re.I)
    prev = None
    while prev != s:                          # 迭代剥离动词/限定词前缀
        prev = s
        s = strip.sub("", s)
    return s

合并同义项时踩到一个值得记住的坑：关键词子集合并会过度合并。"Museum of History" 的关键词集合是 "Natural History Museum" 的子集，但它们是两家不同的博物馆。改用子串包含（"5K run" ⊂ "the Midsummer 5K Run" ✓，"Museum of History" ⊄ "Natural History Museum" ✓）后，最脏的演唱会题从 24 个原始候选收敛到恰好 5 个 GT 条目，答案路径里零人工清单。

五、可操作建议

  • 排序前先问：真的需要日期吗。对话日志的排序题大概率只需要"每个条目最早合格提及的 session 序号"。TIMEX 是最后手段，不是第一步。
  • 给提及分层：fresh / vague-recall / planning。任何"哪次提及算数"的规则里，计划永远垫底；只要有新鲜报告在，模糊回忆全部出局。
  • 意图过滤按子句，时间戳按行。一行多子句混 planning + 证据是常态，不是边缘 case。
  • 实体合并用子串包含，不用关键词子集。集合包含是语义判断的劣质代理。
  • 新机制上线前做劫持面审计：宽分类器命中多少题、其中多少题现在是对的。有任何一题是对的，就收窄门，先在子集上 A/B。

复盘这五连击（0.271→0.474），每一环都是同一个方法论：取证错误家族 → 语料 census 修正人口 → stdlib 原型全对 → 严格形态门零劫持上线 → 逐题 A/B 零回归。没有 LLM 调用，没有 embedding，全部是对语料约定的逆向工程。评测分数不是玄学，是别人没读说明书。
