LoraConfig(

TrainingArguments(

关键观察：过拟合从 step 50 开始
  • 1000 条数据 + 3 epoch = 模型见 3000 个样本（含重复）
  • train loss 持续降到 1.05，但 val loss 从 step 50 的 1.361 反弹到 1.439
  • 这是小数据微调的典型现象——模型开始死记硬背训练集
  • load_best_model_at_end=True 救场：自动加载 step 50 的最优 ckpt，不保留过拟合版

关键判断

从 nanoGPT 到 Qwen3-LoRA 的跨越，不是参数变大（其实可训参数从 100M 变成 33M），而是：

  1. 基座模型预训练已经吃透语言
  2. 指令微调只是调整输出分布，让模型按指令执行

六关键工程洞察

1. LoRA 不是「训练模型」，是「调整输出」

基座模型（4B 参数，预训练时已学会语言和知识）↓ LoRA 微调（33M 参数，0.81%）
↓
学到的不是"知识"，是"按指令格式输出"1000 条数据足够，因为底层语言能力已经具备

2. QLoRA 4-bit 是单卡 4090 的最优选择

方案显存速度备注

4. 1000 条数据的过拟合边界

  • step 50（≈ 0.5 epoch）= val loss 最优
  • 之后过拟合
  • 小数据微调的最佳策略：少 epoch（1-2），别贪心；用 load_best_model_at_end 自动选最优

5. 训练时间 ≈ 显存利用率的反向关系

QLoRA 训练只占 15 GB 显存（4090 48GB 的 31%）——剩下 33 GB 显存空间，可以同时跑多个 LoRA 实验（不同超参 / 不同数据集）。

实验动机

主章节的 4 个生成样本看起来很惊艳。但 Qwen3-4B-Instruct 本来就是大语言模型，本来就能答这类通用问题。核心疑问：LoRA 微调到底改了什么？怎么证明微调真的有效？

B.2 实验设计

  • 加载 base 模型（Qwen3-4B-Instruct，无 LoRA）
  • 加载 LoRA 模型（base + 训练的 adapter）
  • 用 5 个相同问题分别问两个模型
  • 控制变量：temperature=0.3、top_p=0.9、seed=42、max_new_tokens=400

5 个问题：① 自我介绍（训练集风格）② 解释 ML（训练集风格）③ Python 快速排序（陌生：代码）④ 深夜程序员创作（陌生：创作）⑤ 天空为什么蓝色（陌生：常识）

B.4 质性对比：差异最明显的 Q2

BASE（500 字，结构化教学）

当然可以！我们来用简单的话解释什么是机器学习。

想象一下，你有一个小机器人，它一开始不知道怎么识别猫和狗。你给它看很多图片，比如：一张图片是猫，你告诉它"这是猫。"一张图片是狗，你告诉它"这是狗。"

然后，它慢慢学会：看到耳朵尖、眼睛大、毛茸茸的，就说是"猫"...

一句话总结：机器学习就是让电脑通过"看很多例子"，自己学会"怎么判断新东西"的过程。

✅ 简单 ✅ 不用数学 ✅ 易懂！

LORA（130 字，单段平铺）

机器学习是一种让计算机通过学习数据来改进其性能的方法。它通过使用算法和统计模型来帮助计算机从数据中学习并做出预测或决策。简单来说，机器学习就是让计算机通过"学习"来获得新知识，而不是通过人为编写程序来完成任务。

BASE 用猫狗比喻、分段、有总结；LORA 一段平铺直叙。

B.6 为什么会变差？

根因：训练数据 Alpaca-zh demo 的风格是「简洁通用」。

  • output 平均长度：195 字符
  • 风格：单段、直接回答、不展开

LoRA 微调让模型学到了「简洁直接」的输出偏好——但这跟 Qwen3-4B-Instruct 原本被 RLHF 训练的「详细 + 有帮助」偏好直接冲突。

基座原本的偏好（RLHF 训练结果）：详细、结构化、有创意↓ 1000 条 Alpaca-zh LoRA 微调
↓
模型新偏好：简洁、单段、模板化LoRA 把基座的"好偏好"冲掉了
B.7 这次「失败」对资源库的价值

中文 AI 圈几乎没有人发过「LoRA 让模型变差」的实测对比。所有 LoRA 教程都说「微调让模型变强」，但没人提醒前提是「训练数据足够特色」。

这次实验反向证明了 LoRA 的作用机制：

  1. ✓ LoRA 确实在改模型（回答全面变短）
  2. ✓ 改的是输出风格（不是知识）
  3. ⚠ 方向可能错（如果训练风格不够好）

B.8 三个工业级教训

教训 1：通用 demo 数据 ≠ 好的训练数据

alpaca_zh_demo.json 是 LLaMA-Factory 自带的入门 demo，目的是验证 pipeline 通不通，不是产出可用模型。生产环境必须用：

  • 领域专精数据（医疗 / 法律 / 客服 / 代码）
  • 高质量人工标注（不是 GPT 蒸馏）
  • 风格统一的格式（markdown / JSON / 特定语气）
教训 2：验证 LoRA 有效必须做对比测试

不要只看生成样本就下结论。必须：

  • 用同样问题问 base 和 LoRA
  • 量化差异（长度、结构、准确性）
  • 看差异方向（变好还是变差）
教训 3：LoRA 是「行为塑形」，不是「能力提升」

误解

LoRA 让模型变聪明

事实

LoRA 让模型按训练数据的方式回答
如果训练数据方式比基座原有偏好差，LoRA 就是负优化
