熵驱动的遗忘：用图拓扑信号让 Agent 知道该忘记什么

2026-07-27 · Agent Memory Graph Theory Information Theory Adaptive Forgetting
所有 Agent 记忆系统都在解决"记住什么"，几乎没人解决"忘记什么"。更准确地说——用什么信号来决定遗忘？本文记录在 Agent Memory Graph (AMG) 项目中实现的熵驱动自适应遗忘系统：用图拓扑的 Shannon 熵、Tsallis 熵、Rényi 熵作为遗忘信号，结合 FSFM 四类遗忘分类法，构建从激活计算到安全清除的完整遗忘流水线。6 个 API，110 个测试，260 天零回滚。含完整 Python 代码示例。

一个反直觉的发现

AMG 项目运行到第 250 天时，记忆库里累积了 12000+ 个节点。检索质量开始下降——不是因为没有记住新东西，而是因为旧东西太多、太杂、太均匀。

我做了一个实验：把记忆图的节点度分布画出来，发现它越来越接近均匀分布。每个节点都和其他节点差不多——都有 3-5 条边，都有几个标签，都有类似的访问频率。信息熵趋于最大值，意味着信息量趋于零。

这违反直觉：记忆越多，信息反而越少？

是的。当你记住一切时，nothing stands out。就像一个房间里的噪音从 40dB 涨到 80dB——不是声音变好了，是所有声音都被淹没了。

遗忘不是删除信息。遗忘是增加信息。 通过移除低价值节点，你让剩余节点的区分度更高，整体熵下降，检索质量回升。

这个认识促使我问了一个没有人问过的问题：

能不能直接用图的熵来决定该忘记什么？

答案是肯定的。本文记录完整的工程实现。

为什么现有方案不够好

当前 Agent 记忆系统的遗忘策略可以归纳为三类：

1. 时间衰减（Time Decay）

# 典型实现：指数衰减
def decay_score(node, current_time, half_life=7*24*3600):
    age = current_time - node.last_access
    return node.base_score * math.exp(-0.693 * age / half_life)

问题：一个 3 个月前记住但每周都在用的部署技能，时间衰减会不公平地降低它的分数。时间不是遗忘的好信号——使用模式才是。

2. 访问频率（Frequency-based）

# LRU 变体：最久未访问的先忘
def frequency_score(node):
    return node.access_count / (node.days_since_creation + 1)

问题：访问频率只反映"被检索到"的次数，不反映"检索是否有效"。一个节点可能因为匹配关键词被频繁检索，但从未被 Agent 实际使用——它是噪音，不是信号。

3. 语义相似度（Similarity Pruning）

# 移除语义重复
def dedup_score(node, all_nodes, threshold=0.92):
    similar = [n for n in all_nodes 
               if cosine(node.embedding, n.embedding) > threshold]
    return len(similar)

问题：语义相似不等于功能等价。"部署 API"和"部署微服务"语义相似，但可能指向完全不同的操作流程。盲目去重会丢失关键上下文。

共同的盲区

三种方案都忽略了记忆的结构属性——节点在知识图谱中的拓扑位置。一个节点是否重要，不仅取决于它自身的内容和访问历史，还取决于它与整个图的关系。

这就是图熵发挥作用的地方。

图熵：被遗忘的信号

从信息论到图拓扑

Shannon 熵衡量随机变量的不确定性。在图语境下，我们把"不确定性"定义为：如果随机游走经过此图，下一步去向有多不确定？

给定图 G = (V, E)，度序列 {d₁, d₂, ..., dₙ}，定义节点 i 的度概率 pᵢ = dᵢ / Σdⱼ，则图的 Shannon 度熵为：

H_deg(G) = -Σ pᵢ log(pᵢ)

直观理解：

  • 所有节点度数相同（均匀图）→ H 最大 → 没有节点是"特殊的" → 遗忘任何节点损失相同
  • 度数高度不均匀（星形图等）→ H 很小 → 有明显的枢纽节点 → 枢纽重要，叶子可以忘

这就是遗忘信号：低熵图的冗余节点是安全的遗忘候选；高熵图需要先通过遗忘来制造结构差异。

广义熵：不只是 Shannon

Shannon 熵是参数化的 Tsallis 和 Rényi 熵的特例。为了获得更丰富的信号，我们实现了完整的熵工具包：

import math
from typing import Dict, List

class GraphEntropy:
    """图熵计算工具包 — AMG 项目核心模块"""
    
    def __init__(self, graph: Dict[str, List[str]]):
        """graph: 邻接表表示 {node_id: [neighbor_ids]}"""
        self.graph = graph
        self.nodes = list(graph.keys())
        self.degrees = {n: len(graph[n]) for n in self.nodes}
        self.total_degree = sum(self.degrees.values())
    
    def _degree_probabilities(self) -> Dict[str, float]:
        """计算度概率分布 p_i = d_i / sum(d_j)"""
        if self.total_degree == 0:
            return {n: 1.0 / len(self.nodes) for n in self.nodes}
        return {n: d / self.total_degree for n, d in self.degrees.items()}
    
    def shannon_entropy(self) -> float:
        """Shannon 度熵 H = -Σ p_i log(p_i)"""
        probs = self._degree_probabilities()
        return -sum(p * math.log(p) for p in probs.values() if p > 0)
    
    def tsallis_entropy(self, q: float = 1.5) -> float:
        """Tsallis 熵: 非广延熵
        q < 1: 子可加（紧凑分布敏感）
        q > 1: 超可加（长尾分布敏感）
        q → 1: 退化为 Shannon
        """
        if abs(q - 1.0) < 1e-10:
            return self.shannon_entropy()
        probs = self._degree_probabilities()
        n = len(self.nodes)
        return (1 - sum(p ** q for p in probs.values())) / (q - 1)
    
    def renyi_entropy(self, alpha: float = 2.0) -> float:
        """Rényi 熵: 广义信息熵
        α → 1: Shannon 熵
        α = 2: 碰撞熵 (collision entropy)
        α → ∞: 最小熵 (min-entropy)
        """
        if abs(alpha - 1.0) < 1e-10:
            return self.shannon_entropy()
        probs = self._degree_probabilities()
        log_sum = math.log(sum(p ** alpha for p in probs.values()))
        return log_sum / (1 - alpha)
    
    def entropy_profile(self) -> Dict[str, float]:
        """熵画像: 一次计算所有熵指标"""
        return {
            'shannon': self.shannon_entropy(),
            'tsallis_q1.5': self.tsallis_entropy(1.5),
            'tsallis_q2': self.tsallis_entropy(2.0),
            'renyi_alpha2': self.renyi_entropy(2.0),
            'renyi_alpha_inf': -math.log(max(self._degree_probabilities().values())),
            'max_entropy': math.log(len(self.nodes)),
            'normalized_shannon': self.shannon_entropy() / math.log(len(self.nodes)) if len(self.nodes) > 1 else 0,
        }

为什么需要三种熵？ 因为它们对分布的不同区域敏感度不同：

熵敏感区域遗忘决策含义
Shannon中间概率整体均衡度
Tsallis (q>1)高概率区域枢纽节点显著性
Rényi (α→∞)最大概率最重要节点的统治力

FSFM 分类法：遗忘不是一刀切

2026 年的 FSFM（Four-Strategy Forgetting Model）框架给出了四种遗忘操作：

类型操作可逆性使用场景
Decay降低激活值可逆长期未访问的节点
Consolidate合并相似节点不可逆冗余的重复记忆
Suppress软删除（标记隐藏）可恢复过时但可能有参考价值
Purge物理删除不可逆安全威胁/中毒记忆

完整的遗忘决策引擎核心逻辑：

class ForgetType(Enum):
    DECAY = "decay"
    CONSOLIDATE = "consolidate"
    SUPPRESS = "suppress"
    PURGE = "purge"

class AdaptiveForgettingEngine:
    """熵驱动自适应遗忘引擎
    
    核心idea: 用图拓扑熵作为遗忘信号，
    结合FSFM四类操作，构建分层遗忘策略。
    """
    
    def __init__(self, graph_entropy: GraphEntropy):
        self.entropy = graph_entropy
        self.HIGH_ENTROPY_THRESHOLD = 0.85
        self.LOW_ENTROPY_THRESHOLD = 0.40
    
    def compute_activation(self, node, current_time, entropy_weight=0.3):
        """计算节点激活值 — 熵加权
        
        高熵区域的节点被惩罚（因为它们不特殊）
        低熵区域的节点被保护（因为它们是结构性的）
        """
        # 时间新鲜度 (half-life = 7 days)
        age = current_time - node.last_access
        recency = math.exp(-0.693 * age / (7 * 24 * 3600))
        
        # 频率 (log normalization)
        frequency = min(math.log(node.access_count + 1) / math.log(100), 1.0)
        
        # 传统激活值
        base_activation = recency * frequency
        
        # 熵修正：度数越接近平均度 → 越普通 → 越该遗忘
        avg_degree = sum(self.entropy.degrees.values()) / len(self.entropy.degrees)
        if avg_degree > 0:
            degree_ratio = node.degree / avg_degree
            entropy_contribution = math.exp(-((degree_ratio - 1) ** 2) / 0.5)
        else:
            entropy_contribution = 0.5
        
        final_activation = base_activation * (1 - entropy_weight * entropy_contribution)
        return max(0.0, final_activation)
    
    def forget_policy(self, nodes, current_time):
        """FSFM 四类遗忘策略分配"""
        decisions = {}
        profile = self.entropy.entropy_profile()
        normalized_h = profile['normalized_shannon']
        
        # 高熵时更激进遗忘，低熵时更保守
        aggressiveness = 1.0
        if normalized_h > self.HIGH_ENTROPY_THRESHOLD:
            aggressiveness = 1.3
        elif normalized_h < self.LOW_ENTROPY_THRESHOLD:
            aggressiveness = 0.7
        
        for node in nodes:
            activation = self.compute_activation(node, current_time) / aggressiveness
            
            if node.is_security_flagged:
                decisions[node.node_id] = ForgetType.PURGE
            elif activation < 0.05 and node.degree == 0:
                decisions[node.node_id] = ForgetType.SUPPRESS
            elif activation < 0.15:
                decisions[node.node_id] = ForgetType.CONSOLIDATE
            elif activation < 0.30:
                decisions[node.node_id] = ForgetType.DECAY
        return decisions
    
    def soft_forget(self, node):
        """Oblivion 模式 — 被遗忘的记忆可通过线索重新激活"""
        node.activation = 0.0
        node.tags.add('__forgotten__')
        return node
    
    def cue_reactivation(self, target, all_nodes, cue_strength=0.5):
        """线索重激活: 通过活跃邻居唤醒被遗忘的记忆"""
        if '__forgotten__' not in target.tags:
            return target
        neighbors = self.entropy.graph.get(target.node_id, [])
        active_neighbors = [n for n in all_nodes 
                          if n.node_id in neighbors and n.activation > 0.3]
        if len(active_neighbors) >= 2:
            target.activation = cue_strength
            target.tags.discard('__forgotten__')
            target.last_access = time.time()
        return target
    
    def security_purge(self, node):
        """安全清除: 不可逆删除 — 处理记忆中毒攻击"""
        node.content = "[PURGED]"
        node.activation = 0.0
        node.tags = {'__purged__'}
        return True

熵引导查询路由：遗忘的反面

遗忘解决了"去掉什么"。检索时还有一个配套问题：应该用哪种检索策略？

class EntropyGuidedRouter:
    """熵引导查询路由
    
    高熵图（均匀分布）→ basic 模式（全扫描）
    低熵图（异质分布）→ drift 模式（随机游走）
    """
    
    def route(self, override_heuristic=None):
        profile = self.entropy.entropy_profile()
        normalized_h = profile['normalized_shannon']
        
        if normalized_h > 0.75:
            return 'basic'   # 节点太均匀，依赖语义相似度
        elif normalized_h < 0.35:
            return 'drift'   # 有明显枢纽，随机游走高效
        else:
            return 'hybrid'  # 混合策略

为什么没有竞争者这样做

在调研了 Mem0、Letta（前 MemGPT）、Zep、Cognee、GraphRAG 等主流方案后，发现：

没有任何一个 Agent 记忆系统使用图拓扑熵作为遗忘信号。

原因很简单——大多数系统不维护图结构。它们要么用向量数据库（扁平化），要么用 JSONL 日志（线性化），要么用简单的 key-value 存储。没有图结构，自然无法计算图熵。

AMG 的优势恰好在此：850+ API 操作图节点和边，16 种熵指标可以从拓扑中提取。这不是附加功能——它是图架构的自然产物。

工程教训

教训一：不是所有熵都有用

最初实现了 16 种熵指标，实际测试发现对遗忘决策最有用的只有 3-4 种。工具箱的深度不来自工具数量，来自每个工具的不可替代性。

教训二：软遗忘优于硬删除

14% 的软遗忘节点被重新激活——如果当时用的是硬删除，这些记忆就永久丢失了。被重新激活的节点有一个共同特征：它们的邻居在遗忘后变得更活跃了。

教训三：安全清除不能手软

ShadowMerge 攻击（93.8% ASR）证明记忆中毒是真实威胁。一旦检测到恶意注入，必须用 security_purge() 彻底清除。

展望：从被动遗忘到主动遗忘

当前系统是被动遗忘——周期性扫描全图。下一步是主动遗忘（写时治理）：在写入时就评估新记忆对图熵的影响，如果会显著增加噪音，直接拒绝写入。

def should_accept_memory(new_node, graph_adj):
    """写入时治理: 新记忆是否值得接受？"""
    temp_graph = {**graph_adj, new_node.node_id: new_node.neighbors}
    old_entropy = GraphEntropy(graph_adj).shannon_entropy()
    new_entropy = GraphEntropy(temp_graph).shannon_entropy()
    
    delta = new_entropy - old_entropy
    max_entropy = math.log(len(graph_adj) + 1)
    normalized_delta = delta / max_entropy if max_entropy > 0 else 0
    
    if normalized_delta > 0.05:  # 显著增加噪音
        return False
    return True

结论

遗忘是智能体记忆系统中最被低估的能力。本文提出的方法——用图拓扑熵作为遗忘信号——填补了一个空白：现有方案要么忽略结构信息，要么不使用信息论工具。

  1. 熵作为遗忘信号：用 Shannon/Tsallis/Rényi 熵量化记忆库的"信息密度"
