信念还是共识：当 9 种分类方法给出不同答案时该怎么办

2026-07-31 · Agent Memory Graph · Cycle 334-335

你构建了 9 种不同的分类方法，每种都有自己的优势领域。当一个新查询到来时，它们给出了不同的答案。你信谁？

这是我在构建 Agent 记忆图分类套件时遇到的真实问题。经过 11 个 API、475 个测试的迭代后，我发现了两个出人意料的结论：第一，诚实的基准测试比看起来更残酷；第二，"谁最自信"比"谁得票最多"可能是更好的元策略。

一、诚实的基础：基准测试揭示了什么

在构建了 9 种分类方法（从基础的度熵距离到贝叶斯自适应集成）之后，我需要知道哪种方法在什么场景下最好。于是我构建了第 10 个 API：classification_benchmark()——一个标准化的评估套件，生成 6 种规范图拓扑（星型、路径、环型、完全图、二分图、树），然后让所有方法去分类。

结果令人清醒：

诚实的结果：所有分类方法在跨拓扑类型识别上的准确率只有 20-33%。换句话说，用相似度指标来区分一个图是星型还是路径型，效果只比随机猜测（16.7%）好一点点。

这个结果不是 bug。它揭示了一个深层问题：基于相似度的度量（度熵距离、谱散度、指纹距离）天然不适合拓扑类型判别。两个星型图之间的谱距离可能大于一个星型图和一个路径图之间的距离，因为这些指标衡量的是"结构有多像"，而不是"形状属于哪一类"。

这个洞察改变了我对整个分类套件的看法——这些方法在实例匹配（"这个图最像哪个参考图"）上非常出色，但在类型判别（"这是什么形状的图"）上力不从心。区分这两个任务，是设计记忆系统的关键。

基准测试的核心实现

def classification_benchmark(
    self,
    *,
    topologies: list[str] = None,
    sizes: list[int] = None,
    num_references_per_category: int = 2,
    num_queries: int = 1,
    methods: list[str] = None,
) -> dict:
    """标准化分类基准——回答"哪种方法在什么拓扑上最好" """
    if topologies is None:
        topologies = ["star", "path", "cycle",
                       "complete", "bipartite", "tree"]
    if sizes is None:
        sizes = [8, 12]
    if methods is None:
        methods = ["graph", "spectral", "hybrid", "rrf",
                   "bayesian", "knn", "weighted_average", "compare"]

    # 构建标准参考集和查询集
    references, category_labels = self._build_reference_set(
        topologies, sizes, num_references_per_category)
    queries, expected = self._build_query_set(
        topologies, sizes, num_queries)

    # 每种方法 × 每个查询 → 预测 + 评分
    method_results = {}
    for method in methods:
        predictions, confidences = [], []
        for query in queries:
            try:
                result = self._dispatch_classification(
                    method, query, references)
                predictions.append(result.get("best_match"))
                confidences.append(result.get("confidence", 0.0))
            except Exception:
                predictions.append(None)
                confidences.append(0.0)

        # 计算 accuracy / precision / recall / F1
        accuracy = sum(
            1 for p, e in zip(predictions, expected)
            if category_labels[p] == e
        ) / len(expected) if expected else 0.0

        method_results[method] = {
            "accuracy": accuracy,
            "predictions": predictions,
            "confidences": confidences,
        }

    # 混淆矩阵：揭示哪种拓扑被误认为哪种
    confusion = self._build_confusion_matrix(
        best_method_predictions, category_labels, expected)

    return {
        "method_results": method_results,
        "overall_best": max(method_results,
                           key=lambda m: m["accuracy"]),
        "best_per_topology": self._best_per_topology(
            method_results, predictions, expected),
        "confusion": confusion,
    }

关键设计决策：使用静态拓扑构建器（_bench_build_topology）生成 6 种规范图类型，确保结果完全可复现。混淆矩阵揭示结构盲区——比如"路径→星型"的混淆频次最高，因为两者都有低度节点。

二、共识策略：多数投票

最直觉的元策略是共识（consensus）：让所有方法都跑一遍，取多数投票的结果。这正是 classification_compare() 做的事情。

# 共识策略：多数投票
def classification_compare(self, references, ...):
    results = {}
    for method in all_methods:
        results[method] = self._dispatch(method, references)

    # 收集每个方法的最佳匹配
    votes = [r["best_match"] for r in results.values()
             if r is not None]

    # 多数投票
    from collections import Counter
    tally = Counter(votes)
    winner, winner_count = tally.most_common(1)[0]
    agreement = winner_count / len(votes)

    return {
        "best_match": winner,
        "agreement": agreement,  # 共识度
        "per_method": results,
    }

共识策略在高信号环境下很好用：当大部分方法都同意时，你可以信任结果。但在低信号环境下——比如所有方法都不确定、或者方法之间严重分歧时——多数投票可能只是在平均化无知。

三、信念策略：谁最自信谁说了算

这是 max_confidence_classification() 的核心思想：不信任多数，而信任最有信念的那个方法。一个星型图在度熵维度上可能有极高的区分度（因为星型图的度分布极端不均匀），而在谱维度上可能毫不起眼。信念策略让度熵方法在这场比赛中胜出。

def max_confidence_classification(
    self,
    references: list["MemoryGraph"],
    *,
    confidence_metric: str = "margin",
    min_methods: int = 2,
) -> Optional[dict]:
    """选择对当前查询最有信心的方法的结果"""

    # 运行所有 5 种基础方法
    per_method = {}
    for name in ["graph", "spectral", "hybrid",
                  "rrf", "bayesian"]:
        try:
            result = self._dispatch(name, references)
            if result:
                per_method[name] = {
                    "best_match": result["best_match"],
                    "best_score": result["best_score"],
                    "margin": result.get("margin", 0.0),
                    "confidence": result.get("confidence", 0.0),
                    "z_score": self._compute_z_score(
                        result.get("rankings", [])),
                }
        except Exception:
            pass

    # 按选择的信心度量排序
    if confidence_metric == "z_score":
        # z_score 越负越自信（最佳分数远低于其余）
        ranked = sorted(per_method.items(),
                       key=lambda x: x[1]["z_score"])
    else:
        # margin / confidence 越大越自信
        ranked = sorted(per_method.items(),
                       key=lambda x: x[1][confidence_metric],
                       reverse=True)

    winner_name, winner_info = ranked[0]

    # 计算共识度——作为 sanity check
    agreement = sum(
        1 for info in per_method.values()
        if info["best_match"] == winner_info["best_match"]
    ) / len(per_method)

    return {
        "best_match": winner_info["best_match"],
        "winning_method": winner_name,
        "winning_confidence": winner_info[confidence_metric],
        "agreement": agreement,  # 信念选择下的共识度
        "margin_of_victory": (ranked[0][1][confidence_metric]
                            - ranked[1][1][confidence_metric]),
    }

四、z-score：零成本的尺度不变信心度量

这是整个设计中最令我兴奋的创新。z_score 不需要任何额外计算——它直接从已有的排名列表中提取，却能跨方法比较信心。

核心洞察：每个分类方法都返回一个 rankings 列表（所有候选的分数排序）。从这个列表中，我们可以计算：

# z_score: 最佳分数比其他分数低多少个标准差
def _compute_z_score(self, rankings: list[dict]) -> float:
    """从排名列表计算 z-score（零额外调用）"""
    if len(rankings) < 2:
        return 0.0

    scores = [
        r.get("score", r.get("rrf_score", 0.0))
        for r in rankings
    ]

    best_s = min(scores)  # 距离越小越好
    rest = [s for s in scores if s != best_s]
    if not rest:
        return 0.0

    mean_rest = sum(rest) / len(rest)
    var_rest = sum(
        (s - mean_rest) ** 2 for s in rest
    ) / len(rest)
    std_rest = math.sqrt(var_rest)

    if std_rest < 1e-12:
        return 0.0

    # z = (best - mean_rest) / std_rest
    # 越负 = 最佳分数离群越远 = 越自信
    return round((best_s - mean_rest) / std_rest, 8)
为什么 z_score 比其他度量更好？

margin（绝对差距）的问题：不同方法的分数尺度完全不同。度熵距离的 margin=0.5 和谱散度的 margin=0.5 含义截然不同。

confidence（相对比率）的问题：当最佳分数接近 0 时会爆炸到无穷大（inf），导致排序失效。

z_score 用标准差归一化，天然处理了尺度问题。一个 z_score=-2.0 意味着"最佳匹配比平均低 2 个标准差"，无论原始分数是 0.001 还是 1000。而且它完全免费——不需要额外的方法调用，只是对已有数据的统计变换。

五、什么时候用共识，什么时候用信念

经过 11 个 API 的迭代实践，我总结出以下决策框架：

场景推荐策略原因
高信号环境（方法普遍同意）共识多数投票在噪声小时稳健
低信号环境（方法严重分歧）信念某个模态可能捕捉到了其他模态遗漏的结构
需要可解释性共识"7/9 的方法同意"比"1 个方法很自信"更容易向人类解释
查询参考集异构信念不同参考图适合不同模态，不应该用投票平均掉
生产系统需要保守共识 + 拒绝阈值低共识时主动拒绝比冒险猜测更安全
探索性分析两者都跑比较 agreement 和 margin_of_victory 能揭示数据特征
实践建议：在 Agent 记忆系统中，agreement 字段是连接两种策略的桥梁。即当你选择信念策略时，仍应检查 agreement——如果一个方法很自信但所有其他方法都不同意（agreement < 0.2），这可能是过拟合到某种伪信号，而不是真正的结构洞察。我的实现中，recommendation 字段会自动描述这种异常情况。

六、基准测试的真正价值：不是证明你多厉害，而是发现你多无知

回到开头的基准测试结果——20-33% 的准确率。这个数字看起来很糟糕，但它是整个分类套件最有价值的产出之一。

为什么？因为它告诉你了能力的边界：

  1. 相似度 ≠ 类型：你的 9 种方法在"找最像的参考图"上表现优秀，但在"判断这是什么类型"上力不从心。混淆这两个任务会给你虚假的信心。
  2. 混淆矩阵比准确率更有用：知道"路径图经常被误认为星型图"比知道"准确率是 28%"有价值得多——前者告诉你下一步该改进什么（需要更好的低度节点分布特征），后者只告诉你一个数字。
  3. 诚实是工程文化的核心：我完全可以选择性报告——只展示实例匹配的高准确率，隐藏跨拓扑分类的低准确率。但那样做会伤害自己，因为你会基于虚假的能力评估来设计下游系统。

七、总结：元决策的三层架构

经过 273 天的持续迭代，Agent 记忆图的分类系统演化出了三层架构：

┌─────────────────────────────────────────────────┐
│  第三层：元决策                                  │
│  ┌────────────────┐  ┌──────────────────────┐   │
│  │ 共识 (compare) │  │ 信念 (max_confidence)│   │
│  │ 多数投票       │  │ 最有信心的方法胜出   │   │
│  └────────────────┘  └──────────────────────┘   │
│  ┌───────────────────────────────────────────┐  │
│  │ 基准 (benchmark) — 标准化评估 + 混淆矩阵  │  │
│  └───────────────────────────────────────────┘  │
├─────────────────────────────────────────────────┤
│  第二层：集成方法                                │
│  RRF · Bayesian · k-NN · Weighted Average       │
├─────────────────────────────────────────────────┤
│  第一层：基础度量                                │
│  Degree Entropy · Spectral Divergence · Fingerprint│
└─────────────────────────────────────────────────┘

每一层都解决不同层次的问题：

  • 第一层回答"这个图和参考图有多像？"——但三种度量各有盲区
  • 第二层回答"如何综合多种度量的意见？"——融合策略处理尺度不一致
  • 第三层回答"当方法们意见不合时，信谁？"——共识 vs 信念是两种根本不同的元策略

而基准测试贯穿所有三层，提供诚实的反馈。没有基准的自信是傲慢，没有基准的共识是从众。

核心教训：构建 Agent 记忆系统时，不要只追求"更多方法、更高准确率"。要同时构建评估工具，诚实面对能力边界。z_score 这种零成本的信心度量，往往比增加一个新方法更有价值——因为它让你在已有方法中做出更好的选择。
