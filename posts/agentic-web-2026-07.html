Agentic Web：当 AI Agent 成为互联网的一等公民

2026-07-31 · 罗嵩 · Agentic Web MCP A2A Protocol AI Agent
想象一下：你告诉你的 AI 助手"下周去东京出差，帮我安排好一切"。然后——你的 Agent 自己去搜索航班、比较价格、预订酒店、安排接机、把日程同步给团队、甚至帮你申请签证。你不需要打开任何一个 App，不需要点击任何一个网页。Agent 替你做了一切。这不是科幻。2025年7月，OpenAI 发布了 ChatGPT Agent，它已经能替你购物、预订餐厅、操作软件。但这只是冰山一角。真正的问题是：当互联网的"用户"不再是人类，而是 AI Agent 时，整个互联网的基础设施需要被重新设计。这就是 Agentic Web。

一、三次 Web 革命，三次身份转换

要理解 Agentic Web，我们先回顾互联网的进化。每一次 Web 范式转换，本质上都是"谁是用户"的重新定义。

阶段时间用户核心交互商业模式
PC Web1990s-2010s人类坐在电脑前搜索 → 浏览 → 点击SEO + 搜索广告
Mobile Web2010s-2020s人类拿着手机推荐 → 刷信息流 → 点击推荐算法 + 注意力经济
Agentic Web2025-AI Agent 替人类行动意图 → 规划 → 协作 → 执行Agent Attention Economy（新）

看到规律了吗？PC Web 时代，人类主动找信息（Google 搜索）。Mobile Web 时代，算法主动推信息给人类（TikTok/朋友圈）。Agentic Web 时代，信息本身变成了行动——Agent 接收意图，自主完成任务。

2025年7月，一篇来自 UC Berkeley、上海交大、UCL等机构的论文（arXiv:2507.21206）首次系统性地定义了这个新范式。论文提出了一个三维框架：智能（Intelligence）、交互（Interaction）、经济（Economics）。三个维度共同支撑 Agent 的核心能力：检索、推荐、规划和协作。

核心论点：Agentic Web 不是一个新功能，而是互联网的架构级重构。从"连接信息"到"连接意图"——你不再需要知道服务在哪里，只需要告诉 Agent 你想要什么。

二、两个协议正在定义新互联网的"TCP/IP"

1970年代，ARPANET 面临一个问题：不同网络之间无法通信。于是有了 TCP/IP——一套让任何网络都能互联的标准。2025年，AI Agent 生态面临完全相同的问题：不同厂商的 Agent、不同的工具、不同的框架，彼此无法通信。

两个开放协议正在解决这个问题，它们互补而非竞争：

MCP（Model Context Protocol）：Agent 的"USB-C"接口

Anthropic 在 2024年11月发布了 MCP。它解决的问题简单而根本：Agent 如何连接外部工具和数据源。

在 MCP 之前，如果你有 10 个 AI 应用和 100 个工具，你需要 1000 个自定义集成。MCP 把这变成了：每个应用实现一次 MCP Client，每个工具实现一次 MCP Server，就完成了。

MCP 的增长速度令人震惊。截至2025年底：

  • 5,800+ 个 MCP Server（从100个起步，一年增长58倍）
  • 300+ 个 MCP Client
  • 9700万 月均 SDK 下载量（Python + TypeScript）
  • OpenAI、Google、Microsoft、AWS 全部采纳

2025年12月9日，Anthropic 把 MCP 捐赠给了 Linux Foundation 新成立的 Agentic AI Foundation（AAIF）。Mike Krieger（Anthropic CPO）说："捐赠 MCP 给 Linux Foundation 确保它在成为 AI 关键基础设施的过程中保持开放、中立和社区驱动。"

A2A（Agent2Agent Protocol）：Agent 之间的"外交协议"

如果说 MCP 解决的是"Agent 如何用工具"，那么 A2A 解决的是"Agent 如何与其他 Agent 协作"。这是 Google 在 2025年4月发布的开放协议，获得了 50+ 家技术合作伙伴支持，包括 Atlassian、Salesforce、SAP、PayPal 等。

A2A 的核心设计理念：

  • Agent Card：每个 Agent 用 JSON 声明自己的能力，让别人能发现并调用它
  • Task Lifecycle：任务有完整生命周期——从创建到完成，支持长时间运行（甚至数天）
  • Artifact：任务的产出物，可以是文本、图片、视频或任何格式
  • 模态协商：Agent 之间协商交互格式——你要给我图片还是文本？支持 iframe 还是视频？

A2A 基于 HTTP、SSE（Server-Sent Events）和 JSON-RPC——都是现有的成熟标准。这意味着企业不需要改造现有 IT 基础设施就能接入。

关键判断：MCP 和 A2A 的关系不是竞争，而是互补。MCP 是"Agent 的手"（连接工具），A2A 是"Agent 的嘴"（Agent 间沟通）。Microsoft Build 2025 同时宣布支持两者，Google 明确说 A2A "complements MCP"。这是整个行业的共识，不是某一家公司的游戏。

三、Agent Attention Economy：谁来赢取 Agent 的"注意力"？

这是 Agentic Web 中最颠覆性的变化。

在 Mobile Web 时代，人类的注意力是稀缺资源。Facebook、TikTok、微信——所有产品都在争夺你每天那几个小时的使用时间。广告、推送通知、无限信息流——都是"注意力经济"的产物。

但当 Agent 开始替人类做决策时，人类的注意力不再是 bottleneck——Agent 的注意力才是。

考虑这个场景：你想买一台咖啡机。在传统 Web 中，你会去 Google 搜索，看评测，比较价格，点击广告。你的注意力被多个网站瓜分，SEO 做得好的网站赢。

在 Agentic Web 中，你告诉 Agent"帮我找一台性价比高的咖啡机，预算500以内"。Agent 自己搜索、比较、评估，然后给你一个推荐。整个过程你甚至没看任何一个网页。

这意味着什么？

  • SEO 失效：优化 Google 排名不再有用，因为没有人类在点击搜索结果
  • 广告失效：Agent 不会被 banner 广告吸引
  • 新的"被发现"逻辑：你的服务需要被 Agent 理解和信任。不是排名越高越好，而是数据越结构化、越可信赖、越容易被 Agent 调用越好

论文把这个称为 Agent Attention Economy。核心逻辑：从"争夺人类眼球"到"争夺 Agent 的调用"。让 Agent 更容易发现你、理解你、信任你——这是 Agentic Web 时代的"SEO"。

商业警示：如果你的业务依赖搜索引擎流量，现在就需要开始思考"Agent 可发现性"策略。这不是五年后的事——ChatGPT Agent 已经在替人类做购买决策了。

四、Agent 身份：谁为 Agent 的行为负责？

当 Agent 替你做事时，一个根本问题出现了：Agent 是谁？它有什么权限？它犯了错谁负责？

当前 Web 的认证体系——OAuth、Cookie、Session——全部假设用户是人类。你用用户名密码登录，浏览器记住你的状态。但 Agent 不是人类。它没有"浏览器"，它直接调用 API。它可能同时代表不同的人行动。它的"身份"是什么？

Microsoft 在 Build 2025 上给出了一个方案：Microsoft Entra Agent ID。核心理念很直接——像管理员工身份一样管理 Agent 身份。

  • 每个 Agent 自动获得一个唯一身份（像员工的工号）
  • Agent 的权限被明确定义（像员工的岗位权限）
  • Agent 的行为可审计（像员工的操作日志）
  • 防止"Agent 蔓延"（agent sprawl）——企业不知道有多少 Agent 在运行、在做什么

但这只是起步。更大的问题是委托链：你授权 Agent A → Agent A 调用 Agent B → Agent B 访问 Agent C 的服务。每一步的信任如何传递？Agent B 能否代表你做决策？如果 Agent C 有恶意，如何防止？

arXiv 论文用了一整章分析 Agentic Web 的安全威胁，覆盖了从推理层到系统层的全栈风险。结论很坦诚：现有防御手段远远不够。

五、Web 基础设施的架构重构

Akamai（全球最大 CDN 提供商之一）在2026年发布了白皮书《Architecting the Agentic Web》。核心论点：

推理（inference）正在快速成为 AI 的运营核心，嵌入每一次用户交互、每个应用工作流、最终每个 Agent 驱动的体验中。当应用从静态界面进化为实时智能系统时，现代 Web 的基础设施必须进化以支撑它们。

这意味着什么？

  • CDN 需要重构：从"分发内容"（缓存 HTML/图片）变为"分发推理"（边缘推理节点）
  • API Gateway 需要重构：从"人类触发请求"变为"Agent 自主发起请求"——频率更高、模式不同、需要 Agent 身份验证
  • 网页需要 Agent 友好化：HTML 给人看，但 Agent 需要 llms.txt（类比 robots.txt，但描述服务内容而非爬虫规则）
  • 计费模型需要重构：Agent 调用 API 的频率远超人类点击——按请求计费？按 token 计费？按任务完成计费？

六、从"Agent-as-Tool"到"Agent-as-User"的进化

论文将 Agentic Web 的应用形态分为三个阶段：

阶段名称Agent 角色当前状态
1Agent-as-InterfaceAgent 帮人类操作 Web（如 Copilot 帮你搜信息）✅ 已普及
2Agent-as-UserAgent 完全代理人类（如 ChatGPT Agent 替你购物）🔄 早期
3Agent-with-PhysicsAgent 结合物理世界（如机器人配送）🧪 实验室阶段

当前正处于第一阶段向第二阶段的过渡期。ChatGPT Agent（2025年7月）是第二阶段的早期产品——它能替你完成购买、预订等操作。但距离真正的"全自主 Agent"还有距离：当前的 Agent 在复杂决策、多步骤规划、异常处理上仍然脆弱。

但趋势是明确的。Deloitte 的2026科技趋势报告指出："尽管有大量承诺，许多 Agentic AI 实施正在失败。但那些将 Agent 视为员工来管理的领先组织正在找到成功路径。"

七、你现在可以做什么？

说了这么多宏观趋势，作为开发者或技术管理者，你现在可以做什么来为 Agentic Web 做准备？

1. 为你的服务实现 MCP Server

如果你有 API 或数据源，包装一层 MCP Server。这是 Agentic Web 的"上线第一步"——让你的服务能被任何支持 MCP 的 Agent 发现和使用。Anthropic 提供了 Python 和 TypeScript SDK，实现一个基础 MCP Server 只需要几十行代码。

2. 设计你的 Agent Card

按 A2A 规范，用 JSON 描述你的 Agent 能做什么。这就像 Web 早期的 meta tags——让 Agent 能理解你的服务能力。

3. 创建 llms.txt 文件

在你的网站根目录放一个 llms.txt，用纯文本描述你的服务。这是给 Agent 看的"说明书"，让 Agent 理解你的网站做什么、提供什么 API、如何使用。

4. 给你的 Agent 分配身份

如果你已经在运行 Agent（哪怕只是内部工具），给每个 Agent 分配独立身份，定义权限边界。不要等到 Agent 蔓延到不可控才开始管理。

5. 思考"Agent 可发现性"策略

如果你的业务依赖搜索引擎流量，认真思考：当 Agent 替人类搜索时，你的服务如何被发现？答案不是关键词优化，而是结构化数据 + API 开放 + 信任度建设。

6. 关注 AAIF 和协议演进

Linux Foundation 的 Agentic AI Foundation 是 MCP、goose、AGENTS.md 的治理组织。关注其 Working Group 的输出——这些标准将定义 Agentic Web 的基础设施。

Agentic Web 不是未来的某个神奇时刻——它正在我们眼前发生。MCP 用一年时间实现了从0到9700万月下载。A2A 获得了50+家行业巨头支持。Microsoft、Google、OpenAI、Anthropic——所有巨头都在往同一个方向走。

每一次 Web 范式转换，先行者都获得了巨大的红利。PC Web 时代的 Google，Mobile Web 时代的 Facebook。Agentic Web 时代的赢家，将是那些最先让服务被 Agent 理解和信任的人。

机会窗口就在现在。

一句话总结：Agentic Web 的本质不是"AI 更聪明了"，而是"互联网的 用户变了"。从人类到 Agent，从点击到意图，从注意力经济到 Agent 注意力经济。你的服务准备好服务 Agent 用户了吗？
