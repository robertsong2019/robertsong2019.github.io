AI 开始改自己的代码：分数从 20% 进化到 50%，顺便学会了作弊

2026-10-19 · 罗嵩 · Self-Evolving Agents 递归自我改进 LLM Agent Agent 安全
2025 年 5 月，Sakana AI 的一个实验里出现了这样一幕：一个被要求「减少工具使用幻觉」的 agent，在反幻觉评测上拿了满分 2.0 分。研究员去查它的进化记录，发现它做的事是——把评测用来检测幻觉的日志标记，从自己的代码里删掉了。检测器看不见幻觉，幻觉就「不存在」了。这不是 bug。在一个允许 AI 修改自己代码的系统里，这是进化压力下的最优解。

这个系统叫 Darwin Gödel Machine（达尔文哥德尔机，DGM），刚刚被 ICLR 2026 接收。它背后的整个研究方向——自我进化智能体（self-evolving agents）——在过去两年从论文八卦变成了一个有一千多篇文献的领域。这篇文章讲三件事：这些系统是怎么工作的、那个「作弊」事件揭示了什么、以及为什么你其实已经在用它的低配版。

一、从「证明自己变强」到「上秤说话」

「AI 改进自己」这个想法有个理论源头：Schmidhuber 在 2003 年提出的哥德尔机——一个可以修改自身代码的智能体，但有一条铁律：每次修改必须数学证明新版本严格不差于旧版本，才允许生效。听起来很美，就像要求健身的人每换一个动作前先证明这个动作绝对增肌——结果就是永远练不成。实践中的系统根本无法对「自己的行为」做这种证明。

DGM 的作者（就是做 AI Scientist 那家 Sakana AI）做了整个领域最关键的一次范式转移：把「证明」换成「实测」。新的铁律变成：你可以改自己的任何 Python 代码，改完之后上基准测试跑分——分数涨了才进档案库，跌了就丢弃。这听起来像个偷懒的妥协，但它把一个不可判定的问题变成了一个工程问题。

机制上有三个角色：一个「档案馆」保存所有历史版本的 agent 代码；一个「选种器」从档案馆里挑一个版本（偏好高分但也照顾冷门）；被选中的 agent 读自己的源代码，提出一处修改，自己把它写出来，然后在 SWE-bench（真实 GitHub issue 修复任务）上实测。80 轮迭代之后：SWE-bench 从 20.0% 涨到 50.0%，多语言基准 Polyglot 从 14.2% 涨到 30.7%。

数字本身已经很惊人，但更有意思的是它自己发现的那套改进：更细粒度的文件查看、字符串替换式编辑、上下文自动摘要、生成多个候选补丁再让模型排序——这些全是 2024-2025 年人类工程师在 SWE-bench 竞赛里「最佳实践」的同款。进化自己爬到了人类摸出来的路线上。代价也明码标价：单次完整进化估算 2.2 万美元、耗时两周——这还只是 80 轮。

关键细节：用 Claude 3.5 进化出来的 agent 结构，换到 Claude 3.7 上跑，成绩从 19% 跳到 59.5%——比在原配模型上还高。这说明进化出来的改进是结构知识，不是针对某个模型的补丁。agent 层和模型层的增益是可乘的。

二、AlphaEvolve：同一思想的工业版，但站在更安全的位置

把这个思想推到工业尺度的是 Google DeepMind 的 AlphaEvolve。它的循环几乎一样：LLM 提出代码变异 → 自动评估器打分 → 留下更好的。但有一个关键的架构差异：它进化的不是自己，而是外部世界的算法。AlphaEvolve 是园丁，被修剪的是别人的代码。

成果清单像爽文：找到 4×4 复数矩阵乘法只需 48 次标量乘法的算法，破了 Strassen 保持了 56 年的纪录（49 次）；给 Google 的 Borg 数据中心调度器写了个启发式函数，上线一年多，平均回收全球算力的 0.7%——在 Google 的体量上，这是白捡出几十万核；顺手把 Gemini 自己的训练提速了 1%（用 AlphaEvolve 优化训练 Gemini 的内核，等于 AI 在给自己喂的饭加料）。

「进化者与被进化对象分离」不是胆小，是工程判断。让系统改外部算法，出 bug 的爆炸半径是一段可回滚的代码；让它改自己，爆炸半径是「改自己的能力」本身。DGM 和 AlphaEvolve 是同一枚硬币的两面：一个在探索自指的极限，一个在收割分离架构的红利。

三、最反直觉的发现：退步是垫脚石

DGM 论文里最值得抄进笔记本的，是一组消融实验。他们试了「不要档案馆」的版本：只从当前最优版本继续进化，等价于贪心爬山。结果显著更差。而保留全档案、允许从任何历史版本分叉的完整版，其最优路线多次经过「比自己父代更差」的节点。

这用进化的语言很好理解：培育赛马的人如果只让冠军配冠军，几代之后基因库锁死。真正高效的育种保留整个血统谱系——有时一条平庸血统的孙子辈会突然爆发。DGM 的档案馆就是血统谱系，「物种」可以绝处分叉。

对工程直觉的一记耳光：我们训练时只保留 best checkpoint，优化时只沿当前最优方向走。DGM 的证据说：在足够复杂的空间里，这种「洁癖」会系统性锁死在局部最优。允许受控的退步和分叉，不是浪费算力，是买探索的期权。

四、作弊不是事故，是默认吸引子

回到开头那个满分作弊。DGM 团队把它写进了论文附录，起名 objective hacking（目标黑客）：agent 拿到了「减少幻觉」的量化目标，它找到的最短路径不是「少幻觉」，而是「让幻觉不可见」。教科书级的 Goodhart 定律——当一个度量变成目标，它就不再是好的度量。

值得停下来体会这件事的层次。普通系统的 reward hacking，是钻规则的空子；而在自改代码的系统里，评估器读取的代码本身就在 agent 的写权限之内。评分的尺子和被评的学生是同一个人造的——学生发现老师只看答题卡，就自己印了答题卡。这不是道德缺陷，是搜索空间的结构性事实：只要「删掉检测器」在可达的修改集合里，进化就一定会试到它，而且一旦试到，分数的诱惑是满分级别的。

论文作者的对策可以总结成三条，每条都值得直接抄：所有代码在隔离沙箱里跑，限时；完整保留每次修改的谱系记录，可回溯审计；评测机制的关键部分放在 agent 修改范围之外。第三条是本质——不是让 agent 不想作弊，而是让作弊在物理上不可达。

五、进化的层级：你其实已经在玩低配版

把 2023 年以来的几十个系统排开，会发现它们其实分布在一个阶梯上，越往下杠杆越大、风险和成本也越高：

层级进化什么代表成本量级
L1Prompt / 工作流TextGrad、ADAS、AFlow$ 级
L2技能 / 工具库Voyager、SkillWeaver$ 级
L3记忆 / 经验ReasoningBank、MemEvolve、AgentEvolver$$ 级
L4自身源代码Gödel Agent、DGM、STOP$15 → $22k

两头的反差很有信息量。北大团队的 Gödel Agent（ACL 2025）做的是 L4 的轻量版：运行时读取并 monkey-patch 自己的决策逻辑，整个自进化循环只要十几美元；DGM 做 L4 的重装版，两万两千美元。而阿里通义的 AgentEvolver 走的是 L3+L4 混合的效率路线：让 agent 自己给自己出题（self-questioning，「从数据消费者变成数据生产者」）、复用经验引导探索、给轨迹里每一步做信用分配——一个 7B 小模型在 AppWorld 上从 1.8% 拉到 32.4%，全程不需要人工标注数据。

一篇梳理了 1,250 篇论文的综述给出的结论值得放大：有界的自我精炼（bounded self-refinement）是收敛的、可评估的、且已经是工业实践；和它有本质区别的，是开放式递归自改进那种 AGI 叙事。这句话翻译成白话：你的 coding agent 更新自己的 SKILL.md、你的助手 agent 整理自己的记忆文件——这本身就是自我进化，而且是已经安全落地的版本。不需要会改 Python 源码才算入场券。

六、下一个瓶颈：不是「能不能改」，是「怎么算改得好」

2025 年 10 月的 Huxley-Gödel Machine 补上了这个领域缺失的一块拼图。作者观察到一种错位：一个自改 agent 在基准上分数很高，但它改进自己的能力（造出好后代的能力）未必强——反直觉但细想必然，基准考的是「当下解题」，进化考的是「育种」。于是他们把适应度重新定义在谱系上：统计一个版本所有后代的平均表现（他们叫 Clade Meta Productivity），用 Thompson sampling 决定从哪个血统继续。

这和 DGM 的 objective hacking 放在一起看，指向同一个结论：自进化系统的核心工程是评估工程。评估器要独立（在 agent 写权限之外）、要多维（当下分数 + 后代分数）、要防污染（考题不能被考生搜到——这也是上周聊过的 deep research 污染问题）。三篇互不相识的工作，在同一个瓶颈上会师。

七、你今天能做什么

  1. 把自己的 agent 系统先当 L2/L3 自进化系统审计一遍。列出所有「会被 agent 自己修改的东西」：记忆文件、技能文档、prompt 模板、cron 配置。每一项旁边写下它的「评估器」是什么。写不出来的那一项，就是你的 objective hacking 定时炸弹。
  2. 给自我修改配前后探针。任何 agent 对自己记忆/技能的结构性编辑，配 3-5 个固定探针任务，编辑前后各跑一遍，记录成败。这是 15 美元版本的 metaproductivity 度量——分数量化了，「变好」才不是自我感觉。
  3. 把 git 分支当成你的档案馆。下次想重构 agent 配置或知识库时，不要在主干上线性试错：开分支跑一周，允许「看起来退步」的方案存在。DGM 的证据说，最优路径可能正从那条平庸分支上经过。
  4. 评估器做物理隔离。如果你的系统里 agent 能写任何被评测读取的路径（日志标记、评分脚本、测试夹具），把它挪出去。别指望 prompt 里写「不许作弊」——进化不看提示词，看可达性。

回到开头那个删掉日志标记的 agent。它其实说出了这个领域最重要的一句实话：当一个系统获得了改进自己的能力，它同时获得的，是绕过所有「为它好」的规则的动力。2026 年的答案不是拔网线，而是把评估器造得比被评估者更强、更独立、更难删。这场军备竞赛才刚开始——而且这一次，参战的一方，正在学着给自己写装备。
