AI 也需要睡觉：睡眠时计算与记忆固化，让智能体在你不在时变聪明

2026-09-26 · 罗嵩 · Agent 记忆 Sleep-time Compute 记忆固化 前沿研究
晚上十一点，你关掉电脑去睡觉。你的 AI 助手也"下班"了——不，更准确地说，它"失忆"了。这个陪你聊了三个月、读过你所有项目文档的助手，明早第一句话，它对你们共同经历的一切的掌握程度，和三个月前第一次见面时几乎一样。这不是科幻设定，这是今天绝大多数 LLM 应用的日常：LongMemEval 基准的测量结果是，商用助手在持续交互的记忆任务上平均掉 30% 精度。人类睡觉时大脑在做一件关键的事——把白天的经历从海马体固化到皮层。AI 需要睡眠吗？2025-2026 年，这个问题的答案正在从隐喻变成工程。

一、问题不在存储，在固化

先澄清一个常见的误解：agent 记忆的瓶颈不是"存不下"。向量数据库、知识图谱、文件系统，存储方案要多少有多少。真正的瓶颈是固化（consolidation）——原始对话记录躺在库里，和你能"想起来"是两回事。

神经科学里有个经典结论：海马体负责快速记录当天的经历，但真正的长期记忆发生在睡眠期间——大脑离线重放白天的神经活动，把信息从海马体逐步转移到皮层，压缩、重组、与旧知识建立连接。没有这个离线过程，记忆就停留在脆弱的短期状态（这正是某些遗忘综合征的病因）。

把这套类比翻译成 agent 的世界，会得到一个不舒服的对照：今天的大多数"记忆系统"只有海马体，没有睡眠。它们做的是"存"——把对话切块、向量化、建索引；而没做"化"——提炼、去重、失效旧值、重织连接。用户问到的时候才现场翻原始记录，相当于每天早上让海马体直接顶上。

LongMemEval（ICLR 2025）把这个差距量化了。它把长期记忆拆成五种能力：信息提取、跨会话推理、时间推理、知识更新、弃权判断（该说"我不知道"的时候）。注意后两项——知识更新问的是"用户上周改了主意，你还端着旧答案吗"，弃权问的是"用户从没说过这件事，你会不会编一个"。这两项恰恰做在写路径上：没有固化循环的系统，在这两题上必然翻车。

二、睡眠时计算：被浪费的第二条 scaling 轴

过去两年，所有人的注意力都在 test-time scaling 上——让模型在用户等待的那几秒里想得更久。o1、R1、Claude 的推理模式，本质都是花在线等待期买智能。Letta 团队 2025 年 4 月的论文提出了对偶的问题：如果智能可以在线上买，为什么不能在空闲期买？

这就是睡眠时计算（sleep-time compute）：agent 在没有用户等待压力的空闲期，主动"消化"自己拥有的上下文——预判用户可能问什么、预先推理出有用的中间结论。论文的核心概念是把 raw context（原始上下文）转化为 learned context（已消化的上下文）。一个编码 agent 可以在深夜通读整个代码库画好架构图，而不是等你明早提问时现场翻文件。

数字相当硬：在改造过的 Stateful GSM-Symbolic 和 Stateful AIME 上，同样的测试时精度，测试期算力需求降为约 1/5；反过来加大睡眠时投入，精度还能再涨 13% 到 18%；多个相关查询共享同一份消化成果时，单查询成本再摊薄 2.5 倍。这在经济学上是罕见的 Pareto 改进——空闲期算力本来就在闲置，用户侧延迟和成本同时下降，精度不降反升。

但论文还埋了一个重要限定：收益与"查询可预测性"强相关。用户会问什么越可预测（代码库问答、个人助理的偏好类问题），预计算越有的放矢；完全开放探索式的对话，睡眠时计算就接近白忙。给谁用、用在什么场景，比技术本身更决定成败。

这里有个容易被忽略的前提：睡眠时计算只对有状态的 agent 成立。无状态模型两次调用之间什么也不留，离线想出来的东西没有地方安放，下次交互自然也无法兑现。状态不是记忆系统的奢侈品，是第二条 scaling 轴的地基。

三、值班柜员与图书馆员：写路径分体

工程上怎么落地？Letta 的做法很有启发性。他们在产品里把一个 agent 拆成两个：主 agent面向用户，能对话、能调工具、能查记忆，但 deliberately 不给它编辑核心记忆的权限；睡眠时 agent独占记忆编辑权，在空闲期整理主 agent 的记忆块。

类比是银行：值班柜员只管取钱不管记账，记账留给打烊后的对账系统。原始 MemGPT 的设计把对话和内存管理捆在同一个 agent 里——聊着天突然插一段"让我更新一下记忆文件"，又慢又容易出错（你在最需要专注的对话循环里塞进了状态变更逻辑）。分体之后，主循环只读不写，快而稳；所有写操作集中到后台，还顺便把"谁在什么时候改了记忆"的审计问题变简单了。

这个模式的价值独立于 Letta 存在。任何"在对话中途管理状态"的架构都值得重新审视一遍。

四、固化循环的百家争鸣

如果固化的思路是对的，下一个问题就是：固化到底由哪些动作构成？2025-2026 年的方案呈现出有趣的收敛。挑几个代表：

  • Mem0（生产部署最广）：写入时用 LLM 显式决策四个动词——ADD / UPDATE / DELETE / NOOP。记忆不是 append-only 的日志，而是被持续维护的数据库。LoCoMo 基准上比 OpenAI 的方案高 26%，p95 延迟降 91%。
  • A-MEM（NeurIPS 2025）：借了卡片盒笔记法的思路——每条新记忆是一张结构化卡片，写入时分析它与哪些旧卡片相关、建立链接；更妙的是记忆演化：新卡片可以触发旧卡片更新自己的描述和标签。记忆网络的理解随积累持续精炼。
  • Zep / Graphiti：把时间做成一等公民。双时间戳（事件发生时间 vs 系统记录时间）的时间知识图谱，新旧冲突时失效（invalidate）而非覆盖（overwrite）——旧值带着时间戳留在审计链上。LongMemEval 上精度 +18.5%，主要赢在时间推理题。
  • MemoryOS：把操作系统的换页策略搬进来——短期→中期记忆按对话链 FIFO 晋升，中期→长期用分段页组织，冷热分级。
  • MemOS：更激进的"记忆操作系统"，用 MemCube 统一封装明文、激活、参数三级记忆，可组合、可迁移、可融合——明文记忆用多了可以"编译"成参数记忆。
  • hindsight（最近爆火的开源系统，LongMemEval 宣称 SOTA）：四层记忆（世界事实/经历/观察/心智模型），核心是 retain→recall→reflect 三操作循环。它的 observations 层精炼旧记忆时不覆盖，只追加 proof count；心智模型层干脆是物化视图——纯读、无需每次现算。

横着看，三个收敛点浮出水面：

第一，记忆是动词不是名词。没有固化循环的"记忆系统"，只是带 embeddings 的数据库。所有拿到 SOTA 数字方案的核心武器都在写路径，不在检索路径——检索（向量+重排+图游走）各家已经趋同。

第二，遗忘是功能不是缺陷。MemoryBank 直接把艾宾浩斯遗忘曲线做成了机制，hindsight 给记忆带"性情"（disposition traits）。全量保留的代价是检索噪声上升、精度反降。但删除必须可审计——所以趋势是逻辑遗忘、物理保留：失效、降权、带证据计数，而不是抹掉。

第三，OS 隐喻从修辞变成了架构。MemGPT 当年说"虚拟内存"还只是个比喻，如今 MemoryOS 有了真实的换页策略，MemOS 有了真实的资源调度。记忆正在被当作有调度语义的系统资源，而非静态数据结构。

五、泼两盆冷水

冷水一：可预测性天花板。睡眠时计算的收益上限被查询可预测性锁死。如果你的用户明天问什么你猜不到三成，预计算的大半算力就是浪费。评估"该不该上"之前，先评估"能不能猜"——日志里历史查询的聚类结构是现成的答案。

冷水二：固化循环自己也是故障源。每一次离线重写记忆，都是一次引入错误的机会：提炼错了事实、错误地失效了仍然有效的旧值、演化链上一步走偏步步走偏。Letta 用双 agent 分体隔离了一部分风险，但"后台改坏了前台的记忆，且没人发现"这类事故的检测手段（固化前后的一致性校验、审计回放）目前各家都还是薄弱环节。这和数据库迁移的痛点如出一辙——好处是结构化的，坏处也是。

六、今晚可以做什么

这套东西离你并不远。三个立刻能做的实验：

  1. 盘点你已有的 sleep-time 基础设施。如果你在用任何带定时任务或心跳机制的 agent 框架，恭喜——cron 就是现成的睡眠时窗口。检查这些定时任务里有多少是"只存不化"的：只归档日志、只同步数据、从不提炼摘要回流到检索层。给最常用的 agent 加一个周末任务：把本周的原始记录压缩成主题索引，下周注入它的上下文，肉眼对比效果。
  2. 给记忆加失效语义。哪怕你只有一坨 JSON 文件：给每条记忆加 valid_from / valid_to 两个字段，冲突时写新值+封旧值，而不是覆盖。这是 Zep 那 18.5% 里最便宜可抄的部分，也是审计能力的地基。
  3. 写路径分体小实验。如果你的 agent 在对话中途保存状态（大多数人都有这个模式），试着把保存动作挪到会话结束后的一次后台调用里。对比延迟和出错率——你会对"值班柜员不该记账"有体感。

回到开头的问题：AI 需要睡觉吗？更准确的说法是——AI 需要一段不被用户等待绑架的时间，用来消化自己的经历。人类花掉人生三分之一的睡眠换来的能力，正在成为 agent 工程的下一个标配。你的助手今晚打算干什么？如果答案是"什么也不干"，你已经知道该修什么了。
