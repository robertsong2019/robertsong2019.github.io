窗口还空着一半，模型已经开始忘了——上下文腐烂与上下文工程

LLM AI Agent 上下文工程 推理基础设施 2026-10-03 · 基于 Chroma Context Rot / NoLiMa / RULER / Governance Decay / Bouchard 生产实测等 15+ 论文与系统的调研

一个 agent 干了两个小时的活：读文件、调工具、稳步推进。然后，不知道从哪一轮开始，它开始漂移——重读已经总结过的文件，忘掉任务开头给它的约束，同一个工具换着参数反复调用。你的第一反应是"上下文窗口满了"。但一查日志：窗口还空着一半。它不是记不下了，是变笨了。这个现象在 2026 年有了正式的名字：context rot（上下文腐烂），而且它已经成了长时运行 agent 上线的头号拦路虎。

一、三份验尸报告：衰减是真的，且比你想的早

先看证据。Chroma 2025 年 7 月的 Context Rot 研究测了 18 个前沿模型（GPT-4.1、Claude 4、Gemini 2.5、Qwen3 全在内），结论只有一句：模型并不均匀地使用上下文；输入越长，表现越不可靠——哪怕任务简单到只是复制一段文本。这不是"窗口满了才崩"，而是从几千 token 起就开始的持续滑坡。

两个反直觉的细节值得单独说。第一，把测试用的"草堆"文本打乱，模型表现反而更好——连贯文本的结构模式会干扰注意力，说明上下文的呈现方式和它是否存在同等重要。第二，放一个语义相近但无关的干扰项，就能拉低基线；放四个，复合恶化。你的 agent 那几万行无关的工具输出，每一个都是干扰项。

Adobe 的 NoLiMa 基准更狠：只要把问题和目标内容之间的字面词汇重叠去掉（更接近真实提问），12 个模型里 11 个在 32K token 处跌破基线的一半，GPT-4o 从 99.3% 掉到 69.7%。也就是说，"大海捞针"演示里那种靠字面匹配的检索，严重高估了模型对长上下文的真实利用能力。

NVIDIA 的 RULER 和后续的 MECW 研究补上最后一刀：标称上下文和有效上下文是两回事，复杂任务上差距最高达 99%——同一个模型，简单检索 5K token 没问题，复杂汇总任务几百 token 就开始塌。有效上下文不是模型的一个参数，是"模型 × 任务"的函数。厂商发布会上的 1M token，是最好情况下的天花板，不是你可以规划工程的地板。

二、机理：注意力不是硬盘，是一块越摊越薄的黄油

把上下文窗口想成硬盘，是大多数架构错误的源头。硬盘是随机访问：第 10 万个 token 和第 10 个 token 读取成本一样。但注意力更像一块黄油——token 越多，涂抹面积越大，每个位置分到的越薄。这就是注意力稀释：上下文越长，早期 token 分到的注意力权重系统性衰减。2023 年的 Lost in the Middle 已经证明，关键信息放在长文档中部时，检索性能断崖式下跌——三年过去，窗口从 32K 涨到 1M，这个问题没有被解决，只是被推远了。

一个有趣的工程细节：StreamingLLM 团队发现，序列开头的几个 token 会成为注意力的"沉槽"（attention sink）——后面的 token 不管多远都要回头看它们。所以最朴素的滑窗策略（丢掉最老的 token）会瞬间崩溃，除非把前几个 token 永久保留。注意力对位置的执念，比我们想象的深。

更有意思的是失败模式分家族。Chroma 的数据显示：Claude 系在长上下文下倾向保守弃答——宁可说不知道，也不编；GPT 系则相反，干扰项一多，幻觉率上升。这对选型是直接可用的：宁可漏不可错的场景选前者，用后者的必须配外部校验层。

还有一类自产自销的腐烂，专属于推理模型：thinking token 本身就是上下文污染源。一篇 2025 年底的工作测了各种 KV 缓存压缩策略在推理任务上的表现，结果惨烈——GSM8K 上 SnapKV 还能守住 0.80，H2O 直接从 0.81 崩到 0.33。推理轨迹是压缩最脆弱的场景，而推理模型恰恰在生产压缩最多的长轨迹。这个组合值得每个部署推理模型的人警觉。

三、解药一的陷阱：压缩不是免费的，约束是第一个死的

2026 年各大实验室收敛的标准解法叫 compaction（压缩续跑）：总结一下目前干了什么，开个新窗口接着干。Claude Code 的生产默认就是这么做的。听起来很合理——但有两个坑，一个关于钱，一个关于命。

关于钱的坑：prompt caching 把压缩的盈亏平衡点推到了天上。Louis-François Bouchard 团队 2026 年 8 月发布了一组生产实测：在他们的 AI tutor 产品上对比了 11 种压缩策略，结果是——什么都不做，在召回率、成本、延迟三项上同时全胜。原因：97% 的 token 从 prompt 缓存命中，缓存 token 便宜最多 50 倍，而压缩要重写上下文、缓存全部失效。也就是说，压缩必须把上下文缩小 50 倍以上才能回本——绝大多数压缩做不到，还搭上信息损失。结论不是"永远别压缩"，而是：压缩是对具名约束的响应，不是默认习惯。触发压缩前，先算缓存账，并说出你要响应的约束是窗口硬限、成本悬崖，还是实测的质量塌陷。

关于命的坑更隐蔽：治理衰减。2026 年的一篇论文（Governance Decay）系统研究了压缩对安全约束的影响，发现约束条款是上下文里最先死的部分——通过两条通道：一是注意力稀释的被动衰减（约束在对话第 2 轮给出，第 40 轮时权重已趋近于零）；二是压缩的主动删除（摘要器天然认为"不许改 schema""金额必须双人复核"这种条目是废话，一句话带过甚至直接丢掉）。失败的签名极其隐蔽：agent 其余能力完好，它只是在第 40 轮愉快地违反了第 2 轮定下的规矩。你不会看到报错，只会看到事故。

这里的结论是结构性的：事实可以被摘要，约束必须被重注入。可压缩的历史和不可压缩的约束，应该是两条不同的数据通路——约束 pin 在压缩作用域之外，每次压缩后强制重新进入窗口。

四、解药二：别猜它要看什么，让它自己去找

比压缩更根本的转向，是把"哪些 token 配进窗口"的决策权交回给模型本身。检索范式三年里摆了三次钟摆：

  • 预推理 RAG：系统提前猜哪些 chunk 相关，预付 token 在猜测上；
  • 长上下文：不猜了，全塞进去换全局推理——代价是第一节里全部的腐烂；
  • Agent-as-retriever（即时检索）：把检索变成 agent 的工具调用行为——它自己决定看什么、什么时候再看、什么时候停。只为它判断相关的 chunk 付钱。

第三个方向在 2026 年成了主潮流：Claude Code、Cursor、Windsurf、Cline 这些编码 agent 已经不再把代码库索引进向量库，而是把 grep、读文件、AST 查询暴露成工具，让模型自己搜。学术侧也在跟进：有人提出终端级直接语料交互（DCI），有研究把大文本集当文件系统让编码 agent 用原生工具操作，MIT 的递归语言模型（RLM）走得更远——只给模型一个 query 和一个 Python REPL，全文作为变量存在，模型写代码去搜索、切片，甚至递归 spawn 自己的子实例处理子集，10M+ token 照样保持精确。本质上是同一个洞察：上下文工程正在从"为模型准备好证据"变成"让模型管理自己的注意力"。Anthropic 把这条原则表述为：找到使目标结果概率最大的那一小撮高信号 token。

这不是说 RAG 死了，也不是说窗口越大越好。生产答案永远是混合的：全局对比类任务（合同比对、架构评审）吃长上下文；点查类任务（这个函数在哪定义）用即时检索；企业级规模下，预索引的成本摊销依然成立。先分清你的任务是哪一类，再选工具。

五、服务层一瞥：KV cache 是隐形的账单

应用层之下还有一本账。每个进入上下文的 token，都会在 GPU 显存里留下 KV 缓存：32K 以上，KV 内存开始超过模型参数本身；1M token 时，它吃掉 70-90% 的显存和大部分每 token 延迟。2026 年的工程答案是五族技术叠加（paged attention、prefix caching、GQA/MLA、KV 量化、稀疏保留），组合起来能把长上下文推理成本压 4-40 倍——没有这些，1M 窗口在经济上根本不成立。MIT 2026 年的一篇理论工作还给 KV 压缩画了条底线：注意力平滑时压缩空间巨大，注意力尖锐时内存墙无法绕过。这不是纯基础设施话题：你为 agent 省下的每一千 token，都会在延迟和账单上真实兑现。

六、今晚就能做的五件事

  1. 测自己的有效上下文，别信 spec。用 RULER 式的合成任务跑你自己的 agent 轨迹，画出"从第几轮/第几 K token 开始塌陷"的曲线。你的任务分布和任何公开基准都不一样。
  2. 审计压缩触发点。列出系统里所有会触发 compaction 的条件，逐一回答"它响应的具名约束是什么"。答不上来的，先算 prompt cache 的账再决定去留。
  3. 把约束从可压缩历史里拆出来。安全条款和业务不变量单独存放、压缩后强制重注入。做个简单的"约束存活率"抽查：压缩前后各让模型复述一遍全部约束。
  4. 给新项目试点 agent-as-retriever。不再默认建向量索引，先暴露 grep/read 类工具让 agent 自己搜，对比评测 token 成本和答案质量。
  5. 给推理模型单独做压缩评测。如果你的 agent 跑长推理轨迹，任何 KV 压缩上线前，先在你的任务上验一遍——H2O 在 GSM8K 上崩掉的教训说明，通用基准的绿灯不算数。

窗口大小是厂商的军备竞赛，注意力分配才是你的工程问题。2026 年能上生产的 agent，赢的不是模型最大的那批，是上下文管理最有纪律的那批。信息在窗口里，和信息被使用，是两件事——上下文工程就是那座桥。
