车企自研 AI 芯片，真正难在哪

它不是只做一个“算大模型的计算单元”。一颗上车的 AI 芯片通常是完整 SoC：摄像头进来，图像处理，神经网络推理，CPU 调度，安全岛兜底，内存和 IO 喂数据，最后把结果交给智能驾驶系统。

Core Idea

车载 AI 芯片的核心不是 TOPS，而是“端到端数据流”

普通宣传喜欢讲 TOPS，但工程上更关心摄像头、雷达、BEV/Occupancy/Transformer 模型、内存带宽、延迟、功耗、功能安全和软件工具链能否在车上长期稳定工作。

车企真正想自研的，通常是 NPU 架构、内存层级、编译器和模型部署闭环；CPU、DDR PHY、PCIe、SerDes、部分模拟和基础 IO，则大量依赖成熟 IP 和 foundry 生态。 原因很现实：智能驾驶算法变化很快，车企希望自己的芯片更贴合自家模型；但高速接口、存储控制、车规安全和制造库的坑太深，成熟 IP 能显著降低项目风险。
Public Cases

几个公开案例说明了同一个趋势

以下只采用公开资料。不同公司公布口径不完全一致，TOPS、工艺、核心数量不宜直接横向比较；更有价值的是看它们都在围绕“大模型上车、低延迟推理、软硬件协同”做架构。

理想 M100

把差异点放在 NPU

理想公开论文把 M100 描述为面向智能驾驶和舱内 LLM 的车载 SoC。论文明确提到 SoC 内有应用 CPU、多媒体 IP、安全岛和标准 IO，但主要创新集中在可扩展 NPU。

  • 面向端到端智能驾驶和 LLM 推理
  • 强调 NPU 集群、片上 SRAM、LPDDR5X 带宽
  • 这是典型“通用 SoC + 自研 AI 加速器”的路线
蔚来 神玑 NX9031

车规 SoC 不止算力

蔚来公开资料称神玑 NX9031 为 5nm 智驾芯片，包含 CPU、ISP、自研 NPU 和安全能力，并强调 ASIL-D 安全岛。它体现了车载芯片必须同时服务感知、计算、控制和安全。

  • 摄像头图像链路和 AI 推理同等重要
  • 安全岛负责监控、故障处理和可靠性
  • 软件系统和芯片一起定义体验
小鹏 图灵

大模型驱动芯片规格

小鹏官方信息强调图灵 AI 芯片面向机器人、AI 汽车和飞行汽车，包含 40 核处理器、2 个自研 NPU，并提到可支持 30B 参数级模型。这说明车企正在按模型规模反推芯片设计。

  • 模型越大，片上 SRAM 和外部带宽越关键
  • 编译器要把 Transformer 拆成硬件友好的算子
  • 多芯片协同会带来调度和一致性问题
NPU Design

AI 芯片的“自研灵魂”，通常在 NPU 和编译器

如果把 SoC 看成一家公司，NPU 是生产车间，SRAM/DDR 是仓库和物流，编译器是排产系统。算力高但数据喂不上，实际性能会很难看。

NPU 要做什么

1
矩阵乘加阵列Transformer、CNN、BEV 模型都离不开大规模 MAC。阵列规模决定峰值算力，但不是唯一指标。
2
多精度计算INT8、INT4、BF16、FP16 等不同精度影响速度、功耗、模型精度和软件适配。
3
片上存储激活值、权重和中间结果尽量留在 SRAM，少访问外部 DRAM，才能降低延迟和功耗。
4
专用算子Attention、LayerNorm、Softmax、RoPE、稀疏化、后处理等决定大模型推理效率。

车载场景更苛刻

A
低延迟智驾不是离线跑分，感知到规划控制有严格时延预算。
B
低功耗车上散热、供电、座舱温度和整车能耗都会限制芯片功耗。
C
高可靠要考虑温度、电压、老化、软错误和功能安全。
D
可升级算法几个月一迭代，芯片要通过编译器和软件栈支持新模型。
Design Flow

以车企自研 AI SoC 为例，一般会这样推进

它继承普通 SoC 的前后端流程，但前期多了模型画像和算子分析，后期多了车规安全、量产测试、软件部署和整车验证。

01定义任务明确服务 NOA、泊车、舱内语音、多模态助手，还是机器人平台。不同任务决定摄像头数量、模型规模和延迟目标。
02模型画像统计 CNN、Transformer、BEV、Occupancy、LLM 的算子比例、张量尺寸、带宽需求和精度要求。
03架构取舍决定 NPU 阵列、SRAM 容量、NoC、DDR 带宽、CPU 核、ISP、视频、安全岛和 IO 组合。
04IP 集成采购或复用 CPU、DDR/PCIe/SerDes PHY、SRAM compiler、PLL、安全 IP、部分 ISP/Video 等。
05RTL 与验证自研 NPU、DMA、调度器、寄存器、总线桥接，并用模型 trace、随机测试和形式验证证明正确。
06后端与量产综合、布局布线、时序功耗收敛、DRC/LVS、车规可靠性、ATE 测试、封装、板级和整车验证。
Buy vs Build

哪些通常买，哪些值得自研

“自研芯片”不等于每个模块都自己写。真正成熟的芯片公司会把工程资源押在差异化模块上，把标准复杂模块交给成熟 IP 供应商和 foundry 生态。

通常采购 / 复用

  • CPU 核：Arm Cortex-A/R 或 RISC-V 生态核心
  • DDR 控制器与 PHY：高速模拟混合信号风险极高
  • PCIe、Ethernet、USB、MIPI、SerDes 等高速 IO
  • SRAM compiler、标准单元库、PLL、传感器、Efuse
  • 安全启动、加密、调试、JTAG、DFT 基础 IP
  • 部分 ISP、Video Codec、显示和音频 IP

更适合自研

  • NPU/Tensor 计算阵列和数据流
  • 面向自家模型的 Attention、稀疏、量化和后处理单元
  • 片上 SRAM 分层、DMA、调度器和多核同步机制
  • 编译器、算子库、模型量化和部署工具链
  • 智驾系统级 profiling、仿真和性能闭环
  • 与整车软件、OTA、诊断、安全策略的接口
Automotive Grade

车载 AI SoC 最怕“能跑分，但不能上车”

上车芯片不仅要算得快，还要在极端温度、电压扰动、长期老化、软硬件升级和故障场景下保持可诊断、可降级、可追责。

功能安全ASIL 目标、安全岛、锁步或监控、故障注入、诊断覆盖率、失效模式分析。
模型正确性量化误差、算子一致性、编译器正确性、仿真结果与硅后结果对齐。
PPA 收敛在真实频率下同时看性能、功耗和面积，不能只用峰值 TOPS 做宣传。
硅后验证Bring-up、ATE、板级测试、温箱、道路数据回放、OTA 回归和故障诊断。
结论：车企做 AI 芯片，表面是“自研算力”，本质是把算法、数据、编译器、芯片和整车系统变成一个闭环。 能买的 IP 会买，能复用的模块会复用；真正决定差异化的是自家模型如何被映射到硬件上，以及这个硬件能否在车规环境下长期稳定量产。
