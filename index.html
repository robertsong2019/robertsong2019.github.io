你的 Agent 需要一场好梦：Sleep-time Compute 与记忆固化
同一份 500 页文档问了 10 个问题，模型把同样的材料从头到尾读了 10 遍、推理了 10 遍，付了 10 次全款——这是推理模型时代最隐蔽的浪费。Sleep-time Compute（Letta+UCB, arXiv:2504.13171）的解法用一句话说清：把 prompt 拆成静态上下文和动态查询，趁查询还没来先让模型对上下文预推理，产出 learned context——学霸考前把教材消化成笔记，考试时只需检索；同精度省 5 倍考场算力，10 个问题共享材料时平均成本再降 2.5 倍，且收益集中在可预测查询上（复习要押题，不押题的复习是白熬）。2026 上半年三家巨头不约而同把这套东西产品化：Claude Auto Dream（约 24h+5 个 session 触发后台子代理，核心操作前两条都是删除——删被推翻的事实、删失效条目）、OpenAI Dreaming（随时间更新记忆条目，「要去新加坡」自动变「去过了」）、Google Memory Bank（异步固化+memory revisions+TTL）。共识架构收敛为：定时触发不占用户时间、重写而非追加、用最便宜的角色干整理的活。但真正的主角是减法：SleepGate 证明前摄干扰（旧值干扰新值检索）是与上下文长度无关的架构级瓶颈，在 KV cache 上训练「睡眠微周期」把干扰半径从 O(n) 压到 O(log n)，检索准确率 99.5% 对基线全低于 18%；ETH Zurich 的 AGENTS.md 研究反向印证——自动生成的 CLAUDE.md 成功率反降 3%、成本反涨 20%，预缓存 agent 本可自己发现的信息等于导航时代塞给人一张手绘地图。learned context 是从真实交互史中蒸馏、持续被修正的活文档，CLAUDE.md 是人猜 agent 需要什么的快照，前者随使用增值后者随时间腐烂。风险一节必须读：固化错误静默传播（错误合并/误删不会报错只会让 agent 莫名变蠢），「Forgetting needs receipts too」——删除要留收据（superseded 标记+源头链路+audit log），治理三件套=可审阅+可回滚+可过期。今天能做的六件事从查询可预测性审计开始。

你的 MCP 服务器，只能服务第一个连上来的客户端
你写了一个 MCP 服务器，curl 一发 initialize、调一次工具，一切正常，测试全绿。一周后第二个客户端接进来，合法的 initialize 每次都吃到 400 "Server already initialized"——服务器从部署起就只能服务第一个连上来的客户端。病根是最自然的写法：模块顶层 new 一个 StreamableHTTPServerTransport，sessionIdGenerator 一行开启 stateful 模式，transport 内部的会话状态（session id、已初始化标志、SSE 流）成了全局唯一——一个模块级单例把 N 个并发会话焊成一个。三个伴生症状：第二客户端永远 400、未知 session id 被静默接受 200（规范要求 404，谁来都路由到同一个 transport，id 从未被校验）、DELETE 无生命周期可终结。旧测试 5 个全绿的原因不是覆盖好，是测试人口里只有一个客户端——身份冲突类 bug 在单身份宇宙里数学上不可见。修复三件套：initialize 时 factory 现造一对 McpServer+transport（闭包捕获 session id）、Map 按 id 索引、onclose 唯一清理点（DELETE→close→Map 删除→后续 404，生命周期闭环是真跑通的链路不是文档句子）；外加 async listener 的 try/catch——unhandled rejection 在 Node 15+ 杀进程，一个 malformed 请求能带走整个服务器。三层教训：生命周期错配是一个 bug 类不是单个 bug（比使用方活得长的容器装会话状态=共享可变全局，PHP 模块级 DB 连接、Servlet 实例字段都是同族马甲）；宽容的协议实现是调试的地狱（静默接受一切输入的服务器把所有 bug 都变成别人的 bug）；抓并发 bug 的测试人口里必须有第二个身份不同的客户端（12 个新测试 4 个在旧代码上红，全是两客户端交错类）。落地六件：扫模块级有状态对象问进程还是会话 / per-session factory+Map+onclose 三件套 / 协议分支逐条钉测试 / 测试人口两个客户端交错先红后绿 / async await 全包 try-catch / DELETE 后同 id 必须可观测 404。

每个 Agent bug 都该有一枚种子

你的评测分数，取决于你敲命令的速度
同一份代码、同一份数据、钉死 PYTHONHASHSEED=7，一道题在四次官方评测里翻转四次——「tie-jitter」家族。第一次根因诊断（检索路径存在未播种 RNG）听着像教科书，被一次穷尽审计证伪：可达 random.* 为零。真凶是一对双生子：(1) recall() 读路径里的 wall-clock 写回——每查一次就按 time.time() 衰减+加速写回权重，ingest 全部盖章 1.0 的近平局由「在库里躺了几毫秒」的浮点噪声决定，评测分数取决于你敲命令的速度；(2) PPR 种子取 uuid4 键集合的前 8 个迭代序——os.urandom 不受 hash seed 管辖，每次新鲜 ingest 重新洗牌，是伪装成数据结构的随机数发生器。修复=readonly 纯读（不衰减不写回，平局用插入序破）+ first-discovery-order 种子；验收=A/A 复放（q86 四进程跨 seed bitwise-identical、prefix50 50/50 全同、det500 499/500 逐字节一致、86f00804 收回多数裁决）。更深的账：非确定性毒化的不是单个数字而是归因——那个 −1 先怪环境、再怪 flag，确定性落地后才归因正确；归因纪律解决「你有没有骗自己」，确定性解决「世界有没有骗你」。落地六件：seed 查四源（hash/random/time/urandom）、读路径写审计、A/A 进 CI、根因声明也要证伪、修好前 <5 题差异视为噪声、run 身份指纹三件套。

裁判也会抛硬币：拿 LLM 当判分器之前，先校准你的尺子
